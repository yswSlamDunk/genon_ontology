## 폴더 구조

```
04_insurance_ontology_poc/
├── 00_spec/              # 명세 원본 + 해설 + 참고 자료(Palantir 설계 가이드) 해설
├── 01_brief/             # 합의 기록 + Studio 구축 브리프: 구축 의도, 골든 퀘스천(Q1~Q7을 B0 기준으로 구체화), 골든 커맨드(A01~A11을 쓰는 지시 문장)
├── 02_data/              # 가상 데이터
│   ├── schema/           #   테이블 DDL (데이터소스로 연결할 DB)
│   ├── seed/             #   기본 데이터 세트 B0
│   └── variants/         #   테스트별 B0 변형분 (T02~T29)
├── 03_systems/           # 업무 시스템 서버 4개(계약·접수·심사·지급): 서버_설계서.md(기준 문서), FastAPI 서버, 실행 스크립트
│   └── upload/           #   Studio에 올리는 비정형 청구 서류 (시나리오1: 지금, 시나리오2: 발표 때)
├── 04_ontology/          # Studio에서 내보낸 스키마(schema_export.json: 클래스 17·관계 32)와 액션 10개(actions_export.json)
├── 05_tests/             # 서버 시나리오 테스트 결과 (109/109)
├── 06_app/               # 청구 심사 화면(코드 앱) 소스 사본 — 원본은 Studio 데이터 폴더 codeapps/
├── notes/                # 작업 노트, 결정 기록, 명세와 현업의 차이
└── images/               # Studio 화면 캡처
```

## 진행 순서

명세 13절의 **읽기 → 평가 → 쓰기 → 시연** 순서를 지키되, Studio에서는 그 앞에 **B0 데이터와 업무 시스템 등록**이 먼저 와야 합니다. 근거는 [해설 14.4절](00_spec/보험_온톨로지_시나리오_해설.md)에 있습니다.

| 단계 | 할 일 | 끝났다는 증거 | 폴더 |
|---|---|---|---|
| 0. 합의 | Q1\~Q7, 상품 규칙, 역할·날짜 의미 검토 (Studio 밖) | 합의 기록 | `01_brief/` |
| 1. B0 데이터 | 테이블 정의, B0, 변형 데이터. 액션 대상 클래스의 적재 방식 결정 → 데이터소스 등록 | 데이터소스 탭에서 B0 조회 | `02_data/` |
| 2. 업무 시스템 (완료 2026-11-03) | 계약·접수·심사·지급 서버 4개 (조회 + A01–A11 쓰기 API, 평가 엔진) → 시스템 등록 | 시나리오 테스트 통과, Studio 연결 테스트 통과 | `03_systems/`, `05_tests/` |
| 3. 읽기 모델 + 액션 (완료 2026-11-04) | 구축 의도 + 골든 퀘스천 6개 + 골든 커맨드 10개 → 구축·발행 | 골든 퀘스천 PASS, 클래스 17·관계 32·액션 10 | `01_brief/`, `04_ontology/` |
| 3-1. 서류 업로드 (진행 중) | 비정형 청구 서류 추가 인제스천 → 질의·액션 접수 → 재적재 | 시나리오 1 접수 RC-0002·CL-002 (2026-11-04) | `01_brief/`, `02_data/upload/` |
| 4. 평가 | 평가 서비스 구현, Q6·Q7 기반 골든 퀘스천 추가 | T01\~T15 결과 | `03_systems/`, `05_tests/` |
| 5. 업무 실행 | 골든 커맨드 → 액션 구축 → A01\~A11과 대조 | 드라이런 통과, T16\~T29와 동시성 결과 | `01_brief/`, `04_ontology/`, `05_tests/` |
| 6. 시연 | 정상·보완·중복·한도·결과 불명 경로 | 담당자 확인 | `06_app/` |
| 7. 다음 범위 | 실제 업무와의 차이 확인 | 확장 여부 결정 | `notes/` |
