# 액션 타입 개요 (Overview)

- 원문: https://www.palantir.com/docs/foundry/action-types/overview/
- 사이드바 위치: Define Ontologies > Action types > Overview

이 페이지는 사용자가 온톨로지의 객체, 속성(property), 링크를 바꾸는 수단인 액션(action)과, 그 변경 방식을 정의하는 액션 타입(action type)의 개념을 소개합니다. 객체 타입이 데이터를 "읽는" 구조라면 액션 타입은 데이터를 "쓰는" 규칙이며, 누가 어떤 입력으로 어떤 변경을 할 수 있는지와 변경 후에 무엇이 일어나는지를 한곳에 정의합니다.

<a id="action-types"></a>
## 액션 타입 (Action types)

온톨로지에서 사용자는 액션을 적용하여 객체, 속성, 링크를 변경할 수 있습니다. 액션은 사용자가 정의한 로직에 따라 하나 이상의 객체의 속성을 변경하는 단일 트랜잭션입니다. 액션을 사용하면 사용자는 개별 속성 편집(edit)이 아니라 전체 목표를 생각하면서 데이터를 처리하고 관리할 수 있습니다.

**액션 타입(action type)은** 사용자가 한 번에 수행할 수 있는 객체, 속성 값, 링크에 대한 변경 또는 편집의 집합을 정의한 것입니다. 액션 제출 시 일어나는 부수 효과(side effect) 동작도 액션 타입에 포함됩니다.

**설명**: 트랜잭션(transaction)은 데이터베이스에서 여러 변경을 하나로 묶어 "모두 반영되거나 하나도 반영되지 않게" 하는 단위입니다. 예를 들어 직원의 역할을 바꾸고 새 관리자와의 링크를 만드는 두 변경이 하나의 액션이라면, 둘 중 하나만 반영된 어중간한 상태는 생기지 않습니다. 액션 타입과 액션의 관계는 클래스와 인스턴스, 또는 함수 정의와 함수 호출의 관계로 보면 됩니다. 액션 타입은 "어떤 파라미터를 받아 어떤 편집을 하는가"를 정의하고, 사용자가 실제 값을 넣어 제출할 때마다 액션 하나가 실행됩니다.

**예시:**

`Employee` 객체의 `role` 속성 값을 사용자가 어떻게 변경할 수 있는지 정의하는 `Assign Employee` 액션 타입을 만들 수 있습니다. 이 액션 타입은 사용자가 표준화된 양식으로 새 역할을 입력할 수 있게 하는 파라미터 정의를 요구할 수 있고, `Employee` 객체와 새 `Manager` 객체 사이에 링크를 자동으로 만드는 규칙을 포함할 수 있습니다.

이 액션은 다음도 할 수 있습니다.

* 변경 사항을 이전 관리자와 새 관리자에게 알리는 알림 부수 효과를 포함합니다.
* 인사(HR) 부서 직원처럼 권한이 있는 직원만 액션을 수행할 수 있는지 검증합니다.

이렇게 파라미터를 설정하면, 예를 들어 HR 직원이 액션을 실행해 "Melissa Chang"의 `role`을 "Product Manager"로 바꿀 수 있습니다.

**설명**: 위 예시를 함수 시그니처로 적으면 `assignEmployee(employee: Employee, newRole: string, newManager: Manager)` 형태입니다. 실행 결과로 (1) 해당 Employee 객체의 `role` 속성 값이 `"Product Manager"`로 바뀌고, (2) Employee와 Manager 사이의 링크가 생기며, (3) 이전 관리자와 새 관리자에게 알림이 갑니다. (1)과 (2)는 온톨로지 데이터의 편집이고, (3)은 데이터 밖에서 일어나는 부수 효과입니다. "HR 직원만 실행 가능"이라는 검증은 이후 문서에서 다루는 제출 조건(submission criteria)으로 정의합니다.

> **중간 요약**: 액션은 하나 이상의 객체를 바꾸는 단일 트랜잭션이고, 액션 타입은 그 변경 집합과 부수 효과를 정의한 것입니다. 파라미터, 링크 생성 규칙, 알림 부수 효과, 실행 권한 검증을 하나의 액션 타입에 담을 수 있습니다.

## 온톨로지와 실제 데이터의 연결

Foundry 온톨로지는 추상적인 데이터 모델이 아니라, 각 온톨로지 개념을 조직의 실제 데이터에 매핑하여 이 데이터 자산이 현실 세계의 애플리케이션을 구동하게 합니다. 사용자의 결정과 통찰이 온톨로지에 대한 편집 형태로 기록되면서 이 데이터 자산은 더 풍부해지고 가치가 커집니다.

사용자가 액션을 실행하면 객체, 속성 값, 링크에 대한 모든 변경이 온톨로지에 커밋되고 모든 사용자 애플리케이션에 반영됩니다. 마찬가지로, 같은 액션 로직과 검증을 모든 사용자 대상 애플리케이션에서 사용할 수 있게 하여 온톨로지 편집의 일관성을 보장할 수 있습니다. 사용자 편집이 반영된 최신 버전의 객체 데이터는 객체 타입의 라이트백(writeback) 데이터셋에 기록됩니다.

**설명**: 객체 타입의 원본은 파이프라인이 만드는 백킹 데이터셋(backing dataset)입니다. 사용자가 액션으로 바꾼 값은 그 원본 데이터셋을 직접 고치지 않고 따로 기록되며, 원본과 사용자 편집을 합친 최신 상태가 라이트백 데이터셋으로 나옵니다. 예를 들어 백킹 데이터셋에서 Melissa Chang의 `role`이 `"Engineer"`이고 액션으로 `"Product Manager"`로 바꿨다면, 라이트백 데이터셋의 해당 행에는 `"Product Manager"`가 들어 있습니다. 또한 Workshop, Object Explorer 등 어느 화면에서 실행하든 같은 액션 타입을 쓰므로 검증 규칙이 화면마다 달라지지 않습니다.

> **중간 요약**: 액션으로 한 변경은 온톨로지에 커밋되어 모든 애플리케이션에 반영되며, 같은 로직과 검증이 어디서나 적용됩니다. 사용자 편집이 반영된 최신 객체 데이터는 라이트백 데이터셋에 기록됩니다.

## 정리

- 액션은 사용자 정의 로직에 따라 하나 이상의 객체, 속성, 링크를 바꾸는 단일 트랜잭션입니다.
- 액션 타입은 한 번에 수행하는 편집 집합과 제출 시 일어나는 부수 효과(알림 등)를 정의하며, 파라미터와 검증 규칙을 포함할 수 있습니다.
- 액션의 변경은 온톨로지에 커밋되어 모든 사용자 애플리케이션에 반영되고, 같은 로직과 검증이 모든 애플리케이션에 일관되게 적용됩니다.
- 사용자 편집이 반영된 최신 객체 데이터는 객체 타입의 라이트백 데이터셋에 기록됩니다.
