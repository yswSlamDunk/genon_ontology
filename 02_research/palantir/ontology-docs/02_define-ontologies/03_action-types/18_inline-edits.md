# 인라인 편집 (Inline edits)

- 원문: https://www.palantir.com/docs/foundry/action-types/inline-edits/
- 사이드바 위치: Define Ontologies > Action types > Inline edits

이 페이지는 Object Explorer나 Workshop 표에서 셀 하나를 바로 고치는 인라인 편집(inline edit)이 액션 타입을 통해 어떻게 동작하는지 설명합니다. 인라인 편집은 여러 편집을 한꺼번에 검증하고 제출하기 때문에, 하나씩 실행할 때는 잘 동작하던 액션이 예상과 다른 결과를 낼 수 있습니다. 어떤 액션이 인라인 편집에 적합하고 어떤 액션이 부적합한지를 예와 함께 다룹니다.

액션 기반 인라인 편집은 일반 [액션](02_getting-started.md)과 다른 방식으로 검증되고 제출됩니다. 일반 액션에서는 액션이 유효하려면 여러 파라미터를 설정해야 합니다. 그러나 액션 기반 인라인 편집에서는 모든 파라미터가 선택 사항이며 기본값은 객체의 기존 값이므로, 사용자가 속성(property)을 하나씩 개별적으로 바꿀 수 있습니다.

이 문서는 인라인 편집을 사용할 때 예상치 못한 결과를 피하는 방법을 다룹니다. 인라인 편집은 Workshop과 Object Explorer 모두에서 사용할 수 있습니다. 인라인 편집 액션의 구성은 액션이 사용되는 위치에 따라 다릅니다.

**설명**: 예를 들어 Flight 객체에 `origin`, `destination`, `delay_minutes` 세 속성을 바꾸는 액션이 있다고 합시다. 일반 액션 폼에서는 세 값을 모두 채워 제출합니다. 인라인 편집에서는 사용자가 표의 `delay_minutes` 칸 하나만 고치면, 나머지 `origin`과 `destination` 파라미터는 객체의 현재 값으로 자동 채워져서 결과적으로 `delay_minutes`만 바뀝니다.

<a id="object-explorer-inline-edits"></a>
## Object Explorer 인라인 편집 (Object Explorer inline edits)

인라인 편집을 사용하면 [Object Explorer 결과 뷰](../../05_applications/01_object-explorer/04_analyze-and-compare/03_view-results.md)나 속성 카드, 지표(metric) 카드 위젯 같은 기본 Object View 위젯에서 객체의 값을 빠르게 편집할 수 있습니다.

<a id="configuration"></a>
### 구성 (Configuration)

![인라인 편집 액션 구성](https://www.palantir.com/docs/resources/foundry/action-types/inline-action-configuration.png)

인라인 편집 액션을 설정하려면 Ontology Manager에서 객체 타입의 **Properties** 탭으로 이동한 다음 **Interaction** 탭으로 이동합니다. 속성 하나를 선택하고 사이드바의 **Inline edit**으로 이동합니다. 드롭다운 메뉴에서 사용 가능한 액션 타입 중 하나를 선택하거나 새로 만듭니다. 새로 만들기를 선택하면 액션 타입 생성 워크플로가 시작됩니다. 각 속성에는 인라인 편집 액션 타입을 하나만 지정할 수 있습니다.

같은 액션 타입을 여러 속성의 인라인 편집으로 쓸 수도 있고, 속성마다 별도의 액션 타입을 둘 수도 있습니다.

<a id="action-type-requirements-for-inline-edits"></a>
#### 인라인 편집용 액션 타입의 요구 사항 (Action type requirements for inline edits)

모든 액션 타입을 인라인 편집 액션 타입으로 쓸 수 있는 것은 아닙니다. 인라인 편집에 쓰려면 액션 타입이 다음 요구 사항을 충족해야 합니다.

* 단일 객체 타입의 객체 하나만 수정해야 합니다.
* 기본값(default value)이 켜져 있어야 합니다.
* 기본값은 인라인 액션이 정의된 객체 참조 파라미터에서 와야 합니다. 따라서 액션에서 바뀌는 속성을 정적 값이나 "Current User"(현재 사용자), "Current Time"(현재 시각) 같은 특수 값에 매핑할 수 없습니다.
* 표시 상태(visibility status)와 오버라이드(override)는 설정할 수 있지만, Object Explorer와 Object View에서 인라인 편집으로 쓰일 때는 무시됩니다.
* [부수 효과 웹훅](12_side-effects/04_webhooks.md#webhooks-writeback-vs-side-effect)이나 [부수 효과 알림](12_side-effects/02_notifications.md)을 켤 수 없습니다.

**설명**: 세 번째 요구 사항은 "편집하지 않은 칸은 원래 값을 유지해야 한다"는 인라인 편집의 전제를 지키기 위한 것입니다. 예를 들어 `last_modified_by` 파라미터의 기본값이 "Current User"라면, 사용자가 `delay_minutes`만 고쳐도 `last_modified_by`가 현재 사용자로 덮어써집니다. 기본값이 반드시 편집 대상 객체의 현재 속성 값에서 오도록 강제하면 이런 의도치 않은 변경이 생기지 않습니다.

> **중간 요약**: Object Explorer와 Object View의 인라인 편집은 Ontology Manager의 속성별 Interaction 설정에서 액션 타입을 지정해 켭니다. 이 액션 타입은 객체 하나만 수정하고, 기본값이 편집 대상 객체에서 와야 하며, 부수 효과를 쓸 수 없습니다.

<a id="workshop-inline-edits"></a>
## Workshop 인라인 편집 (Workshop inline edits)

Workshop에서 액션 타입을 인라인 편집으로 쓰는 데는 별도 구성이 필요 없지만, 모든 액션이 셀 단위 편집에 적합한 것은 아닙니다. 인라인 편집을 구성하는 방법은 [Workshop 문서](https://www.palantir.com/docs/foundry/workshop/widgets-object-table/#inline-edits-cell-level-writeback)를 참고하세요.

<a id="background"></a>
### 배경 (Background)

액션 하나를 실행할 때는 편집이 하나씩(순차적으로) 검증되고 제출됩니다. 인라인 편집은 편집이 한꺼번에(bulk) 검증되고 제출된다는 점이 다릅니다. 이 때문에 모든 액션이 인라인 편집에 적합한 것은 아닙니다. 인라인 편집 때문에 실패하거나 예상치 못한 결과를 낼 수 있는 액션은 다음과 같습니다.

* 다른 액션이 썼을 수 있는 데이터를 읽으려는 액션
* 같은 객체에 쓰려는 두 액션

**주의**: 인라인 편집이 [시나리오(Scenario)](https://www.palantir.com/docs/foundry/workshop/scenarios-overview/)에 적용될 때는, 제출된 액션이 (인라인 편집에서 보통 그렇듯) 동시에 적용되지 않고 (순서가 정해지지 않은 채) 순차적으로 적용됩니다. 그 결과 여러 액션이 같은 객체에 쓰려 해서 평소에는 실패하는 인라인 편집 액션이 시나리오에 적용될 때는 성공할 수 있습니다. 다만 이런 동작 차이에 의존하는 애플리케이션을 만드는 것은 권장하지 않습니다.

**설명**: 한꺼번에 검증한다는 것은 모든 편집을 "아직 아무것도 반영되지 않은 원래 데이터"를 기준으로 검사한다는 뜻입니다. 예를 들어 액션 A가 Flight F100의 지연 시간을 바꾸고, 액션 B가 F100의 지연 시간을 읽어 공항 전체 지연을 계산한다면, 순차 실행에서는 B가 A의 결과를 보지만 일괄 검증에서는 B가 A 반영 전의 값을 봅니다. 동시성 제어에서 말하는 "갱신 손실(lost update)"이나 "오래된 읽기(stale read)"와 같은 종류의 문제입니다.

<a id="valid-inline-actions"></a>
### 유효한 인라인 액션 (Valid inline Actions)

액션 기반 인라인 편집으로 제대로 동작하려면 액션이 서로 충돌하지 않는 편집을 제출해야 합니다. 실제로는 같은 표 편집 위젯에 구성된 여러 액션이 다음을 해서는 안 된다는 뜻입니다.

* 같은 객체에 쓰기
* 같은 링크 만들기
* 집계 값을 일관되게 유지하려고 시도하기

<a id="invalid-inline-actions"></a>
### 유효하지 않은 인라인 액션 (Invalid inline Actions)

**인라인 편집이 같은 객체를 두 번 편집하려고 하면 액션이 오류를 반환합니다.** 또한 조인 테이블 링크를 추가하거나 삭제하는 것은 인라인 편집에서 지원되지 않으며, 사용자에게 오류 메시지가 표시됩니다.

사용자가 인라인 편집을 적용하면 각 편집에 [제출 조건(submission criteria)](08_submission-criteria.md)이 적용되지만, 편집은 한꺼번에 제출됩니다. 파라미터 제출 조건과 전역 제출 조건 모두 편집된 각 객체에 대해 평가되지만, 공유 객체나 링크된 객체를 참조하는 제출 조건은 인라인 편집과 호환되지 않습니다. 인라인 편집을 적용할 때 누적 제출 조건은 편집된 값을 그 열의 편집되지 않은 값들과 비교하기 때문입니다. 최종 제출 시에는 편집이 한 번에 모두 제출되며, 모든 편집이 해당 객체에 대한 파라미터 제출 조건과 전역 제출 조건을 통과하면 성공합니다.

따라서 여러 액션 타입이 공유하는 객체나 링크된 객체에 대한 제출 조건은, 어떤 편집도 반영되기 전에 편집마다 한 번씩 평가됩니다.

인라인 편집은 한꺼번에 제출되므로, 액션을 순차적으로(하나씩) 적용할 때는 예상대로 동작하는 제출 조건을 위반할 수 있습니다.

**설명**: 조인 테이블 링크는 다대다(many-to-many) 관계를 표현하기 위해 두 객체 타입의 키 쌍을 별도 테이블에 저장하는 링크입니다. 관계형 데이터베이스에서 학생과 강의 사이의 수강 테이블(student_id, course_id)과 같은 구조입니다. 인라인 편집은 이런 링크 행의 추가나 삭제를 지원하지 않습니다.

<a id="example-invalid-inline-actions"></a>
#### 예: 유효하지 않은 인라인 액션 (Example: Invalid inline Actions)

항공편 하나를 최대 20분까지 지연시킬 수 있고, 한 공항의 모든 항공편 지연 합계는 최대 50분까지 허용되는 `Delay Flight` 액션이 있다고 합시다.

* 두 제출 조건(20분 요구 사항과 50분 합계)은 셀이 업데이트될 때마다 평가됩니다.
  * 아직 제출된 편집이 없으므로, 50분 합계 조건은 새 지연 값을 그 열의 편집되지 않은 지연 값들의 합(인라인 편집을 시작하기 전의 지연 값)과 비교합니다.
* 두 번째 제출 조건(공항의 모든 지연 합계가 50분 미만)은 집계 값에 의존하며, 열의 모든 객체가 공유합니다.
  * 인라인 편집은 한꺼번에 제출되므로, 이 두 번째 제출 조건은 특정 공항의 항공편 지연 총합을 제한하는 데 효과가 없습니다. 결과 편집의 합계가 두 번째 제출 조건이 허용하는 50분을 넘을 수 있습니다.
* 이 액션은 각 셀에 대해 액션을 개별 실행하는 경우와 비교해 일관되지 않은 결과를 내므로 표 편집에 적합하지 않습니다.

**설명**: 숫자로 따라가 보겠습니다. 공항에 항공편 F1, F2, F3이 있고 현재 지연이 각각 10분, 10분, 0분(합계 20분)이라고 합시다. 사용자가 인라인 편집으로 F1을 20분, F2를 20분, F3을 20분으로 고칩니다. 각 셀은 "편집 전 값 기준"으로 검사됩니다. F1 편집은 20 + 10 + 0 = 30분, F2 편집은 10 + 20 + 0 = 30분, F3 편집은 10 + 10 + 20 = 40분으로 모두 50분 이하라 통과합니다. 그러나 세 편집이 한꺼번에 반영되면 실제 합계는 60분이 되어 조건을 어깁니다. 하나씩 순차 실행했다면 F3 편집 시점의 합계가 60분으로 계산되어 거부되었을 것입니다.

> **중간 요약**: Workshop 인라인 편집은 여러 편집을 한꺼번에 검증하고 제출하므로, 같은 객체를 쓰거나 같은 링크를 만들거나 집계 값을 지키려는 액션에는 적합하지 않습니다. 같은 객체를 두 번 편집하면 오류가 나고, 집계나 링크된 객체를 참조하는 제출 조건은 편집 전 값으로 평가되어 제한 효과를 잃습니다.

## 정리

- 인라인 편집에서는 모든 파라미터가 선택 사항이고 기본값이 객체의 기존 값이라, 속성을 하나씩 고칠 수 있습니다.
- Object Explorer와 Object View 인라인 편집은 속성별로 액션 타입을 지정하며, 그 액션은 객체 하나만 수정하고 기본값이 객체 참조 파라미터에서 와야 하며 부수 효과를 쓸 수 없습니다.
- Workshop 인라인 편집은 별도 구성이 필요 없지만, 편집이 한꺼번에 검증되고 제출되므로 충돌하는 편집을 내는 액션은 부적합합니다.
- 같은 객체를 두 번 편집하거나 조인 테이블 링크를 추가, 삭제하면 오류가 납니다.
- 집계 값이나 공유, 링크된 객체에 의존하는 제출 조건은 편집 전 값 기준으로 평가되므로 인라인 편집에서는 제한 효과가 없을 수 있습니다.
