# 테스트 실행 (Test run)

- 원문: https://www.palantir.com/docs/foundry/action-types/test-run/
- 사이드바 위치: Define Ontologies > Action types > Test run

액션 타입을 만든 뒤 실제 사용자에게 공개하기 전에, 이 액션이 정말 의도한 대로 데이터를 바꾸는지 확인할 방법이 필요합니다. 이 페이지는 Ontology Manager에서 데이터를 바꾸지 않고 액션을 시뮬레이션하는 테스트 실행(test run) 기능의 사용법, 결과 해석, 테스트 중 건너뛰는 작업과 실제로 실행되는 외부 호출, 제한 사항을 설명합니다.

**테스트 실행(test run)은** 최종 사용자가 액션 타입을 적용하기 전에 Ontology Manager에서 그 액션 타입을 시뮬레이션할 수 있게 해 줍니다. 테스트 실행을 제출하면 Foundry는 제공한 파라미터 값으로 액션을 평가하고, 액션이 *만들게 될* 편집(edit)과 함께 상세한 실행 내역을 반환합니다.

**팁**: 테스트 실행으로 생성된 편집은 온톨로지에 적용되지 **않습니다**. 테스트 실행은 데이터를 바꾸지 않고, 액션이 어떤 편집을 만들고 어떻게 실행되는지 안전하게 확인하는 방법입니다.

테스트 실행은 액션 타입 편집기의 액션 폼 미리보기(action form preview)에 있는 **Test run** 탭에서 사용할 수 있습니다.

<img src="https://www.palantir.com/docs/resources/foundry/action-types/action-test-run-tab.png" alt="액션 타입 편집기의 액션 폼 미리보기에 있는 Test run 탭." width="500" />

**설명**: 데이터베이스로 치면 트랜잭션을 실행한 뒤 커밋하지 않고 롤백하면서 "어떤 행이 바뀌었을지"만 확인하는 것에 해당하는 기능입니다. 다만 Palantir가 내부적으로 트랜잭션 롤백 방식으로 구현했다는 뜻은 아니며, 사용자 입장에서 보이는 결과가 그렇다는 의미입니다.

<a id="run-a-test"></a>
## 테스트 실행하기 (Run a test)

1. Ontology Manager에서 액션 타입을 열고 액션 폼 미리보기를 엽니다.
2. 미리보기가 폼(form) 레이아웃으로 설정되어 있는지 확인합니다. 테스트 실행은 폼 레이아웃에서만 쓸 수 있고 테이블(table) 레이아웃에서는 쓸 수 없습니다.
3. 액션 폼 미리보기에서 **Test run** 탭을 선택합니다.
4. 테스트하려는 파라미터 값으로 폼을 채웁니다.
5. **Submit**을 선택해 테스트를 실행합니다.

실행이 끝나면 테스트 실행 결과가 액션 폼 미리보기에 나타납니다.

테스트 실행은 현재 온톨로지 브랜치에서 액션 타입을 평가하고 **사용자 본인의 권한으로** 실행되며, 일반 액션 제출과 동일하게 객체 보안과 제출 조건(submission criteria)을 적용합니다. Ontology Manager에서 액션 타입 구성을 볼 수 있다면 테스트를 실행할 수 있습니다.

**참고**: 액션 타입에 저장되지 않은 편집 내용이 있으면 테스트 실행을 쓸 수 없습니다. 테스트가 저장된 구성을 평가하도록, 테스트를 실행하기 전에 변경 사항을 저장하세요.

**설명**: "본인 권한으로 실행"된다는 점이 중요합니다. 예를 들어 제출 조건이 "Flight Ops 그룹 구성원만 제출 가능"인데 테스트하는 사람이 그 그룹에 없다면 테스트 실행도 제출 조건 단계에서 실패합니다. 또 테스트하는 사람이 볼 수 없는 객체는 테스트에서도 볼 수 없습니다. 즉 테스트 결과는 "내가 이 액션을 제출했다면 어떻게 되었을지"를 보여 줍니다.

> **중간 요약**: 폼 레이아웃의 Test run 탭에서 파라미터를 채우고 Submit하면 테스트가 실행됩니다. 현재 브랜치에서 본인 권한으로 평가되며, 저장되지 않은 변경이 있으면 실행할 수 없습니다.

<a id="interpret-the-results"></a>
## 결과 해석하기 (Interpret the results)

완료된 테스트 실행은 결과를 두 개의 탭에 나눠 보여 줍니다.

<a id="proposed-changes"></a>
### 제안된 변경 (Proposed changes)

**Proposed changes** 탭은 액션이 온톨로지에 만들게 될 편집, 즉 생성, 수정, 삭제되는 객체와 링크를 나열합니다. 속성 변경은 현재 값과 제안된 값의 비교로 표시됩니다. 액션이 아무 편집도 만들지 않는다면 탭에 **No proposed changes**(제안된 변경 없음)가 표시됩니다.

<img src="https://www.palantir.com/docs/resources/foundry/action-types/action-test-run-proposed-changes.png" alt="액션이 만들게 될 객체와 링크 편집을 보여 주는 Proposed changes 탭." width="400" />

**설명**: 예를 들어 `Delay flight` 액션에 F100과 30분을 넣고 테스트하면, Proposed changes에는 "Flight F100 수정: `departureTime` 09:00에서 09:30으로" 같은 항목이 나타납니다. 데이터베이스의 diff(변경 전 값과 변경 후 값)를 보는 것과 같은 형태입니다.

<a id="details"></a>
### 상세 정보 (Details)

**Details** 탭은 액션이 어떻게 평가되었는지, 그리고 직접적인 편집 외에 무엇이 일어날지 설명합니다.

* **Execution log(실행 로그):** 실행 과정을 단계별로 분해한 내역으로, 메타데이터 로딩, 의존성 검증, 제출 조건, 파라미터 검증, 편집 계산을 다룹니다. 이 로그로 액션이 왜 성공했는지, 또는 어디서 실패했는지 파악합니다.
* **Side effects(부수 효과):** 액션이 일으킬 [부수 효과(side effect)](12_side-effects/01_side-effects-overview.md)의 미리보기입니다. 예를 들어 [알림(notification)](12_side-effects/02_notifications.md)이 여기에 해당합니다. 알림 미리보기를 열어 생성될 내용과 수신자를 검토할 수 있습니다.
* **Referred entities(참조된 엔터티):** 실행 중에 액션이 참조한 객체 타입, 링크 타입, 인터페이스 타입, [함수(function)](11_function-backed-actions/01_function-actions-overview.md)입니다.

액션이 실패하면 **Details** 탭은 오류를 두 범주로 나눠 보여 줍니다.

* **Admin-facing errors(관리자용 오류):** 디버깅을 위한 기술적 세부 정보입니다.
* **End-user-facing errors(최종 사용자용 오류):** 액션을 실행한 사용자에게 보이는 메시지입니다.

<img src="https://www.palantir.com/docs/resources/foundry/action-types/action-test-run-details.png" alt="테스트 실행의 참조된 엔터티와 실행 로그를 보여 주는 Details 탭." width="400" />

**설명**: 실행 로그의 단계 순서(메타데이터 로딩, 의존성 검증, 제출 조건, 파라미터 검증, 편집 계산)는 액션 제출이 처리되는 파이프라인을 그대로 보여 줍니다. 앞 단계에서 실패하면 뒤 단계는 진행되지 않으므로, 로그에서 처음 실패한 단계를 찾으면 원인을 좁힐 수 있습니다. 오류를 두 종류로 나눈 것은 일반적인 소프트웨어 설계에서 내부 스택 트레이스는 개발자에게만, 사용자에게는 이해하기 쉬운 메시지만 보여 주는 관행과 같은 구분입니다.

> **중간 요약**: Proposed changes 탭은 생성, 수정, 삭제될 객체와 링크를 변경 전후 값으로 보여 주고, Details 탭은 단계별 실행 로그, 부수 효과 미리보기, 참조된 엔터티, 그리고 실패 시 관리자용/사용자용 오류를 보여 줍니다.

<a id="what-is-skipped-during-a-test-run"></a>
## 테스트 실행에서 건너뛰는 작업 (What is skipped during a test run)

테스트 실행은 액션의 결과를 판단하는 데 필요한 작업만 수행합니다. 액션이 적용된 뒤에 효과가 나타나는 부수 효과는 건너뜁니다. 액션 타입에 다음 중 하나라도 포함되어 있으면 액션 폼 미리보기가 이것들을 건너뛴다고 알려 줍니다.

* [부수 효과 웹훅(side effect webhook)](12_side-effects/04_webhooks.md#side-effect-webhooks)은 호출되지 않습니다.
* [알림](12_side-effects/02_notifications.md)은 발송되지 않습니다. 대신 발송되었을 알림의 내역이 테스트 실행 결과에 표시됩니다.
* [스케줄 빌드(schedule build)](13_trigger-schedule-build.md)는 트리거되지 않습니다.

<a id="external-calls"></a>
## 외부 호출 (External calls)

정확한 결과를 만들기 위해, 테스트 실행은 액션이 결과에 도달하는 데 필요한 함수와 호출을 실행합니다. 여기에는 액션의 [규칙(rule)](06_rules.md)에 쓰인 함수, 알림의 본문이나 수신자를 생성하는 함수, 웹훅 페이로드를 생성하는 함수, [라이트백 웹훅(writeback webhook)](12_side-effects/04_webhooks.md#writeback-webhooks), 외부 리소스에 접근하는 함수가 포함됩니다. 액션의 결과를 판단하는 데 필요한 호출만 수행됩니다.

**주의**: 외부 호출은 실제로 실행되므로 외부 시스템에 영향을 줄 수 있습니다. 액션 타입에 이런 호출이 포함되어 있으면 Foundry는 실행 출처(execution source)를 나열하고, 테스트 실행을 진행하기 전에 **Confirm the external call**(외부 호출 확인)을 요청합니다. 사용자가 이를 확인한 뒤에만 호출이 실행됩니다.

<img src="https://www.palantir.com/docs/resources/foundry/action-types/action-test-run-confirm-external-call.png" alt="테스트 실행 전에 확인해야 할 실행 출처를 나열하는 Confirm the external call 대화상자." width="500" />

**설명**: 건너뛰는 작업과 실행되는 작업을 가르는 기준은 "결과(편집)를 계산하는 데 필요한가"입니다. 부수 효과 웹훅은 액션이 적용된 뒤 외부에 알리는 용도라 결과 계산에 필요 없으므로 건너뜁니다. 반면 라이트백 웹훅은 외부 시스템에 먼저 기록하고 그 성공 여부에 따라 액션의 성패가 갈리는 구조이므로, 결과를 알려면 실제로 호출해야 합니다. 예를 들어 라이트백 웹훅이 외부 ERP 시스템에 주문을 생성한다면, 테스트 실행을 해도 ERP에 실제 주문이 생길 수 있습니다. 그래서 실행 전에 확인을 받습니다.

> **중간 요약**: 액션 적용 후에 일어나는 부수 효과(부수 효과 웹훅, 알림 발송, 스케줄 빌드)는 건너뜁니다. 그러나 결과 계산에 필요한 함수, 라이트백 웹훅, 외부 리소스 호출은 실제로 실행되므로 외부 시스템에 영향을 줄 수 있고, 실행 전에 사용자 확인을 받습니다.

<a id="limitations"></a>
## 제한 사항 (Limitations)

* 테스트 실행은 폼 레이아웃에서만 쓸 수 있고, 테이블 레이아웃에서는 쓸 수 없습니다.
* 액션 타입에 저장되지 않은 편집 내용이 있으면 테스트 실행을 쓸 수 없습니다. 테스트 전에 변경 사항을 저장하세요.
* [테스트 실행에서 건너뛰는 작업](#what-is-skipped-during-a-test-run)에서 설명했듯이, 액션이 적용된 뒤에 효과가 나타나는 부수 효과는 건너뜁니다. 일부 함수 기반 호출은 여전히 실행됩니다. [외부 호출](#external-calls)을 참고하세요.

## 정리

- 테스트 실행은 Ontology Manager의 액션 폼 미리보기(폼 레이아웃)에서 액션을 시뮬레이션하며, 만들어진 편집은 온톨로지에 적용되지 않습니다.
- 현재 브랜치에서 본인 권한으로 평가되고 객체 보안과 제출 조건이 그대로 적용되며, 저장된 구성만 테스트할 수 있습니다.
- 결과는 Proposed changes(변경 전후 비교)와 Details(실행 로그, 부수 효과 미리보기, 참조 엔터티, 관리자용/사용자용 오류) 두 탭으로 나뉩니다.
- 부수 효과 웹훅, 알림 발송, 스케줄 빌드는 건너뛰지만, 결과 계산에 필요한 함수와 라이트백 웹훅 같은 외부 호출은 실제로 실행되므로 확인 절차를 거칩니다.
