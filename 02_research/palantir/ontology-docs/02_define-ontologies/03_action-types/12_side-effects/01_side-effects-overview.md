# 부수 효과 개요 (Overview)

- 원문: https://www.palantir.com/docs/foundry/action-types/side-effects-overview/
- 사이드바 위치: Define Ontologies > Action types > Side effects > Overview

이 페이지는 액션 타입이 객체를 수정하는 것 외에 Foundry 밖으로 데이터를 내보내는 기능인 부수 효과(side effect)를 소개합니다. 부수 효과에는 사용자에게 알림을 보내는 알림(notification)과 외부 시스템에 요청을 보내는 웹훅(webhook) 두 종류가 있으며, 이 페이지는 각각의 목적과 상세 문서로 가는 길을 안내합니다.

액션 타입은 조직 내 의사 결정 프로세스 전반을 지원하도록 설계되었습니다. 온톨로지가 어떤 의사 결정 프로세스의 기록 시스템(system of record)으로 쓰일 때, [규칙(rules)](../06_rules.md)으로 객체 수정을 정의하면 비즈니스 프로세스를 매우 유연하게 표현할 수 있습니다. 조직의 다양한 프로세스를 모두 지원하기 위해 액션 타입은 몇 가지 추가 기능을 제공합니다.

* 실시간 프로세스에서는 시스템에서 일어나는 변경을 사용자에게 *알려서*, 사용자가 그에 대응해 조치를 취할 수 있게 해야 할 수 있습니다.
* Foundry가 아닌 다른 시스템이 조직의 원천 데이터(source of truth)인 경우, 기존 비즈니스 프로세스를 지원하려면 그 시스템과 *통합*해야 할 수 있습니다. 이 패턴을 "의사 결정 오케스트레이션(decision orchestration)"이라고 부르기도 합니다.

액션 타입의 **부수 효과(side effect)는** Foundry 밖으로 데이터를 보내 기존 조직 프로세스와 통합할 수 있게 해 줍니다. 부수 효과에는 크게 두 가지 유형이 있습니다.

* [알림(Notifications)](02_notifications.md)은 액션이 적용되었을 때 사용자에게 어떻게 알릴지를 유연하게 구성할 수 있게 합니다. 플랫폼 사용자에게 이메일을 보내는 기능도 포함됩니다.
* [웹훅(Webhooks)](04_webhooks.md)은 REST API나 ERP 시스템에 요청을 보내는 것을 포함해, 매우 유연한 방식으로 Foundry 외부 시스템에 연결할 수 있게 합니다. 이를 통해 조직의 다른 원천 시스템에 데이터를 쓰거나, 메시징 시스템과 통합해 사용자에게 더 유연하게 알림을 보낼 수 있습니다.

위 링크에서 알림과 웹훅에 대해 더 알아보거나, 다음 가이드로 시작해 보세요.

* [알림 설정하기](03_set-up-notification.md)
* [웹훅 설정하기](05_set-up-webhook.md)

**설명**: 프로그래밍에서 부수 효과(side effect)는 함수가 반환값을 내는 것 외에 바깥 상태를 바꾸는 동작(파일 쓰기, 네트워크 요청 등)을 말합니다. 액션의 본래 결과는 온톨로지 객체의 편집(edit)이고, 이메일 발송이나 외부 API 호출은 그 바깥에서 일어나는 일이므로 부수 효과라고 부릅니다. 예를 들어 "주문 승인" 액션이 Order 객체의 상태를 `Approved`로 바꾸는 것이 본래 결과라면, 담당자에게 이메일을 보내는 것은 알림, 회사 ERP 시스템의 REST API에 `POST /orders/123/approve` 요청을 보내 같은 승인을 기록하는 것은 웹훅입니다. 기록 시스템(system of record)은 특정 데이터의 공식 원본을 보관하는 시스템을 말합니다.

## 정리

- 액션 타입은 규칙으로 객체를 수정하는 것 외에, 부수 효과로 Foundry 밖에 데이터를 보낼 수 있습니다.
- 알림은 액션이 적용될 때 사용자에게 이메일 등으로 알리는 기능입니다.
- 웹훅은 REST API, ERP 같은 외부 시스템에 요청을 보내 다른 원천 시스템에 쓰거나 메시징 시스템과 통합하는 기능입니다.
- 외부 시스템이 원천 데이터인 환경에서 액션으로 그 시스템과 연동하는 패턴을 의사 결정 오케스트레이션이라고 합니다.
