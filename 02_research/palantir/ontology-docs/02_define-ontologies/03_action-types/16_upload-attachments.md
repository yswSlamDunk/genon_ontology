# 첨부 파일 업로드 (Upload attachments)

- 원문: https://www.palantir.com/docs/foundry/action-types/upload-attachments/
- 사이드바 위치: Define Ontologies > Action types > Upload attachments

이 페이지는 액션으로 객체에 첨부 파일(attachment)을 업로드하는 방법을 설명합니다. 액션 타입과 객체 타입에서 각각 해야 할 설정, 첨부 파일이 업로드되고 삭제되는 수명 주기, 파일 크기와 연결 횟수 제한을 다룹니다. 대량의 미디어에는 [미디어 업로드](15_upload-media.md)가 권장되지만, 객체에 파일 몇 개를 붙이는 단순한 경우에 첨부 파일 속성을 씁니다.

액션은 Workshop, Object Explorer, Object Views, Quiver, Slate에서 첨부 파일을 업로드하는 기능을 지원합니다. 첨부 파일을 보고, 편집하고, 삭제하는 권한은 그 첨부 파일이 업로드된 객체의 권한과 일치합니다. 예를 들어 사용자가 어떤 객체에 대한 보기 권한을 가지고 있다면, 그 객체에 저장된 첨부 파일을 보고 다운로드할 수 있습니다. 기존 첨부 파일을 교체하려면 객체에 대한 편집 권한이 필요합니다.

첨부 파일은 하나만 업로드할 수도 있고 여러 개의 목록으로 업로드할 수도 있습니다. 액션으로 첨부 파일을 업로드하려면 액션 타입과 객체 타입 양쪽의 설정 단계를 모두 따르세요.

<a id="configuring-action-types"></a>
## 액션 타입 설정하기 (Configuring action types)

파라미터 설정 화면에서 파라미터 타입으로 **Attachment**를 선택합니다. 첨부 파일은 attachment 파라미터 타입으로만 업로드할 수 있습니다. 객체의 백킹 데이터셋(object-backing dataset)에서 대응하는 열은 **String**이어야 하고, 편집되는 객체 속성은 **Attachment** 타입이어야 합니다.

여러 미디어 파일을 한 번에 업로드하려면 **Allow multiple values**를 선택합니다. 하나의 액션에서 여러 미디어 파일을 지원하려면, 아래에서 설명하는 [객체 타입 설정](#configuring-object-types) 중에 **Allow multiple**도 켜야 합니다.

<a id="configuring-object-types"></a>
## 객체 타입 설정하기 (Configuring object types)

객체 상세 화면에서 속성 타입으로 **Attachment**를 선택합니다. 첨부 파일은 attachment 속성 타입에만 업로드할 수 있습니다.

하나의 속성에 여러 미디어 파일을 업로드하려면 **Allow multiple**을 켭니다. 이 경우 객체의 백킹 데이터셋에서 해당 속성은 **Array**여야 합니다.

**설명**: 세 계층의 타입이 맞아야 합니다. 예를 들어 `Inspection` 객체 타입에 사진 여러 장을 붙인다면 다음과 같습니다.

| 계층 | 단일 첨부 | 여러 첨부 |
|---|---|---|
| 액션 파라미터 | Attachment | Attachment + **Allow multiple values** |
| 객체 속성 | Attachment | Attachment + **Allow multiple** |
| 백킹 데이터셋 열 | String | Array(문자열 배열) |

데이터셋 열이 String인 이유는 파일 내용이 아니라 첨부 파일을 가리키는 식별자 문자열이 저장되기 때문입니다.

> **중간 요약**: 액션 파라미터와 객체 속성을 모두 Attachment 타입으로 설정하고, 백킹 데이터셋 열은 String(여러 개면 Array)이어야 합니다. 여러 파일을 받으려면 양쪽 모두에서 다중 값 옵션을 켭니다.

<a id="architecture-and-limits"></a>
## 아키텍처와 제한 (Architecture and limits)

첨부 파일은 액션 폼에 추가되는 즉시 Foundry에 업로드됩니다. 폼을 제출하면 첨부 파일을 보고, 편집하고, 삭제하는 권한이 기반 객체 타입에 대한 사용자의 권한으로부터 추론됩니다. 폼 제출이 실패하거나 취소되면, 남아 있는 첨부 파일은 더 이상 직접 접근할 수 없게 되며 일정 시간이 지난 뒤 자동으로 영구 삭제됩니다. 마찬가지로 삭제된 객체에 속한 첨부 파일이나, 더 이상 객체에 매핑되지 않은 첨부 파일(해당 속성이 삭제된 경우 발생)도 직접 접근할 수 없게 되며 결국 자동으로 영구 삭제됩니다.

첨부 파일은 로직 기반 액션과 함수 기반 액션 모두에서 지원됩니다. 파일 크기에는 전역적으로 고정된 200MB 제한이 있습니다.

* 각 첨부 파일은 수명 동안 최대 10개의 객체에 연결될 수 있습니다. 첨부 파일이 10개의 객체에 연결된 뒤에는, 원래 연결된 객체 중 일부가 삭제되었더라도 다른 객체에 더 연결할 수 없습니다. 이 10개 한도에 도달한 뒤 더 많은 객체에 연결하려면 파일을 새 첨부 파일로 다시 업로드하면 됩니다.

**설명**: 업로드 시점과 제출 시점이 분리되어 있다는 점이 핵심입니다. (1) 사용자가 폼에 파일을 넣으면 그 즉시 업로드되지만 아직 어떤 객체에도 속하지 않은 상태이고, (2) 폼을 제출해 객체 속성에 연결되어야 비로소 권한이 정해집니다. (1)에서 멈춘 파일은 어느 객체에도 연결되지 않은 고아(orphan) 파일이 되므로 시스템이 나중에 정리합니다. 10개 제한은 "현재 연결 수"가 아니라 "지금까지 연결된 누적 횟수"라는 점에 주의하세요.

> **중간 요약**: 첨부 파일은 폼에 추가되는 즉시 업로드되고 제출 시 객체 권한을 따르게 되며, 연결되지 않거나 객체가 삭제된 파일은 자동으로 영구 삭제됩니다. 파일당 200MB, 수명 동안 최대 10개 객체 연결 제한이 있습니다.

## 정리

- 액션은 Workshop, Object Explorer, Object Views, Quiver, Slate에서 첨부 파일 업로드를 지원하며, 첨부 파일의 권한은 연결된 객체의 권한을 따릅니다.
- 액션 파라미터와 객체 속성 모두 Attachment 타입이어야 하고, 백킹 데이터셋 열은 String(다중이면 Array)입니다.
- 여러 파일은 파라미터의 **Allow multiple values**와 속성의 **Allow multiple**을 함께 켜서 지원합니다.
- 제출되지 않았거나 객체와 연결이 끊긴 첨부 파일은 자동 영구 삭제되며, 200MB 크기 제한과 누적 10개 객체 연결 제한이 있습니다.
