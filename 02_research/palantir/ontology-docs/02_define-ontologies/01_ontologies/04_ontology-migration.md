# 온톨로지 간 마이그레이션 (Migrating between ontologies)

- 원문: https://www.palantir.com/docs/foundry/ontologies/ontology-migration/
- 사이드바 위치: Define Ontologies > Ontologies > Migrating between ontologies

이 페이지는 이미 만들어진 온톨로지 리소스(객체 타입, 링크 타입, 액션 타입, 워크플로)를 한 온톨로지에서 다른 온톨로지로 옮기는 절차를 설명합니다. 리소스는 생성된 온톨로지에 묶이므로, 조직 구조가 바뀌거나 공유 온톨로지로 옮겨야 할 때 이 기능이 필요합니다.

모든 온톨로지 리소스는 생성된 온톨로지에 자동으로 연결됩니다. 생성된 뒤에는 리소스를 온톨로지 사이에서 옮길 수 있습니다. 온톨로지 간에 리소스를 마이그레이션하면 리소스에 대한 권한도 바뀝니다. 그러나 기반 데이터와 입력 데이터소스에 대한 권한에는 영향을 주지 않습니다. 온톨로지 간에 객체를 마이그레이션할 때 모든 편집(edit)은 기본적으로 보존됩니다.

**설명**: 여기서 권한이 두 층으로 나뉜다는 점이 중요합니다. 객체 타입 정의 자체(온톨로지 리소스)에 대한 권한은 옮겨 간 온톨로지의 규칙을 따르게 되지만, 그 객체 타입을 채우는 데이터셋(백킹 데이터소스)의 권한은 그대로입니다. 편집(edit)은 사용자가 액션 등으로 객체에 가한 수정 내역을 뜻하며, 마이그레이션 후에도 사라지지 않습니다.

리소스를 한 온톨로지에서 다른 온톨로지로 마이그레이션하려면 다음과 같이 합니다.

1. **Ontology Manager** 오른쪽 위에 있는 온톨로지 전환기(Ontology switcher)를 사용해 해당 리소스를 소유한 온톨로지로 이동합니다. <br><br>
   ![온톨로지 선택 드롭다운 메뉴 스크린샷.](https://www.palantir.com/docs/resources/foundry/ontologies/ontology-switcher.png) <br><br>

2. 같은 온톨로지에서 **Migrate resources**를 선택해 마이그레이션 과정을 시작합니다. 그다음 맨 위 행의 온톨로지 선택 드롭다운 메뉴에서 대상 온톨로지를 선택합니다. <br><br>
   ![온톨로지 마이그레이션 대상 선택 스크린샷.](https://www.palantir.com/docs/resources/foundry/ontologies/ontology-migration-switcher.png) <br><br>

3. 마이그레이션할 객체 타입, 링크 타입, 액션 타입, 워크플로를 선택합니다. 마이그레이션될 리소스 선택의 미리보기가 현재 온톨로지(왼쪽)와 대상 온톨로지(오른쪽)에 표시됩니다. 객체 타입이 원래 기본 온톨로지(default ontology)에서 만들어진 경우가 아니라면, 비공개 온톨로지의 객체 타입을 기본 온톨로지로 마이그레이션할 수 없습니다. <br><br>
   ![온톨로지 마이그레이션 대화상자 스크린샷.](https://www.palantir.com/docs/resources/foundry/ontologies/ontology-migration.png) <br><br>

**주의**: 기본 온톨로지로 마이그레이션하기(Migrating to default ontology). 연결된 리소스는 함께 마이그레이션해야 합니다. 관련된 온톨로지 리소스가 선택에서 빠져 있으면 마이그레이션이 실패합니다.

4. 선택을 마친 뒤 **Submit**을 선택해 리소스를 마이그레이션합니다.

**설명**: "연결된 리소스를 함께 옮겨야 한다"는 것은 참조 무결성 문제입니다. 예를 들어 Employee와 Department 사이에 링크 타입이 있을 때 Employee만 옮기면, 링크 타입은 한쪽 객체 타입이 다른 온톨로지에 있는 상태가 됩니다. 관계형 데이터베이스에서 외래 키가 존재하지 않는 테이블을 가리키는 것과 같은 상태이므로, Employee, Department, 그 사이의 링크 타입(그리고 이들을 수정하는 액션 타입)을 한 번에 선택해야 합니다.

## 정리

- 온톨로지 리소스는 생성된 온톨로지에 묶이지만, 나중에 다른 온톨로지로 옮길 수 있습니다.
- 마이그레이션하면 리소스 권한은 바뀌지만 기반 데이터와 입력 데이터소스의 권한은 바뀌지 않으며, 편집은 기본적으로 보존됩니다.
- 절차: Ontology Manager에서 원래 온톨로지로 이동, **Migrate resources** 선택 후 대상 온톨로지 지정, 리소스 선택, **Submit**.
- 서로 연결된 리소스는 함께 선택해야 하며, 비공개 온톨로지에서 만든 객체 타입은 기본 온톨로지로 옮길 수 없습니다.
