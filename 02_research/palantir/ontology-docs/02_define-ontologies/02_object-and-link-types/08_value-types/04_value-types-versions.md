# 값 타입 버전 (Value type versions)

- 원문: https://www.palantir.com/docs/foundry/object-link-types/value-types-versions/
- 사이드바 위치: Define Ontologies > Object and link types > Value types > Value type versions

이 페이지는 값 타입(value type)을 수정할 때 버전이 어떻게 관리되는지 설명합니다. 이름 같은 메타데이터는 자유롭게 바꿀 수 있지만 기본 타입과 제약 조건은 바뀌지 않는 값이며, 제약 조건을 바꾸면 새 버전이 생깁니다. 이미 사용 중인 값 타입을 호환성이 깨지게 바꿀 때의 권장 방법도 다룹니다.

## 값 타입 버전

값 타입은 호환성을 깨는 편집(breaking edit)과 깨지 않는 편집(non-breaking edit)을 처리하기 위해 버전이 관리됩니다. 값 타입 버전은 메타데이터와 제약 조건의 두 부분으로 구성됩니다. 이름(name), 설명(description), apiName 메타데이터 값은 필요할 때 언제든 바꿀 수 있습니다. 기본 타입(base type) 메타데이터와, 타입의 검증 규칙을 정의하는 제약 조건은 변경할 수 없습니다(immutable).

값 타입의 제약 조건을 갱신하기로 하면 값 타입의 새 버전이 만들어집니다. 값 타입을 사용하는 쪽(consumer)이 없다면 제약 조건을 자유롭게 바꿀 수 있습니다. 하지만 값 타입에 사용하는 쪽이 있는데 제약 조건에 호환성을 깨는 변경을 한다면, 현재 값 타입을 사용 중단(deprecate)하고 대신 새 값 타입을 만드는 것을 권장합니다. 이렇게 하면 런타임 오류와 데이터 불일치 가능성을 피할 수 있습니다.

<img src="https://www.palantir.com/docs/resources/foundry/object-link-types/value-type-versioning.png" alt="제약 조건 갱신 경고" width="500" />

값 타입에 호환성을 깨지 않는 변경을 할 때도 새 버전이 만들어집니다. 이 새 버전은 온톨로지(Ontology)에 자동으로 전파되어, 온톨로지 전반에서 값 타입을 사용하는 모든 곳이 최신 버전으로 갱신됩니다.

**설명**: 제약 조건 변경이 "호환성을 깨는지"는 기존에 통과하던 값이 새 규칙에서도 통과하는지로 생각하면 됩니다. 예를 들어 범위 제약을 `0~100`에서 `0~200`으로 넓히면 기존 값은 모두 계속 통과하므로 깨지 않는 변경입니다. 반대로 `0~50`으로 좁히면 기존에 저장된 70 같은 값이 갑자기 검증에 실패하므로 깨는 변경이며, 이 값 타입을 쓰는 객체 타입의 인덱싱이 실패할 수 있습니다. 그래서 사용하는 쪽이 있으면 기존 값 타입은 사용 중단하고 새 값 타입을 만들어 옮겨 가는 방식을 권합니다.

## 정리

- 값 타입 버전은 메타데이터와 제약 조건으로 구성됩니다.
- 이름, 설명, apiName은 언제든 바꿀 수 있고, 기본 타입과 제약 조건은 바꿀 수 없으며 제약 조건 갱신은 새 버전을 만듭니다.
- 사용하는 쪽이 있는 값 타입에 호환성을 깨는 제약 변경이 필요하면 사용 중단 후 새 값 타입을 만드는 것이 권장됩니다.
- 호환성을 깨지 않는 변경으로 만든 새 버전은 온톨로지 전체에 자동 전파됩니다.
