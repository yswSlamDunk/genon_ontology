# 사용자가 객체와 링크를 편집하도록 허용하기 (Allow users to edit objects and links)

- 원문: https://www.palantir.com/docs/foundry/object-link-types/allow-editing/
- 사이드바 위치: Define Ontologies > Object and link types > Allow users to edit objects and links

이 페이지는 사용자가 Workshop 같은 애플리케이션이나 외부 클라이언트에서 객체와 링크를 수정할 수 있게 하려면 무엇을 준비해야 하는지 설명합니다. 편집은 액션 타입으로 구성하며, 그 전제 조건으로 라이트백(writeback) 데이터셋을 만들고 권한을 설정해야 합니다. 원본 데이터와 편집된 데이터를 분리해 보관하는 이유도 함께 다룹니다.

<a id="editing-data-from-foundry-object-applications"></a>
## Foundry 객체 애플리케이션에서 데이터 편집하기 (Editing data from Foundry object applications)

사용자 애플리케이션(Workshop, Object Views 등)에서 사용자가 속성(property) 값을 편집하고, 링크를 추가하거나 제거하고, 객체를 생성하거나 삭제하도록 허용할 수 있습니다. 사용자가 만든 편집(edit)에 따라 부수 효과(side effect, 예: 알림)를 구성할 수도 있습니다.

이 기능을 구성하는 공식 지원 방법은 Ontology Manager에서 액션 타입을 만들고 구성하는 것입니다. [액션 타입 설정 방법을 더 알아보세요.](../03_action-types/01_overview.md)

객체 타입의 모든 속성을 액션으로 채우고 싶다면 [백킹 데이터소스(backing datasource) 없이 객체 타입을 만들](02_object-types/02_create-object-type.md#create-an-object-type-without-a-backing-datasource) 수 있습니다. 그 밖에는 데이터소스로 뒷받침되는 객체 타입에서 개별 속성 하나만 액션으로 채우려면 [편집 전용 속성(edit-only property)](03_properties/06_edit-only-properties.md)을 만드세요.

이 문서의 나머지 부분은 사용자가 액션을 실행하기 전에 객체 타입과 링크 타입에 무엇을 구성해야 하는지 다룹니다.

<a id="editing-data-from-external-applications"></a>
## 외부 애플리케이션에서 데이터 편집하기 (Editing data from external applications)

[Objects API](https://www.palantir.com/docs/foundry/api/ontology-resources/actions/apply-action/)는 외부 클라이언트가 권한을 완전히 적용받으면서 객체, 속성, 링크를 쓰고 갱신할 수 있는 엔드포인트를 제공합니다.

**설명**: 외부 애플리케이션은 HTTP 요청으로 이 API를 호출합니다. "권한을 완전히 적용받는다"는 것은 API를 통한 쓰기도 Foundry 화면에서 하는 편집과 같은 권한 검사를 거친다는 뜻입니다. 링크된 엔드포인트 이름(apply action)에서 알 수 있듯이 API로 하는 쓰기도 액션을 적용하는 형태입니다.

> **중간 요약**: 객체와 링크 편집은 Ontology Manager의 액션 타입으로 구성하며, 외부 클라이언트는 권한 검사를 거치는 Objects API로 같은 일을 할 수 있습니다.

<a id="set-up-the-prerequisites"></a>
## 전제 조건 설정 (Set up the prerequisites)

사용자가 액션 타입 구성에 정의된 액션을 실행하려면 라이트백 데이터셋을 만들어야 합니다. 라이트백 데이터셋은 빌드될 때 사용자가 만든 편집을 읽어 들이며, 각 객체의 최신 상태를 반영합니다.

**참고**: 편집은 객체 타입이나 링크 타입을 뒷받침하는 데이터셋이 아니라 라이트백 데이터셋에 기록됩니다. 이렇게 하면 사용자가 분석할 때 원본 데이터와 편집된 데이터 모두에 접근할 수 있습니다.

라이트백 데이터셋을 설정하는 방법은 다음과 같습니다.

1. 편집을 활성화하려는 객체 타입 또는 링크 타입의 **Datasources** 페이지로 이동합니다.
2. 페이지의 **Writeback dataset** 영역에서 **Generate**(생성)를 선택해 새 라이트백 데이터셋을 만듭니다. 데이터셋을 둘 Project를 고르라는 대화 상자가 열립니다. 위치를 선택합니다.
3. 객체 타입 또는 링크 타입을 편집할 수 있게 하려는 사용자에게 라이트백 데이터셋의 편집 권한이 있는지 확인합니다.
4. 객체 타입 또는 링크 타입에 가해진 변경을 볼 수 있게 하려는 사용자에게 라이트백 데이터셋의 보기 권한이 있는지 확인합니다.
   * 객체와 링크를 볼 수 있는지는 객체 타입과 링크 타입의 백킹 데이터소스가 제어합니다.
   * 객체와 링크에 가해진 편집을 볼 수 있는지는 라이트백 데이터셋의 권한이 제어합니다.
   * 사용자가 앞의 것에만 접근할 수 있다면 편집이 적용되지 않은 상태의 객체만 볼 수 있습니다. 뒤의 것에 접근할 수 있다면 편집과 현재 상태의 객체를 모두 볼 수 있습니다.

**설명**: 구체적인 예를 들어 보겠습니다. 백킹 데이터셋에 `(E1, Kim, 부서=영업)` 행이 있고, 사용자가 액션으로 E1의 부서를 "마케팅"으로 바꿨다고 합시다. 백킹 데이터셋은 그대로 "영업"으로 남고, 편집 내용은 따로 기록됩니다. 라이트백 데이터셋을 빌드하면 원본 행에 편집을 적용한 결과 `(E1, Kim, 부서=마케팅)`이 만들어집니다. 그래서 백킹 데이터셋 보기 권한만 있는 사용자는 "영업"을, 라이트백 데이터셋 보기 권한까지 있는 사용자는 "마케팅"을 보게 됩니다. 원본을 덮어쓰지 않으므로 나중에 원본과 편집본을 비교하는 분석도 가능합니다.

> **중간 요약**: 액션을 실행하려면 Datasources 페이지에서 라이트백 데이터셋을 생성하고, 편집할 사용자에게 편집 권한, 결과를 볼 사용자에게 보기 권한을 줘야 합니다. 원본 보기 권한과 편집 보기 권한은 각각 백킹 데이터소스와 라이트백 데이터셋이 따로 제어합니다.

## 정리

- 사용자 애플리케이션에서 객체와 링크를 편집하게 하려면 Ontology Manager에서 액션 타입을 구성합니다.
- 모든 속성을 액션으로 채우려면 백킹 데이터소스 없는 객체 타입을, 일부 속성만 그렇게 하려면 편집 전용 속성을 씁니다.
- 외부 클라이언트는 권한이 적용되는 Objects API로 객체, 속성, 링크를 쓸 수 있습니다.
- 편집은 백킹 데이터셋이 아니라 라이트백 데이터셋에 반영되며, 이 데이터셋을 생성하고 편집 권한과 보기 권한을 설정해야 합니다.
