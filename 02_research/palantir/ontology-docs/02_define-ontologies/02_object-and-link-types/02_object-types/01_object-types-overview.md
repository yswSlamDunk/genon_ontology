# 객체 타입 개요 (Overview)

- 원문: https://www.palantir.com/docs/foundry/object-link-types/object-types-overview/
- 사이드바 위치: Define Ontologies > Object and link types > Object types > Overview

이 페이지는 온톨로지의 가장 기본 단위인 객체 타입, 객체, 객체 집합(object set)의 정의를 예시와 함께 설명하고, 이를 데이터셋의 구조(데이터셋, 행, 필터링된 행 집합)와 대응시킵니다. 또한 객체가 실제로 어떻게 만들어지는지(백킹 데이터소스 또는 액션)를 소개해, 다음 페이지인 객체 타입 만들기로 이어집니다.

**객체 타입(object type)은** 현실 세계 엔터티나 이벤트의 스키마 정의입니다.
**객체(object) 또는 객체 인스턴스(object instance)는** 객체 타입의 인스턴스 하나를 가리킵니다. 객체 하나는 현실 세계의 엔터티나 이벤트 하나에 대응합니다.
**객체 집합(object set)은** 여러 객체 인스턴스의 모음을 가리킵니다. 즉 객체 집합은 현실 세계 엔터티나 이벤트의 그룹을 나타냅니다.

예를 들어 Ontology Manager에서 "모든 직원(All employees)", 즉 그 타입의 모든 객체가 가지는 특성을 정의하는 `Employee` 객체 타입을 만들 수 있습니다. 객체는 가상의 직원 "Melissa Chang", "Akriti Patel", "Diego Rodriguez"처럼 `Employee` 객체 타입의 인스턴스 하나를 가리킵니다. "모든 정규직 직원(All tenured employees)" 같은 객체들의 그룹은 객체 집합을 나타냅니다.

마찬가지로 Ontology Manager에서 "모든 항공편(All flights)", 즉 그 타입의 모든 객체가 가지는 특성을 정의하는 `Flight` 객체 타입을 만들 수 있습니다. 객체는 "JFK → SFO 2021-02-24"나 "TLV → LHR 2020-04-16"처럼 `Flight` 객체 타입의 인스턴스 하나를 가리킵니다. "도착한 모든 항공편(All arrived flights)" 같은 객체들의 그룹은 객체 집합을 나타냅니다.

온톨로지를 뒷받침하는 개념들은 데이터셋의 구조에 대응하는 개념을 가지고 있습니다. 온톨로지에서 객체 타입의 정의는 데이터셋의 정의에 대응하고, 객체의 정의는 데이터셋의 행 하나에 대응합니다. 객체 집합의 정의는 데이터셋에서 필터링된 행들의 집합에 대응합니다. 예를 들어 `Employee` 데이터셋은 "모든 직원 행"의 스키마를 정의할 수 있습니다. 이 경우 행 하나는 "Melissa Chang", "Akriti Patel", "Diego Rodriguez" 같은 직원 한 명을 가리킵니다. 재직 기간(tenure)을 기준으로 데이터셋을 필터링하면 "모든 정규직 직원"을 나타내는 행 집합을 얻게 됩니다.

**설명**: 위 대응을 구체적인 데이터로 보면 다음과 같습니다.

| employee_id | name | tenured |
|---|---|---|
| E1 | Melissa Chang | true |
| E2 | Akriti Patel | false |
| E3 | Diego Rodriguez | true |

이 테이블 전체의 스키마(`employee_id`, `name`, `tenured` 열)가 `Employee` 객체 타입이고, 각 행이 객체 하나입니다. `SELECT * FROM employee WHERE tenured = true`의 결과인 E1과 E3 두 행이 "모든 정규직 직원" 객체 집합입니다. 객체 집합은 저장된 별도 테이블이 아니라, 조건으로 정해지는 객체들의 모음이라는 점에 주의하십시오.

Foundry 온톨로지는 추상적인 데이터 모델에 머무르지 않고, 각 온톨로지 개념을 조직의 실제 데이터에 매핑하여 이 데이터 자산이 현실 세계의 애플리케이션을 구동할 수 있게 합니다. 객체는 Ontology Manager에서 백킹 데이터소스(backing datasource)를 추가하거나, 객체 타입의 객체를 생성하는 액션을 구성함으로써 만들어지고 사용자 애플리케이션에 표시됩니다. 기존 데이터로부터 `Employee` 타입의 객체를 만들려면, 조직은 `Employee` 객체 타입에 백킹 데이터소스를 추가하고 직원 디렉터리와 기타 기업 데이터를 온톨로지에 연결할 수 있습니다. 모든 객체가 액션을 통해 생성될 예정이라면, 대신 [백킹 데이터소스 없이 객체 타입을 만들](02_create-object-type.md#create-an-object-type-without-a-backing-datasource) 수 있습니다.

**설명**: 객체를 채우는 방법은 두 가지입니다. 첫째, 백킹 데이터소스 방식은 이미 있는 데이터셋(예: 인사 시스템에서 가져온 직원 테이블)의 각 행을 객체로 만듭니다. 데이터셋이 갱신되면 객체도 따라 갱신됩니다. 둘째, 액션 방식은 사용자가 "직원 등록" 같은 액션을 실행할 때마다 객체가 하나씩 새로 생깁니다. 예를 들어 현장 점검 보고서처럼 처음부터 Foundry 화면에서 입력되는 데이터라면 원본 데이터셋이 없으므로 두 번째 방식을 씁니다.

[객체 타입 만들기](02_create-object-type.md)부터 시작해 보십시오.

## 정리

- 객체 타입은 스키마 정의, 객체는 그 인스턴스 하나, 객체 집합은 여러 객체의 모음입니다.
- 데이터셋 구조로 보면 객체 타입은 데이터셋, 객체는 행, 객체 집합은 필터링된 행 집합에 대응합니다.
- 객체는 백킹 데이터소스를 연결하거나, 객체를 생성하는 액션을 구성하는 방식으로 만들어집니다. 모든 객체가 액션으로 생성된다면 백킹 데이터소스 없이 객체 타입을 만들 수 있습니다.
