# 링크 타입 개요 (Overview)

- 원문: https://www.palantir.com/docs/foundry/object-link-types/link-types-overview/
- 사이드바 위치: Define Ontologies > Object and link types > Link types > Overview

이 페이지는 링크 타입(link type)과 링크(link)가 무엇인지, 링크 타입의 방향성(directionality)이 어떻게 동작하는지, 그리고 링크 타입이 데이터셋의 조인과 어떻게 대응하는지 설명합니다. 객체 타입들 사이의 관계를 온톨로지에 모델링하려면 먼저 이 개념을 알아야 합니다.

**링크 타입(link type)은** 두 객체 타입 사이의 관계에 대한 스키마 정의입니다. **링크(link)는** 같은 온톨로지 안의 두 객체 사이에 있는 그 관계의 인스턴스 하나를 가리킵니다.

예를 들어 Ontology Manager에서 `Employee` 객체 타입과 `Company` 객체 타입 사이에 `Employee`와 `Employer`(고용주)의 관계를 정의하는 링크 타입을 만들 수 있습니다. 링크는 `Employee → Employer` 링크 타입의 인스턴스 하나를 가리키며, 가상의 직원 "Melissa Chang"과 그 고용주 "Acme, Inc." 사이의 관계가 그 예입니다.

마찬가지로 Ontology Manager에서 `Flight` 객체 타입과 `Aircraft` 객체 타입 사이에 `Scheduled Flight`(예정된 항공편)와 `Assigned Aircraft`(배정된 항공기)의 관계를 정의하는 링크 타입을 만들 수 있습니다. 링크는 `Scheduled Flight → Assigned Aircraft` 링크 타입의 인스턴스 하나를 가리키며, "JFK → SFO 24-02-2021" 항공편과 거기에 배정된 항공기 "Boeing 737-123" 사이의 관계가 그 예입니다.

링크는 같은 타입의 두 객체 사이에도 존재할 수 있습니다. `Employee` 객체 타입과 그 자신 사이에 `Direct Report ↔ Manager`(직속 부하와 관리자) 링크 타입을 정의할 수 있습니다.

서로 다른 온톨로지에 속한 객체 타입 사이의 링크는 지원되지 않습니다. 이런 경우에는 공유 온톨로지(shared Ontology)를 활용하는 편이 나을 수 있습니다.

**설명**: 같은 타입끼리의 링크는 SQL의 자기 조인(self join)에 해당합니다. 예를 들어 `employees` 테이블에 `manager_id` 열이 있고 그 값이 같은 테이블의 `employee_id`를 가리킨다면, `employees e JOIN employees m ON e.manager_id = m.employee_id`로 직원과 관리자를 연결합니다. `Direct Report ↔ Manager` 링크 타입은 이 관계를 온톨로지에 정의한 것입니다.

> **중간 요약**: 링크 타입은 두 객체 타입 사이 관계의 스키마이고, 링크는 두 객체 사이 관계의 인스턴스입니다. 같은 객체 타입끼리도 링크를 만들 수 있지만, 서로 다른 온톨로지 사이에는 만들 수 없습니다.

## 방향성 (Directionality)

링크 타입은 양방향입니다. 링크 타입은 항상 두 개의 **면(side)을** 가지며, 관계를 맺는 두 객체 타입 각각에 하나씩 대응합니다. 링크 타입의 각 면은 독립적으로 탐색(traverse)할 수 있고, 각자의 표시 이름과 [API 이름(TSv1)](../../04_functions/13_functions-on-objects/06_api-objects-links.md)을 가집니다. 예를 들어 `Flight ↔ Aircraft` 링크 타입 하나에는 `Flight` 면과 `Aircraft` 면이 있습니다. 코드에서 `flight.assignedAircraft.get()`을 호출하면 링크 타입의 `Aircraft` 면을 탐색해 항공편에 배정된 항공기를 가져오고, `aircraft.flights.all()`을 호출하면 `Flight` 면을 탐색해 그 항공기에 배정된 항공편들을 가져옵니다. 이 예시는 TSv1 문법을 사용했으며, 다른 언어도 같은 두 면을 탐색합니다.

두 객체 타입 사이에 링크 타입 하나를 만든다고 해서 반대 방향의 두 번째 링크 타입이 암묵적으로 생기지는 않습니다. 그 대신 링크 타입 하나가 이미 두 면을 통해 양방향 탐색을 지원하므로, 같은 관계를 표현하기 위해 `Aircraft`에서 `Flight`로 가는 링크 타입과 `Flight`에서 `Aircraft`로 가는 링크 타입을 따로 정의할 필요가 없습니다.

같은 두 객체 타입 사이에 서로 다른 링크 타입을 여러 개 정의할 수는 있지만, 각 링크 타입은 기존 링크 타입의 반대 방향이 아니라 별개의 현실 세계 관계를 나타냅니다. 예를 들어 배정된 항공기를 나타내는 `Flight ↔ Aircraft` 링크 타입에 더해, 예정된 정비 기록을 나타내는 독립적인 두 번째 `Flight ↔ Aircraft` 링크 타입을 정의할 수 있습니다. 애플리케이션이 관계들을 구분할 수 있도록, 각 링크 타입은 면마다 고유한 [API 이름](02_create-link-type.md#define-link-type-names)을 가져야 합니다.

**설명**: 아래 데이터로 두 면의 동작을 확인해 봅니다.

| Flight | Flight Tail Number |
|---|---|
| F100 | N101 |
| F101 | N101 |
| F102 | N202 |

`flight.assignedAircraft.get()`은 F100 객체에서 출발해 Aircraft N101 하나를 돌려줍니다(다대일에서 "일" 쪽이므로 `get()`). 반대로 `aircraft.flights.all()`은 N101 객체에서 출발해 F100과 F101 두 개를 돌려줍니다("다" 쪽이므로 `all()`). 링크 타입은 하나지만 출발점에 따라 다른 면을 따라가는 것입니다.

> **중간 요약**: 링크 타입 하나는 두 면을 가지며 양방향으로 탐색할 수 있으므로, 역방향 링크 타입을 따로 만들 필요가 없습니다. 같은 두 객체 타입 사이에 링크 타입을 여러 개 두면 각각은 서로 다른 관계를 뜻합니다.

온톨로지의 바탕이 되는 개념들은 데이터셋의 구조에 대응하는 개념을 가집니다. 온톨로지에서 링크 타입의 정의는 두 데이터셋 사이의 조인(join) 정의에 대응하고, 링크의 정의는 한 데이터셋의 행이 다른 데이터셋의 행의 필드와 조인된 결과 행에 대응합니다. 예를 들어 `Employee` 데이터셋과 `Company` 데이터셋을 조인해 `Employees`와 그들의 `Employers` 사이의 관계를 살펴볼 수 있습니다. 조인된 데이터셋에서 "Melissa Chang"과 고용주 "Acme, Inc."를 잇는 행 하나가 링크 하나를 나타냅니다.

Foundry 온톨로지는 추상적인 데이터 모델에 그치지 않고 각 온톨로지 개념을 조직의 실제 데이터에 매핑하므로, 이 데이터 자산으로 현실 세계의 애플리케이션을 움직일 수 있습니다. 링크는 Ontology Manager에서 링크 타입이 가리키는 객체 타입들에 백킹 데이터소스(backing datasource)를 추가함으로써 생성되고 사용자 애플리케이션에 표시됩니다. 객체 타입들이 다대다(many-to-many) 카디널리티로 관계를 맺는 링크 타입의 경우에는 데이터소스가 링크 타입 자체를 뒷받침합니다. `Employee → Employer` 타입의 링크를 만들려면 조직은 `Employee`와 `Company` 객체 타입에 백킹 데이터소스를 추가하고, 직원 명부와 기타 기업 데이터를 온톨로지에 연결합니다.

**설명**: 카디널리티(cardinality)는 한쪽 행 하나에 다른 쪽 행이 몇 개 대응하는지를 뜻합니다. 다대일 관계는 "다" 쪽 테이블의 외래 키 열 하나로 표현할 수 있으므로 객체 타입의 데이터소스만 있으면 링크가 만들어집니다. 다대다 관계는 외래 키 열 하나로 표현할 수 없어서, 관계형 데이터베이스에서 별도의 조인 테이블(연결 테이블)을 두듯 링크 타입 자체에 데이터소스가 필요합니다.

[새 링크 타입 만들기](02_create-link-type.md)를 익히는 것부터 시작하세요.

> **중간 요약**: 링크 타입은 데이터셋 조인에, 링크는 조인 결과의 행 하나에 대응합니다. 링크는 객체 타입(다대다의 경우 링크 타입 자체)의 백킹 데이터소스를 통해 실제 데이터로 만들어집니다.

## 정리

- 링크 타입은 두 객체 타입 사이 관계의 스키마, 링크는 그 관계의 인스턴스입니다.
- 링크 타입은 두 면을 가진 양방향 구조이며, 면마다 표시 이름과 API 이름이 있습니다.
- 역방향 링크 타입을 따로 만들 필요는 없고, 같은 객체 타입 쌍 사이의 여러 링크 타입은 서로 다른 관계를 뜻합니다.
- 같은 타입끼리의 링크는 가능하지만 온톨로지를 넘나드는 링크는 지원되지 않습니다.
- 링크 타입은 SQL 조인에 대응하며, 다대다 관계는 링크 타입 자체에 백킹 데이터소스가 필요합니다.
