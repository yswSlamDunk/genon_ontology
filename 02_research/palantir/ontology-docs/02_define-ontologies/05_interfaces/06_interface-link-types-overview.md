# 인터페이스 링크 타입 (Interface link types)

- 원문: https://www.palantir.com/docs/foundry/interfaces/interface-link-types-overview/
- 사이드바 위치: Define Ontologies > Interfaces > Interface link types

이 페이지는 인터페이스(interface) 수준에서 객체 사이의 관계를 정의하는 "인터페이스 링크 타입 제약 조건(interface link type constraint)"을 설명합니다. 링크 대상을 인터페이스로 할지 객체 타입으로 할지, 카디널리티를 `ONE`과 `MANY` 중 무엇으로 할지 고르는 기준을 예시와 함께 다룹니다.

(원문 페이지의 본문 제목은 "Interface link type constraints"입니다.)

인터페이스 링크 타입 제약 조건은 인터페이스를 구현하는 모든 객체 타입에 공통되는 객체 간 관계를 정의합니다. 사용자는 링크에 대한 설명과, 코드에서 참조할 때 쓰는 링크 타입의 API 이름을 지정할 수 있습니다. 객체가 인터페이스 링크 타입 제약 조건이 있는 인터페이스를 구현하면, 객체 타입에 있는 구체적인 링크 타입이 인터페이스 링크 타입 제약 조건을 충족하는 데 사용됩니다.

<img src="https://www.palantir.com/docs/resources/foundry/interfaces/create-link-type-constraint-modal.png" alt="인터페이스 링크 타입 생성." width="500" />

위 예시처럼, 시설(facility)과 그 시설이 서비스하는 항공사(airline) 사이의 관계를 모델링하기 위해 `Facility` 인터페이스는 `Facility` 인터페이스를 구현하는 모든 객체와 `Airline` 객체 타입 사이에 선택적(optional) 일대다(one-to-many) 링크 타입 제약 조건을 선언합니다. 이는 구현 객체 타입(예: `Airport`)에 `Airlines` 객체 타입으로 가는 구체적인 링크 타입이 있다면, 그 링크를 인터페이스 링크 타입의 API 이름으로 접근할 수 있다는 뜻입니다.

**설명**: 객체 타입의 링크 타입은 데이터베이스의 외래 키 관계에 해당합니다(예: `airport_airline` 테이블이 `airport_id`와 `airline_id`를 가짐). 인터페이스 링크 타입 제약 조건은 그런 관계가 "있어야 한다"는 요구 사항만 적은 것이고, 실제 데이터 연결은 각 구현 객체 타입의 구체적인 링크 타입이 담당합니다. 코드는 인터페이스 쪽 API 이름(예: `servedAirlines`)으로 링크를 따라가고, 실행 시에는 객체의 실제 타입에 매핑된 링크 타입이 쓰입니다.

> **중간 요약**: 인터페이스 링크 타입 제약 조건은 구현 객체 타입 전체에 공통인 관계를 선언하고, 각 객체 타입의 실제 링크 타입이 이를 충족합니다. 코드는 인터페이스의 링크 API 이름으로 그 링크를 사용합니다.

<a id="link-type-constraints"></a>
## 링크 타입 제약 조건 (Link type constraints)

링크 타입 제약 조건은 인터페이스 링크 타입의 파라미터를 정의합니다. 링크 타입이 필수라면, 모든 구현 객체 타입은 이 제약 조건을 만족하는 링크를 가져야 합니다. 이 파라미터에는 다음이 포함됩니다.

* **링크 대상 타입(Link target type):** 인터페이스 또는 객체 타입.
* **대상(Target):** 특정 인터페이스 또는 객체 타입.
* **카디널리티(Cardinality):** 일대일(one-to-one) 또는 일대다(one-to-many).
* 객체 타입 구현의 일부로 링크가 필수인지 여부.

<a id="link-target-interface"></a>
## 링크 대상: 인터페이스 (Link target: Interface)

두 추상 객체 타입 사이의 관계를 모델링하려면 `interface` 타입의 링크 대상을 사용해야 합니다.

예를 들어 인터페이스 링크 대상을 사용해 `Facility`와 그곳에서 발생하는 `Alert` 사이의 관계를 모델링할 수 있습니다. 시설에도 여러 종류가 있고 경보에도 여러 종류가 있으므로, 링크의 양 끝에 각각 객체 타입 하나만 쓸 수 있다면 둘 사이의 연결을 모델링하는 것이 불가능합니다. 대신 `Facility` 인터페이스와 `Alert` 인터페이스를 정의하고, `Facility`에 `Alert` 인터페이스로 링크되도록 설정한 인터페이스 링크를 정의해 이 관계를 모델링할 수 있습니다. 그런 다음 `Facility` 인터페이스를 구현하는 `Airport` 객체 타입과 `Alert` 인터페이스를 구현하는 `Flight Alert` 객체를 정의할 수 있습니다. 이후 `Airport`에서 `Flight Alert`로 가는 구체적인 링크 타입을 정의해 `Facility` 인터페이스의 링크 타입 제약 조건을 충족할 수 있습니다.

**설명**: 시설 종류가 `Airport`, `Maintenance Hangar` 두 가지이고 경보 종류가 `Flight Alert`, `Weather Alert` 두 가지라면, 객체 타입끼리 직접 연결할 때는 조합마다 링크 타입이 따로 필요합니다. 인터페이스끼리 링크를 선언해 두면 "모든 Facility에서 그곳의 모든 Alert로" 가는 관계를 하나의 이름으로 다룰 수 있고, 각 구현 객체 타입은 자기에게 맞는 실제 링크 타입으로 이를 충족합니다.

<a id="link-target-object-type"></a>
## 링크 대상: 객체 타입 (Link target: Object type)

인터페이스와 대상 사이의 관계가 구체적이고, 그 구체성을 링크 타입 제약 조건으로 강제해야 할 때는 `object type` 타입의 링크 대상을 사용해야 합니다.

예를 들어 `Airlines` 객체 타입에 링크되는 `Facility` 인터페이스를 정의할 수 있습니다. 이 인터페이스 링크는 시설 유형이 무엇이든 그 시설이 서비스하는 특정 항공사에 대한 링크가 있을 것으로 기대한다는 사실을 모델링합니다.

> **중간 요약**: 링크 양쪽이 모두 여러 종류일 수 있는 추상 관계는 인터페이스를 대상으로, 대상이 정해진 하나의 객체 타입이어야 하는 관계는 객체 타입을 대상으로 지정합니다.

<a id="cardinality"></a>
## 카디널리티 (Cardinality)

인터페이스 링크 타입은 `ONE` 또는 `MANY` 카디널리티를 갖도록 추가로 지정할 수 있습니다. 이 카디널리티는 각각 일대일 모델링과 일대다 모델링에 해당합니다. `ONE` 카디널리티는 인터페이스를 구현하는 각 객체가 대상 타입의 객체 하나에 링크되어야 함을 나타냅니다. `MANY` 카디널리티는 인터페이스를 구현하는 각 객체가 대상 타입의 객체 몇 개에든 링크될 수 있음을 나타냅니다.

온톨로지의 모델링 요구에 따라 `ONE`과 `MANY` 중 무엇을 쓸지 결정해야 합니다. 경우에 따라서는 링크의 카디널리티를 객체 하나로 제한하는 것이 더 타당할 수 있습니다. 예를 들어 `Driver's License`와 `Person` 사이의 관계는 각 면허가 구체적인 한 사람에게만 속할 수 있으므로 `SINGLE` 카디널리티 링크로 모델링하고 싶을 수 있습니다. `Company`와 그 `Shareholders`처럼 관계에 더 많은 유연성이 허용된다면, 각 회사가 구체적인 주주를 한 명 이상 가질 수 있음을 나타내기 위해 `MANY` 카디널리티 링크를 사용하고 싶을 수 있습니다.

**설명**: 원문의 예시에는 `SINGLE`이라는 표기가 나오지만, 앞 문단에서 정의한 값은 `ONE`과 `MANY`이므로 여기서 `SINGLE`은 `ONE`을 가리키는 것으로 읽으면 됩니다. 데이터베이스로 보면 `ONE`은 `driver_license` 테이블에 `person_id` 외래 키 열이 하나 있는 구조이고, `MANY`는 `company_shareholder` 같은 별도 테이블에 한 회사의 행이 여러 개 들어갈 수 있는 구조에 대응합니다.

> **중간 요약**: `ONE`은 구현 객체마다 대상 객체 하나, `MANY`는 대상 객체 여러 개에 링크될 수 있음을 뜻하며, 실제 관계의 성격에 맞춰 고릅니다.

## 정리

- 인터페이스 링크 타입 제약 조건은 인터페이스를 구현하는 모든 객체 타입에 공통인 관계를 선언하고, 각 객체 타입의 구체적인 링크 타입이 이를 충족합니다.
- 제약 조건은 링크 대상 타입, 대상, 카디널리티, 필수 여부로 구성됩니다.
- 양쪽이 여러 종류인 추상 관계는 인터페이스를, 대상이 고정된 관계는 객체 타입을 링크 대상으로 씁니다.
- 카디널리티는 `ONE`(일대일)과 `MANY`(일대다) 중에서 관계의 성격에 맞게 고릅니다.
