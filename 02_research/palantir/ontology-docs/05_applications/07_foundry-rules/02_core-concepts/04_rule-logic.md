# 규칙 로직 (Rule logic)

- 원문: https://www.palantir.com/docs/foundry/foundry-rules/rule-logic/
- 사이드바 위치: Applications > Foundry Rules > Core concepts > Rule logic

이 페이지는 Foundry 규칙 하나가 가진 로직이 입력, 로직 블록, 규칙 출력의 세 부분으로 어떻게 구성되는지 설명합니다. 규칙 작성자가 무엇을 데이터로 받아 어떤 변환을 거쳐 어떤 형식으로 내보내는지 이해하는 데 필요한 페이지입니다.

각 Foundry 규칙에는 로직이 연결되어 있습니다. 이 로직은 세 부분으로 이루어집니다.

1. [입력(Inputs):](#inputs) Foundry 규칙에 들어가는 데이터 입력입니다.
2. [로직 블록(Logic blocks):](#logic-blocks) 선택한 입력에 적용할 변환입니다.
3. [규칙 출력(Rule output):](#rule-output) 규칙의 출력 형식입니다.

![위에서 설명한 세 부분으로 된 Foundry Rules 로직 예시](https://www.palantir.com/docs/resources/foundry/foundry-rules/labeled_foundry_rules_logic.png)

*모든 스크린샷은 가상의 데이터를 사용합니다.*

**설명**: 세 부분은 SQL 쿼리 하나와 그대로 대응시켜 볼 수 있습니다. 입력은 `FROM` 절의 테이블, 로직 블록은 `WHERE`, `GROUP BY`, `JOIN`, 계산식, 규칙 출력은 `SELECT` 목록과 결과를 `INSERT`할 대상 테이블입니다. 예를 들어 "금액이 10000을 넘는 거래를 high 등급 알림으로 내보낸다"는 규칙은 입력 Transaction, 로직 블록 `amount > 10000` 필터, 출력 Alerts 데이터셋(열 `transaction_id`, `severity = high`)으로 구성됩니다.

<a id="inputs"></a>
## 입력 (Inputs)

Foundry 규칙의 입력은 사용 사례에 따라 데이터셋일 수도 있고 객체일 수도 있습니다. 다만 객체를 입력으로 사용하면 더 사용하기 쉬운 인터페이스와 함께, 필터 값에 대한 자동 완성 드롭다운 같은 추가 기능을 쓸 수 있습니다.

규칙 작성자가 사용할 수 있는 데이터셋과 객체는 워크플로 소유자가 [Foundry Rules 워크플로 구성](05_foundry-rules-workflow-configuration.md)에서 설정합니다. 제한된 뷰(restricted view)를 백킹으로 하는 객체는 입력으로 직접 사용할 수 없습니다. 대신 워크플로 소유자가 그 제한된 뷰를 백킹하는 데이터셋을 [대체 백킹 데이터셋(alternate backing dataset)](../03_deploy/03_configure-workflow.md#alternate-backing-datasets)으로 구성해야 합니다.

**주의**: Foundry Rules는 여러 데이터소스를 백킹으로 하는 객체 타입, 여러 머티리얼라이제이션(materialization)을 가진 객체 타입, 편집 전용(edit-only) 속성(property)을 사용하는 객체 타입을 지원하지 않습니다.

**설명**: 제한된 뷰는 행 단위 접근 제어가 걸린 데이터셋의 뷰로, 사용자마다 볼 수 있는 행이 다릅니다. 규칙은 파이프라인에서 데이터 전체를 대상으로 실행되므로, 이런 경우에는 뷰 아래에 있는 원본 데이터셋을 별도로 연결해 주어야 한다는 의미로 이해할 수 있습니다. 또 Foundry Rules는 객체 타입의 백킹 데이터셋(backing dataset)을 읽어 규칙을 적용하므로, 데이터소스가 하나로 정해지지 않거나 사용자 편집으로만 존재하는 속성처럼 백킹 데이터셋 하나에서 값을 얻을 수 없는 구성은 지원 범위 밖입니다.

> **중간 요약**: 규칙의 입력은 데이터셋 또는 객체이며, 객체를 쓰면 편의 기능이 더 많습니다. 어떤 입력을 쓸 수 있는지는 워크플로 소유자가 정하며, 일부 객체 타입 구성은 지원되지 않습니다.

<a id="logic-blocks"></a>
## 로직 블록 (Logic blocks)

규칙의 입력에 적용되는 변환은 일련의 로직 블록으로 표현됩니다. 사용할 수 있는 변환에는 필터링, 표현식(expression), 집계(aggregate), 조인(join)이 있습니다. 이 변환 가운데 어떤 것을 최종 사용자에게 제공할지 설정할 수도 있습니다. [선택 기능 활성화](../04_settings-customization/02_enable-optional-features.md)에 대해 더 알아보세요.

각 로직 블록은 이전 블록 또는 소스에서 출력된 행을 받아 변환을 적용하고, 새로운 행과 열의 집합을 출력합니다. 블록 오른쪽 위의 **Preview** 버튼을 클릭하면 그 출력을 볼 수 있습니다.

**설명**: 블록들은 앞 블록의 출력 테이블이 다음 블록의 입력 테이블이 되는 파이프라인 구조입니다. 예를 들어 1번 블록이 Transaction 1000행 중 `amount > 10000`인 30행을 남기고, 2번 블록이 `customer_id` 기준으로 집계해 고객별 건수 12행을 만들면, 2번 블록의 Preview에는 그 12행이 보입니다.

> **중간 요약**: 로직 블록은 필터, 표현식, 집계, 조인 같은 변환을 순서대로 이어 붙인 것이며, 각 블록의 중간 결과를 Preview로 확인할 수 있습니다.

<a id="rule-output"></a>
## 규칙 출력 (Rule output)

규칙의 끝에는 규칙 출력이 있습니다. 각 규칙 출력은 [Foundry Rules 워크플로 구성](05_foundry-rules-workflow-configuration.md)에 설정된 출력 데이터셋 하나에 대응합니다. 따라서 선택한 출력이 Foundry 규칙이 내보내는 행의 목적지와 형식을 지정합니다. 각 필드의 입력 화면은 [그 필드가 받는 값의 종류에 맞게 조정](../04_settings-customization/05_permitted-and-default-output-values.md)할 수 있습니다. *생성되는 출력 데이터셋에는 그 출력을 사용하는 모든 규칙이 내보낸 행이 들어갑니다*. 이 동작은 서로 다른 규칙의 출력을 일관되게 유지하기 쉽도록 설계된 것입니다.

규칙 출력을 통해 워크플로 소유자는 규칙 작성자가 로직에서 반드시 내보내야 하는 열과 타입을 정확하게 강제할 수 있습니다. 화면에서는 이 강제가 폼으로 표시되며, 폼의 각 입력 칸은 출력 데이터셋의 열 하나에 대응합니다.

같은 애플리케이션 안의 Foundry 규칙들이 서로 다른 스키마의 행을 내보내야 한다면, 여러 규칙 출력 중에서 고를 수 있도록 구성할 수 있습니다. 또는 스키마가 비슷하다면 새 규칙 액션을 만드는 대신 일부 액션 파라미터를 선택 사항(optional)으로 구성하는 편이 더 쉬울 수 있습니다.

[규칙 출력 구성](05_foundry-rules-workflow-configuration.md#workflow-outputs)에 대해 더 알아보세요.

![구성된 규칙 액션과 그에 대응하는 출력 데이터셋](https://www.palantir.com/docs/resources/foundry/foundry-rules/rule_action_output_column_mapping.png)

**설명**: 여러 규칙이 같은 출력을 쓰면 결과가 하나의 데이터셋에 합쳐집니다. 규칙 A가 3행, 규칙 B가 5행을 내보내면 Alerts 데이터셋에는 8행이 쌓이고, 모든 행이 같은 열 구조를 가집니다. SQL로 보면 같은 스키마의 결과를 `UNION ALL`로 합친 테이블입니다. 스키마가 고정되어 있기 때문에 이 데이터셋을 읽는 후속 애플리케이션은 규칙이 몇 개든 같은 방식으로 처리할 수 있습니다.

> **중간 요약**: 규칙 출력은 출력 데이터셋의 열과 타입을 강제하는 폼이며, 같은 출력을 쓰는 모든 규칙의 결과는 한 데이터셋에 모입니다. 스키마가 다른 결과가 필요하면 출력을 여러 개 두거나 파라미터를 선택 사항으로 만듭니다.

## 정리

- 규칙 로직은 입력, 로직 블록, 규칙 출력의 세 부분으로 구성됩니다.
- 입력은 데이터셋이나 객체이며, 사용 가능한 목록은 워크플로 구성에서 정해집니다. 다중 데이터소스, 다중 머티리얼라이제이션, 편집 전용 속성을 가진 객체 타입은 지원되지 않습니다.
- 로직 블록은 필터, 표현식, 집계, 조인을 순차 적용하며 Preview로 중간 결과를 볼 수 있습니다.
- 규칙 출력은 출력 데이터셋의 열과 타입을 강제하고, 같은 출력을 쓰는 규칙들의 결과는 한 데이터셋에 합쳐집니다.
