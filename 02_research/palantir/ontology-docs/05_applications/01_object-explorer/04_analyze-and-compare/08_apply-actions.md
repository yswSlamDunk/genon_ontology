# 액션 적용하기 (Apply Actions)

- 원문: https://www.palantir.com/docs/foundry/object-explorer/apply-actions/
- 사이드바 위치: Applications > Object Explorer > Analyze and compare > Apply Actions

이 페이지는 Object Explorer의 탐색 화면에서 현재 객체 집합이나 선택한 객체를 대상으로 액션을 실행하거나, 다른 애플리케이션에서 열거나, 데이터를 내보내는 방법을 설명합니다. 객체를 조회하는 데서 그치지 않고 실제로 데이터를 바꾸는(라이트백) 지점이 어디에 있는지 보여 줍니다.

탐색(Exploration)에서는 화면 오른쪽 위의 버튼들이 현재 객체 집합이나 선택 항목과 관련된 액션을 분류해 나열합니다. 주요 범주는 세 가지입니다. 데이터 라이트백(writeback)을 위한 **"Actions"**, 현재 탐색을 플랫폼의 다른 애플리케이션으로 가져가는 **"Open In"**, 그리고 Excel 스프레드시트처럼 데이터를 플랫폼 밖으로 내보내는 **"Export"입니다**.

**설명**: 라이트백은 사용자가 화면에서 한 변경을 온톨로지 데이터에 다시 기록하는 것입니다. 원본 데이터셋을 직접 수정하는 대신 액션을 통해 "어떤 객체의 어떤 속성을 어떻게 바꾼다"는 편집(edit)을 기록합니다.

<a id="actions"></a>
### 액션 (Actions)

온톨로지에 구성된 [액션 타입](../../../02_define-ontologies/03_action-types/01_overview.md)이 이름과 설명과 함께 맨 먼저 표시됩니다. 하나를 선택하면 파라미터를 입력하고 액션을 제출할 수 있는 양식이 열립니다. 탐색에서 현재 선택된 객체 집합(선택한 객체가 없으면 모든 객체)이 양식에 바로 전달되므로, 나머지 파라미터만 설정하면 됩니다. 선택된 객체 수가 1000개를 넘으면 액션을 사용할 수 없습니다.

Object Explorer는 선택된 관련 객체로 액션 파라미터를 미리 채웁니다. 어떤 파라미터를 미리 채워야 할지 불확실한 경우에는 결정을 사용자에게 맡기고 미리 채우지 않습니다.

**설명**: 예를 들어 "항공편 상태 변경"이라는 액션 타입에 파라미터가 `flights`(항공편 객체 목록)와 `newStatus`(문자열) 두 개 있다고 합시다. 결과 표에서 항공편 5건을 체크하고 액션을 열면 `flights`에는 그 5건이 자동으로 들어가고, 사용자는 `newStatus`만 입력하면 됩니다. 반대로 항공편 객체를 받는 파라미터가 두 개(예: `originalFlight`, `replacementFlight`)라면 어느 쪽에 넣어야 할지 정할 수 없으므로 미리 채우지 않습니다.

<a id="opening-in-other-applications"></a>
### 다른 애플리케이션에서 열기 (Opening in other applications)

현재 결과 집합을 다른 애플리케이션에서 열 수 있는 방법이 있으면 **"Open In"** 제목 아래에 표시됩니다.

<a id="export"></a>
### 내보내기 (Export)

Excel로 내보내기나 객체 ID를 클립보드에 복사하기처럼 객체 집합을 내보내는 방법이 여기에 표시됩니다.

## 정리

- 탐색 화면 오른쪽 위에는 **Actions**, **Open In**, **Export** 세 범주의 버튼이 있습니다.
- **Actions**는 온톨로지의 액션 타입을 실행하며, 선택한 객체(없으면 전체)가 파라미터로 자동 전달되고 1000개를 넘으면 사용할 수 없습니다.
- 어느 파라미터에 넣을지 애매하면 미리 채우지 않고 사용자에게 맡깁니다.
- **Open In**은 다른 애플리케이션에서 결과를 열고, **Export**는 Excel 내보내기나 객체 ID 복사 같은 방법을 제공합니다.
