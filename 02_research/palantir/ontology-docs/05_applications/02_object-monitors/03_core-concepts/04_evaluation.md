# 평가 (Evaluation)

- 원문: https://www.palantir.com/docs/foundry/object-monitors/evaluation/
- 사이드바 위치: Applications > Object Monitors [Sunset] > Core concepts > Evaluation

이 페이지는 객체 모니터가 조건을 언제, 어떤 방식으로 검사하는지(평가, evaluation)를 설명합니다. 변경을 거의 즉시 감지하는 실시간 평가, 최대 24시간 간격으로 검사하는 폴링 기반 비실시간 평가, 테스트용 수동 평가의 세 방식과 각각의 조건을 다룹니다. 모니터가 "얼마나 빨리 반응하는가"를 결정하는 부분입니다.

**주의**: 단계적 종료(Sunset). Object Monitors는 [Automate](https://www.palantir.com/docs/foundry/automate/overview/)로 대체되었습니다. Automate는 이전 버전과 완전히 호환되는 제품으로, 플랫폼의 모든 비즈니스 자동화를 위한 단일 진입점을 제공합니다.

객체 모니터는 구독자별로 개별적으로 평가되며, 액션 효과도 구독자별로 개별 실행됩니다. 이렇게 하면 데이터 접근 권한과 사용자 속성에 의존하는 액션 검증이 지켜지면서도, 사용자가 각자의 워크플로에 맞게 객체 모니터를 구성할 수 있습니다.

**설명**: 구독자가 앨리스와 밥 두 명인 모니터가 있다고 합시다. 앨리스는 모든 지역의 주문을 볼 수 있고 밥은 서울 지역 주문만 볼 수 있다면, 같은 모니터라도 앨리스 기준으로 평가하면 객체 5건이, 밥 기준으로 평가하면 2건이 감지될 수 있습니다. 구독자마다 따로 평가하기 때문에 밥은 자신이 볼 권한이 없는 객체에 대한 알림을 받지 않습니다. 액션도 각 구독자 이름으로 실행되므로 그 사용자의 권한과 제출 조건(submission criteria)이 적용됩니다.

<a id="realtime-evaluation"></a>
### 실시간 평가 (Realtime evaluation)

일부 입력과 조건의 조합은 실시간 평가를 지원합니다. 실시간 평가를 지원하는 객체 모니터는 계속해서 평가됩니다. 알림이나 액션은 보통 변경이 감지되고 몇 분 안에 실행됩니다. 파이프라인 빌드에서 대량의 변경이 동기화되면, 해당 객체를 입력으로 쓰는 모니터의 평가와 그에 따른 액션이나 알림 실행에 더 오랜 시간이 걸릴 수 있습니다.

실시간 평가를 지원하려면 다음이 모두 참이어야 합니다.

* 입력 객체 타입이 온톨로지 구성에서 [Object Storage v2](../../../06_ontology-architecture/01_overview-and-getting-started/01_overview.md#evolution-of-the-ontology-backend)로 마이그레이션되어 있어야 합니다.
* 입력 객체 타입의 객체 인스턴스가 1,000만 개 미만이어야 합니다. 조건이 실시간으로 평가되고 있는데 새 객체가 추가되어 객체 타입이 이 한도를 넘어서면, 모니터 평가가 실패합니다.
* 입력 객체 집합 정의가 문자열에 대한 정확 일치(exact-match) 필터, 숫자 범위, 불리언 속성만 사용해야 합니다.
* 입력 객체 집합 정의에 연결된 객체(linked object)의 속성이나 배열(array) 속성이 포함되지 않아야 합니다.
* 규칙이 입력에 객체가 추가되거나 제거되는 [이벤트 조건](03_condition.md#event)을 사용해야 합니다.

**설명**: 이 제약들은 "변경 하나가 들어왔을 때 그 객체가 집합에 들어가는지 빠르게 판단할 수 있는가"와 관련이 있는 것으로 이해할 수 있습니다. 예를 들어 `status = "Open"`(정확 일치)이나 `amount BETWEEN 100 AND 500`(숫자 범위)은 변경된 객체 한 개의 값만 보고 바로 판단할 수 있습니다. 반면 연결된 객체의 속성으로 거는 필터는 다른 객체 타입까지 조회해야 판단할 수 있습니다.

<a id="scheduling-monitors"></a>
#### 모니터 스케줄링 (Scheduling monitors)

**참고**: 실시간 평가는 파이프라인 빌드에서 들어오는 변경에만 적용됩니다. 액션을 통해 이루어진 변경은 Object Monitors가 감지하기까지 최대 7시간이 걸릴 수 있습니다. 이 시간을 줄이려면, 즉시 알림을 보내야 하는 액션에 [알림 규칙](../../../02_define-ontologies/03_action-types/12_side-effects/03_set-up-notification.md#add-a-notification)을 포함합니다.

실시간 평가는 현재 모니터 스케줄링을 지원하지 않지만, TypeScript로 현재 시각이나 요일을 확인해 객체 모니터가 특정 시간대에 이벤트를 감지했을 때만 실행되는 함수 기반 액션을 구성할 수 있습니다. 다음 코드 조각이 그 예입니다.

```typescript
@Edits(ObjectType)
@OntologyEditFunction()
public someEditFunction(): void {
    const currentTime = Timestamp.now()
    const currentHour = currentTimestamp.getHours();
    if (currentHour >= 0 && currentHour < 12) {
      // 편집 수행
    }
}
```

**설명**: 이 함수는 모니터가 발동시킨 액션 안에서 실행되는 온톨로지 편집 함수입니다(`@OntologyEditFunction()`). `Timestamp.now()`로 현재 시각을 얻고 시(hour)를 꺼내, 0시부터 12시 전까지일 때만 편집을 수행합니다. 즉 모니터 자체는 언제든 이벤트를 감지하지만, 실제 데이터 변경은 오전에만 일어나도록 액션 쪽에서 걸러 내는 방식입니다. 원문 코드에서는 변수를 `currentTime`으로 선언한 뒤 `currentTimestamp`로 사용하고 있으므로, 실제로 쓸 때는 이름을 하나로 맞춰야 합니다.

> **중간 요약**: 모니터는 구독자별로 평가됩니다. OSv2 객체 타입, 1,000만 개 미만, 단순 필터, 연결 속성과 배열 속성 미사용, 추가/제거 이벤트 조건을 모두 만족하면 실시간으로 평가되어 몇 분 안에 반응합니다. 다만 실시간 평가는 파이프라인 빌드 변경에만 적용되고, 액션으로 생긴 변경은 최대 7시간 늦게 감지될 수 있습니다.

<a id="non-realtime-evaluation"></a>
### 비실시간 평가 (Non-realtime evaluation)

실시간으로 평가할 수 없는 객체 모니터는 폴링(polling) 방식으로 평가됩니다. 모니터는 이전 평가로부터 24시간 이내에 평가되는 것이 보장됩니다. 많은 모니터를 평가하는 부하를 분산하기 위해, 폴링 기반 평가가 일어나는 구체적인 시각은 명시적으로 예약할 수 없습니다. 폴링 기반 모니터의 마지막 평가 시각은 저장되어 Object Monitors 애플리케이션 화면의 모니터 개요 패널에 표시됩니다.

**설명**: 폴링은 변경이 생길 때 알림을 받는 대신, 일정 간격으로 직접 가서 "지금 상태가 어떤가"를 다시 계산하는 방식입니다. 예를 들어 어떤 모니터가 오전 3시에 평가되었다면 다음 평가는 늦어도 다음 날 오전 3시 전에 일어나지만, 그 사이 정확히 언제일지는 지정할 수 없습니다.

<a id="manual-evaluation"></a>
### 수동 평가 (Manual evaluation)

비실시간 객체 모니터는 Object Explorer 화면에서 수동으로 평가할 수도 있습니다. 이 옵션은 주로 비실시간 모니터를 설정할 때 테스트하는 용도입니다.

![Object Explorer의 수동 평가 버튼](https://www.palantir.com/docs/resources/foundry/object-monitors/manual_evaluation_button.png)

## 정리

- 모니터는 구독자별로 평가되고 액션도 구독자별로 실행되어, 각 사용자의 데이터 권한과 액션 검증이 적용됩니다.
- 실시간 평가는 OSv2, 1,000만 개 미만, 단순 필터, 연결 속성과 배열 속성 미사용, 추가/제거 이벤트 조건을 모두 만족해야 하며 보통 몇 분 안에 반응합니다.
- 실시간 평가는 파이프라인 빌드 변경에만 적용되며, 액션으로 생긴 변경은 최대 7시간이 걸릴 수 있으므로 즉시 알림이 필요하면 액션에 알림 규칙을 넣습니다.
- 그 밖의 모니터는 폴링 방식으로 24시간 이내에 평가되며 시각은 지정할 수 없고, 테스트를 위해 Object Explorer에서 수동 평가할 수 있습니다.
