# 오류 레퍼런스 (Error reference)

- 원문: https://www.palantir.com/docs/foundry/object-monitors/errors/
- 사이드바 위치: Applications > Object Monitors [Sunset] > Error reference

이 페이지는 Object Monitors 애플리케이션이나 Object Explorer의 **Monitors** 화면을 사용할 때 마주칠 수 있는 주요 오류 범주를 설명합니다. 모니터 평가 자체가 실패하는 경우, 평가는 성공했지만 알림이나 액션 실행이 실패하는 경우, 그리고 권한 문제로 실패하는 경우를 나누어 원인과 확인 방법을 다룹니다.

**주의**: 지원 종료(Sunset). Object Monitors는 [Automate](https://www.palantir.com/docs/foundry/automate/overview/)로 대체되었습니다. Automate는 완전히 하위 호환되는 제품으로, 플랫폼의 모든 비즈니스 자동화를 위한 단일 진입점을 제공합니다.

이 페이지는 Object Monitors 애플리케이션이나 Object Explorer의 **Monitors** 화면을 사용할 때 마주칠 수 있는 일반적인 오류 범주 일부를 설명합니다.

<a id="evaluation-errors"></a>
## 평가 오류 (Evaluation errors)

모니터는 기반 데이터의 문제로 평가에 실패할 수 있습니다. 모니터는 자동으로 재시도되지만, 일부 오류는 수동 개입이 필요할 수 있습니다. 예를 들어 모니터링 대상 객체 타입이 삭제되면, 그 타입의 객체를 포함하는 입력을 사용하는 모니터는 평가에 실패합니다.

<a id="monitor-out-of-sync"></a>
### 모니터 동기화 어긋남 (Monitor out of sync)

객체 모니터는 입력을 정의하기 위해 [저장된 탐색(saved exploration)](../01_object-explorer/04_analyze-and-compare/06_save-explorations.md)에 대한 참조를 사용합니다. 이 참조는 동적이지 않으며, 모니터를 저장하는 시점에 존재하는 탐색 상태에 따라 저장됩니다. 탐색이 바뀌어도 모니터를 업데이트하지 않으면 모니터는 탐색의 예전 상태로 계속 평가합니다. 이 경우 모니터에 경고 배너가 표시됩니다.

![동기화가 어긋난 모니터의 경고 배너](https://www.palantir.com/docs/resources/foundry/object-monitors/monitor_out_of_sync_banner.png)

**설명**: 즉 원문의 "참조"는 저장 시점 값의 복사본입니다. 프로그래밍 용어로는 모니터가 저장된 탐색 객체의 포인터를 들고 있는 것이 아니라, 저장 시점의 필터 조건 값을 복사해 들고 있는 것입니다. 예를 들어 저장된 탐색의 필터가 "origin = JFK"일 때 모니터를 저장하고, 나중에 탐색을 "origin = SFO"로 바꿔도 모니터는 여전히 JFK 조건으로 평가하며, 모니터를 다시 저장해야 SFO 조건이 반영됩니다.

> **중간 요약**: 평가 오류는 기반 데이터 문제(예: 대상 객체 타입 삭제)로 생기며, 자동 재시도로 해결되지 않으면 수동 개입이 필요합니다. 모니터는 저장 시점의 탐색 상태를 기준으로 평가하므로, 탐색을 바꾼 뒤 모니터를 업데이트하지 않으면 동기화 어긋남 경고가 표시됩니다.

<a id="notification-effect-errors"></a>
## 알림 효과 오류 (Notification effect errors)

모니터 평가가 성공한 뒤에도 알림 전송이 실패할 수 있습니다. 이런 경우 이력(history) 이벤트에 해당 이벤트의 알림이 구독자에게 전송되지 않았음을 나타내는 태그가 오류 식별자와 오류 메시지 같은 추가 세부 정보와 함께 표시됩니다.

<a id="action-effect-errors"></a>
## 액션 효과 오류 (Action effect errors)

모니터 평가가 성공한 뒤에도 액션 효과가 실행에 실패할 수 있습니다. 이 실패는 여러 이유로 일어날 수 있는데, 액션 로직이 바뀌어 모니터에 저장된 입력 구성과 호환되지 않게 되었거나, 액션의 [제출 조건(submission criteria)](../../02_define-ontologies/03_action-types/08_submission-criteria.md)이 충족되지 않은 경우 등이 있습니다. 이런 실패가 일어나면 이력 이벤트 타임라인에 해당 이벤트에서 하나 이상의 액션이 실행에 실패했음을 나타내는 태그가 관련 오류 세부 정보와 함께 표시됩니다.

**설명**: 평가와 효과(effect)는 별도 단계입니다. 평가 단계는 "조건이 충족되었는가"를 계산하고, 효과 단계는 그 결과로 알림을 보내거나 액션을 제출합니다. 그래서 평가는 성공했는데 알림이나 액션만 실패하는 경우가 생기며, 이때는 이력 타임라인의 태그와 오류 메시지를 확인해 원인을 찾습니다. 예를 들어 액션 타입에 필수 파라미터가 새로 추가되었는데 모니터 구성에는 그 값이 없다면, 저장된 입력 구성과 호환되지 않아 액션 효과가 실패합니다.

<a id="permissions"></a>
## 권한 (Permissions)

모니터 평가는 개별 구독자의 권한을 사용합니다. 이는 모니터 평가와 그에 이어지는 액션이나 알림 효과가, 모니터가 평가되는 시점에 사용자가 접근할 수 있는 데이터만 항상 반영하도록 하기 위함입니다. 사용자에게 입력 객체 타입, 저장된 탐색, 객체 모니터 중 하나 이상을 볼 권한이 없으면, 평가가 성공하는 대신 권한 관련 오류 메시지를 보게 될 수 있습니다. 모니터와 그 입력을 공유 [프로젝트(Projects)](https://www.palantir.com/docs/foundry/security/projects-and-roles/)에 저장할 것을 강력히 권장합니다.

**설명**: 같은 모니터라도 구독자마다 결과가 다를 수 있다는 뜻입니다. 예를 들어 행 단위 권한 때문에 구독자 A는 Flight 객체 1,000개를 보고 구독자 B는 그중 200개만 볼 수 있다면, 각자의 권한으로 평가되므로 B는 자신이 볼 수 없는 800개에 대한 알림을 받지 않습니다. 저장된 탐색이 개인 폴더에 있으면 다른 구독자는 그것을 볼 권한이 없어 오류가 나므로, 공유 프로젝트에 두라고 권장하는 것입니다.

> **중간 요약**: 평가가 성공해도 알림이나 액션 효과는 따로 실패할 수 있으며, 이력 타임라인의 태그와 오류 세부 정보로 확인합니다. 모니터는 구독자 개인의 권한으로 평가되므로 입력 객체 타입, 저장된 탐색, 모니터 자체를 볼 권한이 필요하고, 이를 위해 공유 프로젝트에 저장하는 것이 권장됩니다.

## 정리

- Object Monitors는 지원 종료 단계이며 Automate로 대체되었습니다.
- 평가 오류는 기반 데이터 문제로 생기며, 모니터는 저장 시점의 탐색 상태로 평가되므로 탐색 변경 후에는 모니터를 다시 저장해야 합니다.
- 알림 효과와 액션 효과는 평가와 별개로 실패할 수 있고, 이력 이벤트의 태그와 오류 정보로 원인을 확인합니다.
- 평가는 각 구독자의 권한으로 수행되므로, 모니터와 입력은 공유 프로젝트에 두는 것이 좋습니다.
