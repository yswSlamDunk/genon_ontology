# 모니터링 제한 (Monitoring limits)

- 원문: https://www.palantir.com/docs/foundry/object-monitors/limits/
- 사이드바 위치: Applications > Object Monitors [Sunset] > Monitoring limits

이 페이지는 객체 모니터링(object monitoring)에 적용되는 규모 제한을 정리합니다. 모니터가 시간당, 하루당 트리거될 수 있는 횟수, 입력 객체 수, 구독자 수, 실시간 실행이 가능한 객체 타입 크기와, 각 제한에 도달했을 때의 동작을 표로 보여 줍니다.

**주의**: 지원 종료(Sunset). Object Monitors는 [Automate](https://www.palantir.com/docs/foundry/automate/overview/)로 대체되었습니다. Automate는 완전히 하위 호환되는 제품으로, 플랫폼의 모든 비즈니스 자동화를 위한 단일 진입점을 제공합니다.

객체 모니터링은 실행과 트리거 효과의 성능을 보장하기 위해 몇 가지 제한을 둡니다. 이 제한과 예상되는 동작은 아래 표에 나와 있습니다.

<a id="scale-limits"></a>
### 규모 제한 (Scale limits)

| 설명 | 제한 | 제한에 도달했을 때의 동작 |
| ---------------------------------------------- | ----------- | ------------------------------ |
| 모니터가 시간당 트리거될 수 있는 횟수 | 12 | 모니터가 자동으로 비활성화됩니다 |
| 모니터가 하루에 트리거될 수 있는 횟수 | 96 | 모니터가 자동으로 비활성화됩니다 |
| 객체 추가/제거(object added/removed) 조건의 최대 입력 크기 | 100K | 모니터 저장 시 오류 메시지, 또는 입력 집합이 10만 개 객체를 넘어서면 모니터 평가 시 런타임 오류 |
| 모니터 하나의 최대 구독자 수 | 30 | 모니터 저장 시 오류 메시지 |
| 실시간 실행을 위한 객체 타입의 최대 크기 | 10M | 모니터 저장 시 오류 메시지, 또는 객체 타입의 전체 객체 수가 제한을 넘어서면 모니터 평가 시 런타임 오류 |

**설명**: 표의 K는 1,000, M은 1,000,000을 뜻하므로 100K는 10만 개, 10M은 1,000만 개입니다. 트리거 제한을 환산하면 시간당 12회는 평균 5분에 한 번, 하루 96회는 평균 15분에 한 번입니다. 너무 자주 트리거되는 모니터는 조건이 지나치게 느슨하거나 데이터가 요동치고 있을 가능성이 높으므로, 알림 폭주를 막기 위해 자동으로 꺼집니다. 입력 크기 제한은 "저장할 때"와 "실행할 때" 두 번 검사된다는 점에 유의하세요. 저장 시점에는 9만 개여서 통과했더라도, 이후 데이터가 늘어 10만 개를 넘으면 그때부터 평가가 런타임 오류로 실패합니다.

## 정리

- Object Monitors는 지원 종료 단계이며 Automate로 대체되었습니다.
- 모니터는 시간당 12회, 하루 96회를 넘게 트리거되면 자동으로 비활성화됩니다.
- 객체 추가/제거 조건의 입력은 최대 10만 개, 실시간 실행 대상 객체 타입은 최대 1,000만 개이며, 저장 시와 평가 시 모두 검사됩니다.
- 모니터 하나의 구독자는 최대 30명입니다.
