# 프로세스 마이닝 (Process mining)

- 원문: https://www.palantir.com/docs/foundry/machinery/process-mining/
- 사이드바 위치: Applications > Machinery > Process mining

이 페이지는 Machinery에서 데이터로부터 프로세스 모델을 자동으로 도출하는 프로세스 마이닝(process mining) 모드를 설명합니다. 직접 그린 프로세스 정의가 실제 데이터와 맞는지 확인하거나, 데이터에 나타난 상태와 전이를 정의에 추가할 때 사용합니다. 마이닝 결과 표시 방식, 설정, 잡음을 걸러 내는 필터를 다룹니다.

Machinery 애플리케이션으로 프로세스 모델을 만드는 방법은 여러 가지입니다. [상태와 전이를 직접 그려서](03_draw-a-graph.md) 프로세스를 수동으로 정의하거나, *프로세스 마이닝으로* 과거 관측 기록에서 프로세스 모델을 자동으로 도출할 수 있습니다.

프로세스 마이닝은 Machinery에서 전용 모드로 지원됩니다. [데이터 연결을 구성하고 나면](04_connect-data.md) 메인 툴바에서 프로세스 마이닝 워크플로를 열 수 있습니다.

![필터가 설정된 프로세스 마이닝 화면.](https://www.palantir.com/docs/resources/foundry/machinery/process-mining.png)

마이닝 모드에서는 기존 프로세스 정의 위에 데이터에 실제로 나타나는 상태와 전이가 겹쳐서 표시됩니다. 스타일은 다음을 뜻합니다.

* **Amber(호박색):** 마이닝 결과입니다. 확인하면 이 요소들이 프로세스 정의에 추가됩니다.
* **Gray(회색):** 데이터에 나타나지만 이미 프로세스 정의에 있는 요소입니다.
* **Dashed line(점선):** 현재 프로세스 정의에 있지만 데이터에서는 참조되지 않는 요소입니다. 프로세스 정의에 문제가 있다는 신호일 수 있습니다.

**설명**: 세 가지 색은 "정의에 있는 요소 집합 D"와 "데이터에 나타난 요소 집합 M"을 비교한 결과입니다. 호박색은 M에만 있는 것(M - D), 회색은 둘 다에 있는 것(M ∩ D), 점선은 D에만 있는 것(D - M)입니다. 예를 들어 정의에 `created`, `approved`, `paid`가 있고 데이터에 `created`, `approved`, `rejected`가 나온다면, `rejected`는 호박색, `created`와 `approved`는 회색, `paid`는 점선으로 표시됩니다.

<a id="settings"></a>
## 설정 (Settings)

마이닝 사이드 패널 상단에서 마이닝에 사용할 데이터소스를 구성할 수 있습니다. 프로세스 객체, 로그 객체, 또는 둘 다를 선택할 수 있습니다. 프로세스 객체 타입에서 최신 상태 값만 마이닝하는 것도 가능하지만, 로그 객체 타입을 권장합니다.

또한 마이닝할 요소를 선택할 수 있습니다. 상태, 전이, 또는 둘 다입니다. 관련 데이터소스가 있다면 일반적으로 상태와 전이를 모두 마이닝하는 것이 좋습니다.

<img src="https://www.palantir.com/docs/resources/foundry/machinery/mining-settings.png" width=350 alt="마이닝 사이드 패널 설정." >

**설명**: 프로세스 객체 타입에는 객체마다 현재 상태 하나만 있으므로, 여기서는 "어떤 상태 값들이 존재하는가"만 알 수 있고 전이(어느 상태에서 어느 상태로 갔는가)는 알 수 없습니다. 전이를 마이닝하려면 Old state와 New state를 담은 로그 객체가 필요하기 때문에 로그 객체 타입을 권장하는 것입니다.

> **중간 요약**: 마이닝 모드는 정의와 데이터를 겹쳐 보여 주며, 새로 발견된 요소(호박색), 일치하는 요소(회색), 데이터에 없는 요소(점선)를 구분합니다. 데이터소스는 로그 객체 타입을 권장하고, 가능하면 상태와 전이를 모두 마이닝합니다.

<a id="filtering"></a>
## 필터링 (Filtering)

수집된 데이터에는 잡음과 오류가 섞여 있는 경우가 많습니다. 마이닝의 원시 출력은 지나치게 복잡하거나 예상치 못한 결과를 포함할 수 있습니다. Machinery에서는 데이터의 상태와 전이를 필터링해 프로세스를 더 쓸모 있게 표현하도록 도울 수 있습니다.

<img src="https://www.palantir.com/docs/resources/foundry/machinery/filters-and-exclusions.png" width=350 alt="마이닝 필터와 제외 항목." >

마이닝 사이드 패널 하단에서 필터를 구성할 수 있습니다.

* **Transition filter(전이 필터):** 모든 전이를 발생 횟수 순으로 정렬해 가장 자주 일어나는 전이를 맨 위에 둡니다. 그다음 그 값들의 누적 합을 계산해 전체 전이 중 상위 *x* %를 남깁니다. 이렇게 하면 드물게 일어나는 전이들의 꼬리 부분이 잘려 나갑니다.
* **Excluded elements(제외 요소):** 프로세스 정의에 받아들이지 않을 잘못된 상태 값이나 전이의 목록입니다. 이 제외 값들은 저장할 때 함께 유지되며 시간이 지나면서 관리할 수 있습니다.

**설명**: 전이 필터를 예시 데이터로 계산해 보겠습니다. 전이 발생 횟수가 A 60건, B 25건, C 10건, D 4건, E 1건(합계 100건)이라면 누적 비율은 A 60%, B 85%, C 95%, D 99%, E 100%입니다. *x* = 90으로 두면 누적 비율이 90%에 이를 때까지의 전이를 남기므로 A, B, C가 남고 D와 E가 잘려 나갑니다(경계에 걸친 전이를 포함하는지는 원문에 명시되어 있지 않습니다).

> **중간 요약**: 원시 마이닝 결과는 잡음이 많으므로, 빈도 기준 누적 상위 *x* %만 남기는 전이 필터와, 저장되어 계속 관리되는 제외 요소 목록으로 정리합니다.

## 정리

- 프로세스 마이닝은 데이터 연결을 구성한 뒤 메인 툴바에서 여는 Machinery의 전용 모드입니다.
- 마이닝 결과는 기존 정의 위에 겹쳐 표시되며, 새 요소는 호박색, 이미 있는 요소는 회색, 데이터에 없는 정의 요소는 점선입니다.
- 데이터소스는 프로세스 객체, 로그 객체, 또는 둘 다를 쓸 수 있으나 로그 객체 타입을 권장합니다.
- 전이 필터로 드문 전이를 잘라 내고, 제외 요소 목록으로 잘못된 값을 영구적으로 걸러 냅니다.
