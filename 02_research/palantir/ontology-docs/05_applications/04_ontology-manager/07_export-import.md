# 온톨로지 내보내기, 편집, 가져오기 (Export, edit, and import an Ontology)

- 원문: https://www.palantir.com/docs/foundry/ontology-manager/export-import/
- 사이드바 위치: Applications > Ontology Manager > Export, edit, and import an Ontology

이 페이지는 온톨로지 스키마 정의를 JSON 파일로 내보내고, 편집기에서 고친 뒤, 다시 Foundry로 가져오는 기능을 설명합니다. 화면 대신 코드로 온톨로지를 편집하거나, 한 온톨로지의 작업 상태를 다른 온톨로지로 복사하려는 고급 사용자를 위한 기능입니다.

**주의**: 내보낸 JSON 스키마는 시간이 지나면서 바뀔 수 있으므로 이 형식에 의존해서는 안 됩니다.

온톨로지 스키마 정의는 [JSON 파일 ↗](https://en.wikipedia.org/wiki/JSON)로 저장됩니다. 온톨로지 JSON 파일은 내보낸 다음 코드 편집기나 텍스트 편집기로 편집하고 다시 Foundry로 가져올 수 있습니다. 이 가져오기/내보내기 기능으로 고급 사용자는 다음 두 가지 워크플로를 사용할 수 있습니다.

* 온톨로지 편집을 코드로 하고 싶다면, 온톨로지 JSON 파일을 내보내고, 코드 편집기나 텍스트 편집기에서 JSON 파일을 직접 편집한 다음, 수정한 온톨로지 JSON 파일을 다시 플랫폼으로 가져오는 방식으로 Ontology Manager 인터페이스를 거치지 않을 수 있습니다.
* 한 온톨로지의 작업 상태(working state)를 다른 온톨로지로 복사하고 싶다면, 온톨로지의 현재 상태를 JSON 파일로 내보낸 다음 복사한 JSON을 다시 플랫폼으로 가져올 수 있습니다(원하는 변경은 코드 편집기에서 JSON에 반영).

![온톨로지 JSON 편집하기](https://www.palantir.com/docs/resources/foundry/ontology-manager/import-export-edit-ontology-json.png)

**설명**: 스키마 정의란 데이터 자체(객체의 속성 값)가 아니라 구조, 즉 어떤 객체 타입이 있고 각 타입에 어떤 속성과 기본 키가 있으며 어떤 링크 타입으로 연결되는지에 대한 정의입니다. 데이터베이스에서 행 데이터가 아니라 `CREATE TABLE` 문만 덤프하는 것에 해당합니다. 작업 상태는 아직 저장하지 않은 내 변경이 반영된 온톨로지 상태를 뜻합니다. "형식에 의존하지 말라"는 경고는 이 JSON의 필드 구조가 예고 없이 바뀔 수 있으니, 이 파일을 자동으로 생성하거나 파싱하는 프로그램을 만들어 장기간 운영하는 용도로는 쓰지 말라는 의미입니다.

> **중간 요약**: 온톨로지 스키마는 JSON으로 내보내고 가져올 수 있으며, 코드로 직접 편집하거나 다른 온톨로지로 작업 상태를 복사하는 데 씁니다. 단, JSON 형식은 바뀔 수 있으므로 의존하면 안 됩니다.

<a id="export"></a>
## 내보내기 (Export)

애플리케이션 홈 페이지에서 **Advanced** 설정 페이지를 선택한 다음 **Export**를 선택하면 온톨로지 작업 상태를 내보낼 수 있습니다. 내보내기에는 작업 상태에 있는 모든 변경 사항이 포함됩니다.

<a id="import"></a>
## 가져오기 (Import)

애플리케이션 홈 페이지에서 **Advanced** 설정 페이지를 선택한 다음 **Import**를 선택하면 이전에 내보낸 온톨로지 작업 상태를 가져올 수 있습니다. 로컬 드라이브에서 온톨로지 파일을 고르라는 안내가 나타납니다.

다음으로 **Import**를 선택하면 JSON 파일로부터 애플리케이션 안의 작업 상태 전체가 다시 만들어집니다. 파일에서 이루어진 변경 중 저장이 필요한 변경의 개수가 애플리케이션 헤더에 표시됩니다.

**주의**: 속성에 조건부 서식(conditional formatting) 규칙이 설정된 상태로 내보낸 온톨로지 작업 상태는, 그것을 내보낸 온톨로지가 아닌 다른 온톨로지로 가져올 수 없습니다.

**설명**: 가져오기는 곧바로 온톨로지를 바꾸지 않고 작업 상태를 다시 만들 뿐입니다. 헤더에 표시된 변경 개수를 확인한 뒤 저장해야 실제 온톨로지에 반영됩니다. 조건부 서식은 속성 값에 따라 표시 색상 등을 바꾸는 규칙으로, 이 규칙 집합이 원래 온톨로지에 묶여 있어 다른 온톨로지로 옮겨지지 않습니다.

> **중간 요약**: **Advanced** 설정 페이지에서 **Export**로 작업 상태를 내보내고, **Import**로 JSON 파일에서 작업 상태를 다시 만듭니다. 가져온 변경은 저장해야 하며, 조건부 서식 규칙이 있으면 다른 온톨로지로는 가져올 수 없습니다.

<a id="troubleshooting"></a>
## 문제 해결 (Troubleshooting)

<a id="error-ontologymetadataunreferencedrulesets"></a>
### 오류: `OntologyMetadata:UnreferencedRuleSets`

`OntologyMetadata:UnreferencedRuleSets` 오류가 발생한다면, 해당 온톨로지에 정의되어 있지 않아 옮겨 올 수 없는 조건부 서식 규칙이 포함된 온톨로지 작업 상태를 가져오려고 하는 것입니다. 가져오기 전에 온톨로지 작업 상태에서 조건부 서식 규칙을 삭제해야 합니다.

## 정리

- 온톨로지 스키마 정의를 JSON으로 내보내고, 편집하고, 다시 가져올 수 있습니다. JSON 형식은 바뀔 수 있으므로 의존하지 않습니다.
- 용도는 코드로 직접 온톨로지를 편집하는 것과, 한 온톨로지의 작업 상태를 다른 온톨로지로 복사하는 것입니다.
- 내보내기와 가져오기는 홈 페이지의 **Advanced** 설정 페이지에서 하며, 가져온 결과는 작업 상태로 들어오므로 저장해야 합니다.
- 조건부 서식 규칙이 있는 작업 상태는 다른 온톨로지로 가져올 수 없고, 이 경우 `OntologyMetadata:UnreferencedRuleSets` 오류가 나므로 규칙을 삭제한 뒤 가져옵니다.
