# Palantir Foundry 온톨로지 전체 요약

- 원문: https://www.palantir.com/docs/foundry/ontology/overview/ (사이드바 "Ontology building" 전체 399페이지)
- 페이지별 번역은 [README.md](README.md)의 목차에서 찾을 수 있습니다.

이 문서는 399페이지 분량의 공식 문서에서 **꼭 알아야 하는 핵심만** 추린 것입니다. 세부 설정 방법, 화면 조작, 제약 사항은 각 페이지 번역을 보면 됩니다.

## 1. 온톨로지란

Palantir의 온톨로지(Ontology)는 회사의 데이터셋, 가상 테이블, 모델 위에 올라가는 **운영 계층(operational layer)입니다**. 테이블의 행과 열을 그대로 쓰는 대신, 그 데이터를 현실의 대상(공장, 장비, 주문, 직원 등)과 그 관계로 다시 정의합니다. 공식 문서는 이것을 조직의 디지털 트윈(digital twin)이라고 부릅니다.

데이터베이스 개념과의 대응은 다음과 같습니다.

| 데이터셋 | 온톨로지 |
|---|---|
| 데이터셋(테이블) | 객체 타입(object type) |
| 행(row) | 객체(object) |
| 열(column) | 속성(property) |
| 셀 값 | 속성 값 |
| 조인(join) | 링크 타입(link type) |

> **중간 요약**: 온톨로지는 테이블 데이터를 "객체, 속성, 링크"로 바꿔 부르는 스키마 계층이면서, 그 위에서 실제 업무가 돌아가도록 만든 운영 시스템입니다.

## 2. 구성 요소 두 갈래: Semantic과 Kinetic

문서는 온톨로지 요소를 두 종류로 나눕니다.

**Semantic 요소 (무엇이 존재하는가)**

- **객체 타입**: 현실의 대상이나 사건의 스키마. 기본 키(primary key)로 객체 하나를 구분하고, 보통 백킹 데이터소스(backing datasource)라는 데이터셋에서 객체를 만듭니다.
- **속성**: 객체 타입의 특성. string, integer, date, geopoint, 시계열(time series), 첨부 파일, 구조체(struct) 등 타입을 가집니다.
- **링크 타입**: 두 객체 타입 사이의 관계. 1:1, 1:N, N:N이 있고, N:N은 별도의 조인 테이블 데이터셋으로 정의합니다.
- **공유 속성(shared property)과 값 타입(value type)**: 여러 객체 타입에서 같은 속성 정의나 값 제약(정규식, 범위 등)을 재사용하기 위한 장치입니다.
- **인터페이스(interface)**: 여러 객체 타입이 공통으로 갖는 형태를 정의한 추상 타입입니다. 프로그래밍 언어의 인터페이스처럼 다형성을 제공합니다. 예를 들어 `Facility` 인터페이스를 `Airport`, `Manufacturing Plant`가 구현하면, `Facility`를 대상으로 만든 화면이나 코드가 두 타입 모두에 동작합니다.

**Kinetic 요소 (무엇을 할 수 있는가)**

- **액션 타입(action type)**: 사용자가 한 번에 수행하는 객체 생성, 수정, 삭제, 링크 변경의 묶음입니다. 하나의 트랜잭션으로 처리됩니다. 입력 파라미터, 규칙(rule), 제출 조건(submission criteria, 누가 어떤 조건에서 실행 가능한지), 부수 효과(알림, 웹훅으로 외부 시스템 호출)를 함께 정의합니다.
- **함수(function)**: TypeScript나 Python으로 작성해 서버에서 실행하는 로직입니다. 객체와 객체 집합을 입력으로 받고, 속성을 읽고, 링크를 따라가고, 온톨로지 편집을 만들 수 있습니다. 액션의 로직(function-backed action), Workshop 화면의 계산 값, 집계, LLM 호출 등에 쓰입니다.

> **중간 요약**: Semantic 요소는 데이터의 구조(명사), Kinetic 요소는 그 데이터를 바꾸는 방법(동사)입니다. 팔란티어 온톨로지의 특징은 후자, 즉 "쓰기"까지 온톨로지 안에 정의한다는 점입니다.

## 3. 왜 이렇게 만드는가

"Why create an Ontology?" 페이지는 운영상의 결정 하나를 네 요소로 봅니다.

1. **Data**: 결정에 쓰는 정보. 원천 시스템 데이터뿐 아니라 사람과 에이전트가 결정하면서 만든 데이터도 포함합니다.
2. **Logic**: 결정을 평가하는 계산. 비즈니스 규칙, 예측 모델, 최적화 모델, LLM 등.
3. **Action**: 결정한 내용을 실제로 실행하고 원천 시스템에 반영하는 것.
4. **Security**: 위 세 가지가 권한 정책을 지키도록 보장하는 것.

일반적인 분석용 데이터 구조는 1번만 다룹니다. 온톨로지는 네 가지를 한 모델에 묶어서, 사람과 AI 에이전트가 같은 객체를 보고, 같은 로직을 쓰고, 같은 액션으로 데이터를 바꾸게 합니다.

## 4. 온톨로지를 관리하는 방법

- **Ontology Manager**: 객체 타입, 속성, 링크, 액션, 인터페이스를 정의하고 수정하는 웹 화면입니다.
- **브랜치와 제안(proposal)**: Git처럼 브랜치에서 온톨로지를 수정하고, 리뷰를 거쳐 메인에 병합합니다.
- **권한**: 온톨로지 리소스(타입 정의)에 대한 권한과, 객체 데이터 자체에 대한 권한(행 단위, 속성 단위 보안 정책)이 따로 있습니다. 객체를 볼 수 있는지는 백킹 데이터셋의 권한과 객체 보안 정책(object security policy)으로 결정됩니다.
- **설계 가이드**: Best practices, Structural guidance, Anti-patterns, Validation 네 페이지가 객체 타입을 어떻게 나누고 링크를 어떻게 설계할지 원칙을 제시합니다.

## 5. 내부 구조 (Ontology architecture)

온톨로지 백엔드는 여러 마이크로서비스로 구성됩니다.

| 서비스 | 역할 |
|---|---|
| Ontology Metadata Service (OMS) | 객체 타입, 링크 타입, 액션 타입 같은 정의(메타데이터)를 저장 |
| Object databases (Object Storage v2) | 객체 데이터를 인덱싱해 저장하고 빠른 조회 제공. v1(Phonograph)은 폐기 예정 |
| Object Set Service (OSS) | 객체 검색, 필터, 집계 등 읽기 요청 처리 |
| Object Data Funnel | 데이터셋, 스트림, 사용자 편집을 읽어 객체 DB에 쓰는(인덱싱) 파이프라인 관리 |
| Actions | 사용자 편집을 객체 DB에 적용 |
| Functions on Objects | 객체를 다루는 서버 측 함수 실행 |

데이터 흐름은 "원천 데이터셋에서 Funnel이 인덱싱, 객체 DB에 저장, OSS가 조회 처리"입니다. 사용자가 액션으로 바꾼 값은 원본 데이터셋을 직접 고치지 않고 별도의 편집(edit)으로 저장됩니다. Funnel이 원본 데이터와 사용자 편집을 합친 결과를 관리하며, 이 합쳐진 결과를 데이터셋으로 만든 것이 머티리얼라이제이션(materialization)입니다.

> **중간 요약**: 정의는 OMS, 저장은 Object Storage v2, 읽기는 OSS, 쓰기는 Funnel(데이터)과 Actions(사용자 편집)가 맡습니다. 원본 데이터와 사용자 편집은 따로 저장되고 조회할 때 합쳐집니다.

## 6. 온톨로지 위에서 동작하는 앱

온톨로지를 만들면 아래 앱들이 객체를 공통 데이터로 사용합니다.

- **Object Explorer**: 객체 검색, 필터, 차트, 링크된 객체로 이동, 액션 실행
- **Object Views**: 객체 하나에 대한 상세 화면(속성, 링크된 객체, 관련 앱)
- **Vertex**: 객체와 링크를 그래프로 보고, 시나리오로 변화를 시뮬레이션
- **Map**: 위치 속성을 가진 객체를 지도에 표시
- **Machinery**: 프로세스(상태 전이)를 그래프로 그리고 분석
- **Foundry Rules**: 코드 없이 규칙을 만들어 객체에 적용하고 알림 생성
- **Dynamic Scheduling**: 간트 차트 형태로 일정 객체를 배치하고 검증
- **Vulcan**: 온톨로지에 저장된 CAD 모델, 도면, 포인트 클라우드를 3D로 렌더링
- 이 밖에 Workshop(로우코드 앱 빌더), Quiver(분석)도 온톨로지를 사용합니다.

그 외에 **Semantic search**(임베딩 벡터 속성으로 의미 기반 검색, LLM에 객체를 근거로 주는 Ontology augmented generation)와 **Ontology scenarios**(실제 데이터를 바꾸지 않고 가정한 편집을 적용해 보는 기능)가 있습니다.

## 7. 한 문단 정리

팔란티어 온톨로지는 테이블 데이터를 객체, 속성, 링크로 다시 정의하고(Semantic), 그 객체를 바꾸는 액션과 함수를 함께 정의하며(Kinetic), 모든 읽기와 쓰기에 같은 권한 모델을 적용하는 운영 플랫폼입니다. 정의는 Ontology Manager에서 브랜치 단위로 관리하고, 데이터는 Funnel이 객체 DB로 인덱싱하며, Workshop, Object Explorer, Vertex, Map 같은 앱과 AI 에이전트가 같은 객체 위에서 동작합니다.
