## Claude가 내린 결정 (ADR `승인(Claude)`)
- ADR-0014 분석 깊이·프런트엔드 근거
- ADR-0016 실행 방식 (병렬 에이전트 + 순차 실행 기록)

## 열린 질문 (사용자 답이 필요)
1. **[막힘] 원본 동작 기록 방법 (ADR-0017)** — 샌드박스 때문에 Claude가 분석용 인스턴스를 띄우지 못함. 권장: 아침에 터미널에서 아래 명령을 한 번 실행해 두기
   ```bash
   ONTOLOGICAL_STUDIO_USER_DATA=~/Desktop/workplace/rea/analysis/ontological-studio/runtime-data/userdata \
     "/Applications/Ontological Studio.app/Contents/MacOS/Ontological Studio"
   ```
   (평소 쓰는 앱과 별도 창·별도 데이터로 뜸. 창이 뜨면 Claude에게 알려 주기)
   ⚠️ M5 발견: 대시보드는 데이터 폴더가 아니라 **앱 패키지 안**에 저장되고 개발 중 만든 대시보드 12개가 동봉돼 있음 → 데이터 폴더를 나눠도 대시보드는 평소 앱과 공유됨. 분리하려면 위 명령에 `BOARD_STORAGE_DIR=<분석용 폴더>`도 붙일지 결정 필요(앱 폴더에 쓰기가 막히면 저장 실패 가능 — 실행 시 확인).
2. **그래프 엔진을 어떻게 할지** (A2 design §7, notes) — 원본 그래프 엔진(ontological-db: PostgreSQL 확장 + Rust Bolt 게이트웨이, Neo4j 4.4로 자신을 소개)을 (a) 그대로 재사용 (b) 다른 그래프 DB로 대체 (c) 새로 구현 중 무엇으로 할지. 배포본에 LICENSE 파일이 없고(README엔 Apache-2.0 표기), 동봉된 Oracle 클라이언트 라이브러리는 재배포 제한 가능성. → 구현 범위 결정(ADR-0001) 때 함께.
3. (참고·보안) 모든 구성 요소가 PostgreSQL 슈퍼유저 하나와 같은 비밀번호를 공유 → 에이전트가 실행하는 스크립트도 슈퍼유저 권한일 가능성(A2 notes).
4. (참고·버그 추정) PG 포트가 바뀌면 예제 데이터소스 3개만 재등록되고, 사용자가 직접 만든 데이터소스는 옛 포트를 계속 가리킬 수 있음(A2, 추정 — 실행 기록에서 확인).
5. (참고·보안) 데이터소스 원천 비밀번호가 DB 사용자 매핑에 평문 옵션으로 저장되고(화면엔 ••••), 패브릭 브리지는 인증 없이 그래프 관리자 계정으로 실행됨(M3 notes). 새 구현에서 비밀번호 보관 방식을 정해야 함.
6. (참고) 튜토리얼과 다른 점: 「실행한 문장」에는 쓰기 문장만 최대 30건 남고 읽기 문장은 기록되지 않음(M3).
7. (참고) 튜토리얼 04장 구성도와 다른 점: 포털 서버는 Bolt가 아니라 PostgreSQL에 슈퍼유저로 직접 접속하고, Bolt는 자연어→Cypher에서만 씀. 포털 HTTP는 인증 없음(루프백·동일 출처·JSON 강제로만 보호) (M4).
8. (참고) 포털에 튜토리얼에 없는 기능: 스키마 디자이너(계획→단계 실행), 릴리스 패키지 API(내보내기·계획·적용, 화면 없음). 앱 기본 설정에서 꺼진 기능: 원시 SQL, 스키마 AI 제안 (M4). 새 구현에 포함할지 구현 범위 결정 때 판단.
9. **(보안·중요) 에이전트가 승인 원칙을 우회할 가능성** (A3 notes) — CLI 에이전트가 권한 확인 없이 실행되면서 백엔드 환경 전체(PostgreSQL 슈퍼유저 비밀번호, 승인자 역할이 든 kinetic 토큰)를 물려받음 → "에이전트는 액션을 승인할 수 없다"는 원칙이 프로세스 수준에서 깨질 수 있음. **M2 결론(정적 분석, 실행 검증 안 함):** 에이전트 자신의 도구에는 승인 기능이 없고, 에이전트 토큰은 승인 시 403 → 설계상 분리는 지켜짐. 그러나 인증 없는 백엔드의 승인 API가 사람 사용자 신원(승인 권한 보유)으로 승인하고, CLI 에이전트는 권한 확인 없이 셸을 쓸 수 있으며 백엔드 주소·토큰을 물려받음 → curl 등으로 승인 후 실행이 가능할 것으로 **추정**. 감사 기록엔 사람이 승인한 것과 똑같이 남음. 막는 것은 스킬 안내 문구뿐(내장 에이전트는 셸 도구가 없어 해당 없음). 새 구현에서는 에이전트에 넘기는 환경을 최소화하는 설계 필요.
10. (참고) 앱 안에 설정 편집 화면은 없음(「설정」 카드는 studio.env를 텍스트로 열 뿐). 새 구현에서 설정 화면을 둘지 결정 (M8).
11. (참고·문서 불일치) 튜토리얼 14장은 "등록 시스템 비밀 값을 studio.env에 적으라"고 하지만, 코드상 kinetic-action 프로세스는 studio.env를 받지 않음 → **M7에서 확인: 안 됨.** 실행기는 앱 프로세스 환경·예제 비밀 3개·KINETIC_* 설정만 받음. 우회는 터미널에서 export 후 앱 실행뿐 (M7).
12. **M7 설계 결정 4가지** (menus/07-systems/design.md 11절): ① 등록 시스템 비밀 공급 방식(원본 유지 / studio.env를 실행기로 전달) ② 헬스 판정(원본 0.1.1: 3xx 이상 실패 / 튜토리얼: 5xx만 실패, 404·405는 경고) ③ 같은 이름 덮어쓰기 막을지 ④ 시스템별 재시도를 실제 적용할지(원본은 저장만 함).
13. (보안) 실행기 내부 비밀 헤더가 업무 시스템 호출에도 함께 전송됨 → 외부 시스템 등록 시 노출 가능 (M7 notes).
14. **M6 범위 결정**: 튜토리얼에 없는 전문가용 「⚙ 고급」 화면(8개 탭)을 재구현 범위에 넣을지.
15. **원본 결함을 재현할지 고칠지** (M6 notes): 카디널리티 검사 미동작, 재시도 3회 한도가 표시만 되고 막지 않음, 규칙 API는 있으나 화면 없음, `table_ingest`가 로컬 임의 경로 파일을 읽을 수 있음(보안). — M7 결정(12번)과 함께 "원본 버그·차이를 어떻게 다룰지" 일반 원칙을 정하면 편함.
16. (참고) 품질 추출 LLM은 선택한 에이전트(Claude Code 등)와 무관하게 백엔드가 OpenAI 호환 API를 직접 호출 → 키 없으면 추출 실패 (M6).
17. **승인 설계 결정** (M2 design 보안 절): 새 구현에서 (a) 원본처럼 인증 없는 백엔드 + 공용 UI 신원으로 승인 / (b) 사람 승인의 증명 요구(1회용 토큰, OS 확인 창 등) 중 무엇으로 할지. 권장: (b).
18. **우회 가능성 실험 여부**: 4단계 실행 기록 때 분석용 데이터 폴더에서만, 에이전트가 승인을 우회할 수 있는지 실제로 시험할지. (예제 시스템만 대상, 외부 영향 없음)
19. **M1 설계 결정 5가지** (menus/01-ontology-build/design.md §13): ① 데이터소스 SQL 경로(가상 클래스 + behavior)를 살릴지 — 원본 0.1.1에선 패브릭 브리지가 직접 SQL을 501로 막아 동작하지 않을 가능성 높음 ② 구축 화면의 계획 카드를 보기 전용으로 제한할지(지금은 구축 화면에서도 승인·실행까지 가능) ③ 화면에 발행 버튼을 추가할지(원본은 대화로만 발행) ④ 「초기화」가 그래프 전체를 지우는 범위를 줄일지, 스키마 삭제 시 발행물도 거둘지 ⑤ 문서 OCR을 넣을지(원본은 모듈은 있으나 구축 흐름에 연결 안 됨).
20. (참고·버그 추정) 업로드 파일 이름 경로 이동 미검사(보안), 이름 조회 부분 일치로 다른 스키마를 잡을 수 있음, 적재 도구가 기존 클래스 설명·속성을 비우는 것으로 보임 (M1 notes).
21. (참고) 온톨로지 **정의**는 그래프가 아니라 로컬 SQLite(sessions.db)에 저장되고, 그래프에는 인스턴스와 발행 시점의 정의 사본만 들어감 (M1).
22. **(보안) 코드 앱 격리** (M5): 코드 앱이 Studio와 같은 오리진이라 `/api/*` 전체·액션 승인 경로를 직접 부를 수 있고, 승인 확인은 `Sec-Fetch-Mode` 헤더 존재만 봄. SDK 확인 창이 앱 문서 안에 그려져 앱 코드가 흉내·대리 클릭 가능. 미리보기 iframe에 샌드박스 없음(부모 셸 API 접근 추정). → 새 구현에서 앱을 별도 오리진으로 분리하고 승인 창을 앱 밖으로 옮길지 결정. 권장: 분리.
23. (참고) 대시보드 AI 편집 중 에이전트 도구가 저장(`dry_run=false`)까지 할 수 있어, 사람이 「적용」을 누르기 전에 저장될 수 있음 (M5).
24. 실행 기록 때 보안 우회 시험(헤더를 붙인 curl 등)을 할지와 범위 — 18번과 함께 결정.
