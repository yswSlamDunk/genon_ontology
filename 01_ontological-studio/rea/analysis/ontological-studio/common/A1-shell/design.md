# A1 데스크톱 셸·부팅·프로세스 관리 — 설계 문서

- 상태: 초안 v0.1 (정적 분석 기반, 2026-10-31). "모르는 점"은 원본 동작 기록 후 갱신.
- 클린룸 문서: 원본 코드·파일 경로·내부 식별자를 담지 않는다. 외부에서 관찰되는 계약(URL 경로, 응답 필드, 화면 문구, 단축키)만 적는다.

## 1. 목적
여러 서버 프로그램(관계형 DB, 그래프 게이트웨이, 웹 포털, 분석 백엔드, MCP 서버, 액션 실행기, 예제 업무 서비스)을 한 데스크톱 앱 안에서 **설치 없이** 띄우고, 사용자에게는 탭 기반 창 하나로 보여 주는 실행 셸.

## 2. 핵심 개념
- **데이터 폴더**: 사용자별 상태 전체(DB, 설정, 비밀값, 로그, 포트, 작업 공간)를 담는 폴더 하나. 환경 변수로 다른 폴더를 지정하면 완전히 별개의 인스턴스가 된다.
- **런타임 번들**: 앱 패키지 안에 DB 서버, 언어 런타임, 서비스 코드, 정적 웹 자산이 모두 들어 있다(외부 설치 불필요).
- **로컬 웹 오리진**: 127.0.0.1의 단일 HTTP 서버가 UI 정적 파일, 셸 페이지, 여러 내부 서비스로의 프록시를 한 오리진으로 묶는다.
- **탭 창**: 창마다 상단 38px 탭 바(셸 페이지)가 있고, 탭은 그 아래 겹쳐 놓인 독립 웹 뷰다.

## 3. 데이터 폴더
| 항목 | 내용 | 권한 |
|---|---|---|
| 설정 파일 (`studio.env`) | 사용자 편집용 키=값. 없으면 예제 파일 복사 | 0600 |
| 비밀값 파일 | DB 비밀번호 등 무작위 생성값(JSON) | 0600 |
| 포트 파일 | 서비스별 마지막 포트(JSON) | |
| `pgdata/` | 관계형 DB 데이터. 첫 실행 준비 완료·예제 생성 완료 마커 파일 포함 | |
| `logs/` | 셸 로그, 서비스별 로그, 부팅 시간 기록 | |
| `run/` | 서비스별 PID 파일 | |
| `sandbox/`, `codeapps/` | 에이전트 작업 공간, 코드 앱 (A3, M5) | |
| 세션 DB, 액션 실행기 DB | SQLite 파일 (A3, M2/M7) | |
- 위치 기본값: OS 표준 앱 데이터 위치 아래 앱 이름 폴더. 환경 변수(`ONTOLOGICAL_STUDIO_USER_DATA`, 옛 이름 `ONTOLOGY_LITE_USER_DATA`)로 바꿀 수 있다.
- 옛 앱 이름의 폴더에 DB가 있고 새 폴더엔 없으면 첫 실행 때 옮긴다. 옛 앱이 실행 중이면 옮기지 않고 옛 폴더를 그대로 쓴다.
- **데이터 폴더당 인스턴스 1개.** 같은 폴더로 다시 실행하면 기존 창을 앞으로 가져온다. 다른 폴더라면 동시에 실행 가능.

## 4. 포트 할당
- 서비스 10개(DB, 그래프 게이트웨이, 포털, 백엔드, MCP, 웹 오리진, 액션 실행기, 예제 서비스 3개)에 선호 포트가 있다: 27432, 27687, 27474, 27800, 27810, 27900, 27830, 27841–27843.
- 우선순위: 서비스별 환경 변수(`ONTOLOGY_LITE_<서비스>_PORT`) > 지난번 포트 > 선호 포트 > OS가 주는 빈 포트. 모두 127.0.0.1에서 독점 바인딩으로 시험한다.
- 지난번 포트를 유지하는 이유: 데이터소스·외부 MCP 클라이언트가 주소를 기억하기 때문.

## 5. 부팅
### 5.1 순서
1. 데이터 폴더·설정 파일 준비
2. 지난 실행의 고아 프로세스 정리 (6.3)
3. 포트 할당·저장, 비밀값 로드(없으면 생성)
4. **DB 시작** — 처음이면 초기화. 첫 실행 준비 마커가 없으면 확장·예제 DB 준비. 서비스 스키마 마이그레이션.
5. **그래프 게이트웨이와 포털**을 병렬 시작, 셸이 게이트웨이에 접속
6. 데이터 패브릭 재연결·예제 데이터소스 등록(필요 시)
7. **로컬 웹 오리진** 시작
8. **액션 실행기·예제 서비스**와 **분석 백엔드·MCP**를 병렬 시작. 액션 실행기가 뜨면 예제 시스템을 재연결·등록
9. (첫 실행, 액션 실행기 성공 시) 예제 온톨로지 생성. 실패하면 로그만 남기고 다음 시작에 재시도
10. 준비 완료 → 모든 창이 부팅 화면에서 셸 화면으로 전환 → 부팅 시간 기록
- 액션 실행기 시작 실패는 치명적이지 않다(액션 없이 계속). 나머지 단계 실패는 부팅 실패.
- 설정 파일에 외부 액션 실행기 주소가 있으면 내장 실행기를 띄우지 않는다.

### 5.2 진행 표시
- 단계 이름: `starting`, `postgres`, `bootstrap`, `ontological`, `studio`, `ready`, `error`.
- 부팅 화면에 단계 목록과 단계별 경과 시간을 표시하고, 실패하면 오류 메시지와 로그 폴더 위치를 보여 준다.
- 트레이 메뉴 첫 줄에 단계 라벨: 시작하는 중 / PostgreSQL 시작 중 / 첫 실행 준비 중 / Ontological 시작 중 / Studio 시작 중 / 실행 중 / 시작하지 못함.
- 부팅 시간 기록(JSON): `{at, fresh, timings:{postgres, bootstrap?, ontological, fabricSeed?, kinetic?, studio, sampleOntology?, uiLoaded}}` (앱 시작 기준 ms). 실측 재시작: 약 3.1초.

## 6. 프로세스 관리
### 6.1 시작
서비스마다 이름을 붙여 하위 프로세스로 띄운다. 표준 출력·오류는 `logs/<이름>.log`에 이어 쓰고(시작 시각과 명령 줄 기록), `run/<이름>.pid`를 남긴다. 종료되면 PID 파일을 지운다.
### 6.2 준비 확인
TCP 연결 성공 또는 HTTP GET 상태 < 500. 150ms 간격, 기본 120초 제한. 대기 중 프로세스가 죽으면 즉시 "…프로세스가 종료됐습니다 (로그: logs/<이름>.log)", 시간 초과면 "…N초 안에 준비되지 않았습니다".
### 6.3 고아 정리
`run/`의 PID가 살아 있고, 그 명령 줄이 이 앱의 런타임 폴더를 가리킬 때만 종료한다(DB는 SIGINT로 빠른 종료, 나머지 SIGTERM, 10초 후 강제 종료). 다른 프로그램을 잘못 죽이지 않도록 명령 줄을 확인하는 것이 핵심.
### 6.4 종료
앱 종료 요청을 가로채 정리 후 종료한다. 순서: 트레이 제거 → 코드 앱 에이전트 작업 중지 → 웹 오리진 닫기 → 그래프 연결 닫기 → 백엔드·MCP·액션 실행기·예제 서비스 → 포털·게이트웨이 → DB(가장 마지막, 깨끗한 체크포인트). 서비스별 대기 시간 후 강제 종료. 모든 창을 닫으면 앱 종료.

## 7. 로컬 웹 오리진 (계약)
127.0.0.1:<web 포트>, 인증 없음.
| 경로 | 동작 |
|---|---|
| `/lite-shell/…` | 셸 페이지(탭 바+홈). 캐시 재검증 |
| `/kinetic-idp/jwks.json` | 액션 실행기 토큰 검증 키 (M7) |
| `GET /api/act/health` (액션 실행기 없음) | 200 `{"url":"시작하지 않음","identity":null,"reachable":false,"error":"키네틱 액션 실행기(kinetic-action)가 아직 시작되지 않았거나 시작하지 못했습니다. 로그 폴더의 kinetic.log 를 확인하세요."}` |
| `GET /api/act/systems` (액션 실행기 없음) | 503 `{"detail": <위 error 문구>}` |
| `/app/portal-info` | `{"url": 포털 URL, "graph": 그래프 이름}` |
| `/app/status` | `{"phase", "timings", "ports", "userData", "error", "pids":[{name,pid}]}` |
| `/fabric-bridge/…`, `/api/gateway/data-fabric/…`, `/api/gateway/text2sql/…` | 데이터 패브릭 브리지 (M3) |
| `/codeapps/api/…`, `/apps/…` | 코드 앱 (M5) |
| `/api/…` | 분석 백엔드로 그대로 프록시(스트리밍 응답 포함) |
| `/mcp…` | MCP 서버로 프록시 |
| `/analyzer…` | 이 배포판에 없는 화면이라는 안내 HTML |
| 그 밖 | UI 정적 파일, 없는 경로는 SPA 진입 HTML |
- 캐시: 콘텐츠 해시가 붙은 `/assets/…`만 1년 immutable, 나머지 no-cache.
- 프록시 대상 오류: 502 `{"error":"upstream :<포트> <오류코드>"}`.

## 8. 창과 탭
### 8.1 창
기본 1440×900, 최소 1024×640, 어두운 배경, macOS에선 타이틀바를 숨기고 신호등 버튼을 탭 바 안에 둔다. 서비스 준비 전엔 부팅 화면, 준비 후 셸 화면.
### 8.2 탭 종류
| 종류 | 내용 | URL |
|---|---|---|
| studio | 분석 UI의 한 화면(view)·대화(session)·데이터소스(ds) | `http://127.0.0.1:<web>/?view=<v>&session=<s>&ds=<d>` |
| portal | 그래프 포털 | `http://127.0.0.1:<portal>/` |
| app | 코드 앱 | `http://127.0.0.1:<web>/apps/<id>/` (id: 소문자·숫자·하이픈 4–64자) |
- view 값: `build`(온톨로지 구축), `act`(질의·액션), `board`(대시보드), `quality`(품질 검수), `datasources`(데이터소스), `systems`(시스템 등록), `browser`(포털).
- 탭 제목: studio는 페이지 제목을 따른다(기본 view 이름), portal은 "Ontological Portal", app은 앱 이름.
- **코드 앱 탭에는 셸 API를 주지 않는다**(생성된 코드가 셸 기능을 호출하지 못하게).
### 8.3 탐색 규칙
새 창 요청: 포털·앱·studio URL이면 새 탭, 그 밖은 기본 브라우저. 탭 안 이동도 studio·포털 밖이면 막고 기본 브라우저로.
### 8.4 탭 조작
| 동작 | 방법 |
|---|---|
| 홈 | ⌘T, ⌘1, 탭 바의 + 버튼 |
| 탭 전환 | 클릭, ⌘2–⌘8, ⌘9(마지막), Ctrl+Tab / Ctrl+Shift+Tab |
| 닫기 | ⌘W(홈이면 창 닫기), × 버튼, 가운데 클릭 |
| 새로고침 | ⌘R |
| 새 창 | ⌘N, 탭 바의 창 버튼 |
| 탭 우클릭 | 새로고침 / 새 창으로 분리 / 탭 닫기 / 다른 탭 닫기 |
| 개발자 도구 | ⌥⌘I (현재 탭) |
- 새 창으로 분리할 때 탭은 다시 로드되지 않는다(상태 유지).
### 8.5 셸 ↔ 메인 프로세스 브리지 (렌더러 API)
렌더러는 격리·샌드박스이고 아래 함수만 쓴다: 플랫폼 이름, `open(settings|logs|data|portal)`, `info()`, 전체화면 여부·변경 알림, 새 창, 탭 열기(대상), 자연어→Cypher 변환(M4), 탭 목록·전환·닫기·메뉴·변경 알림.
- 탭 목록·전환·닫기·메뉴는 **그 창의 셸 페이지만** 호출할 수 있다. 탭 페이지는 탭 열기와 고정된 셸 동작만.
- `info()` 응답: `{graph, ports, phase, agent:{backend, agentId, label, ready, note}, llmConfigured, kineticConfigured, version}`.
- `open('portal')`은 포털을 기본 브라우저로 연다.

## 9. 홈 화면
- 상단: 카드 8개 (feature-map 참조). 에이전트 미준비 시 「온톨로지 구축」「질의·액션」에 "에이전트 설정 필요" 배지.
- 최근 항목 표: 열 = 이름 / 종류 / 정보 / 날짜. 날짜 표기: 오늘이면 "오늘 HH:MM", 올해면 "M월 D일", 그 외 "YYYY. M. D.".
  | 종류 | 정보 칸 | 열리는 곳 |
  |---|---|---|
  | 구축 대화 / 질의·액션 대화 | 대상 온톨로지 이름 | studio build/act + 해당 대화 |
  | 온톨로지 | "클래스 N" | studio build |
  | 대시보드 | 온톨로지 이름 | studio board |
  | 코드 앱 | "에이전트 작업 중" 또는 "수정 N회" | app 탭 |
  | 데이터소스 | "<엔진> · 테이블 N · 노드 N" | studio datasources + 해당 데이터소스 |
  - 기본 대화(id `default`)는 제목·대상이 바뀌기 전엔 숨긴다. 날짜 없는 항목은 뒤로.
- 필터: 전체(사이드바 "최근 항목") · 온톨로지 · 대화 · 앱 · 데이터소스 (개수 표시). 검색: 이름+정보 부분 일치(대소문자 무시).
- 빈 상태 문구: 항목 없음 "아직 만든 것이 없습니다. 위에서 시작하세요." / 필터 결과 없음 "조건에 맞는 항목이 없습니다."
- 빠른 이동: Ontological Portal(탭), 로그 폴더, 데이터 폴더(OS 파일 관리자).
- 상태: "Ontological 연결됨/연결 안 됨 — 그래프 <이름> · PostgreSQL 16 · 127.0.0.1", "에이전트 <라벨>/사용할 수 없음 — <메모 또는 설명>" + 미준비 시 「설정」 버튼.
- 데이터 출처(병렬 조회): 대화 목록, 온톨로지 목록, 대시보드 목록, 패브릭 개요(데이터소스·가상 노드), 그래프 연결 상태, 코드 앱 목록, `info()`. 하나가 실패해도 나머지는 표시.
- 홈 탭으로 돌아올 때와 창이 포커스를 얻을 때 다시 조회.
- 테마: 밝음/어두움 토글. 분석 UI와 같은 저장 키를 공유해 탭 사이 즉시 동기화.

## 10. 메뉴바·트레이
- 메뉴바: 앱 / 편집 / 탭(8.4) / 보기(실제 크기·확대·축소·전체 화면) / 런타임(포털 탭 열기, 포털을 브라우저에서 열기, 에이전트 ▸ [Claude Code | Codex | 내장 에이전트 (OpenAI 호환 키)] 라디오 — 설치 안 된 CLI는 "(설치 안 됨)" 비활성, 설정 파일 열기, 로그 폴더 열기, 데이터 폴더 열기) / 창.
- 트레이: 상태 줄, 에이전트 줄, 홈 열기, Ontological Portal 탭, 데이터소스 탭, 새 창(준비 후에만 활성), 설정 파일 열기, 로그 폴더 열기, 종료. macOS는 템플릿 이미지(메뉴바 색 따라감).

## 11. 의존 관계
- 아래로: A2(DB·게이트웨이), A3(에이전트·MCP), M3(패브릭 브리지), M5(코드 앱), M7(액션 실행기).
- 위로: 모든 메뉴가 이 셸의 탭·웹 오리진·`info()`를 쓴다.

## 12. 오류·예외
- 부팅 실패: 단계 `error`, 부팅 화면에 메시지와 로그 폴더, 트레이 "시작하지 못함". 앱은 계속 떠 있다(로그 확인 가능).
- 액션 실행기 실패: 로그에 남기고 계속. 관련 API는 7절의 대체 응답.
- 에이전트 전환 중 또는 준비 전 요청은 무시.

## 13. 원본과 비교할 테스트 항목
1. 빈 데이터 폴더 첫 실행: 생성 파일·권한, 단계 순서, 예제 데이터 준비, 부팅 시간 기록 형식
2. 재실행: 첫 실행 준비 생략, 포트 재사용
3. 선호 포트가 사용 중일 때 다른 빈 포트로 대체
4. 같은 데이터 폴더 두 번째 실행 → 기존 창 포커스 / 다른 폴더 → 동시 실행
5. 강제 종료 후 재실행 → 고아 프로세스 정리, 이 앱 것이 아닌 프로세스는 건드리지 않음
6. 정상 종료 → 하위 프로세스 0개
7. 웹 오리진 7절 각 경로의 응답(특히 `/app/status`, `/app/portal-info`, 액션 실행기 없음 대체 응답, `/analyzer`)
8. 탭 규칙: URL 형식, 외부 링크는 브라우저, 코드 앱 탭엔 셸 API 없음, 탭 분리 시 상태 유지
9. 홈: 최근 항목 종류·정보 문구·날짜 형식·필터·검색·빈 상태 문구
10. 단축키 8.4 전부

## 14. 모르는 점 (원본 동작 기록에서 확인)
- 부팅 화면의 실제 단계 표시 문구와 모양, 첫 실행 전체 소요 시간
- 첫 실행 시 생성되는 파일의 정확한 목록(Electron 캐시 제외)과 액션 실행기 DB·세션 DB 생성 시점
- 웹 오리진·백엔드·MCP에 같은 PC의 다른 프로그램이 인증 없이 접근 가능한지(보안 평가용)
- 에이전트 전환 시 사용자 체감(열린 탭 새로고침)
- 개발자 도구 메뉴가 배포판에서도 동작하는지

## 15. 설계 시 고려(개선 여지, 원본과 다르게 할 수 있는 점)
- 로컬 웹 오리진·MCP에 실행마다 바뀌는 토큰 같은 최소 인증 추가 검토
- 앱 서명·공증, 런타임 무결성 확인(원본은 ad-hoc 서명, 무결성 검사 꺼짐)
