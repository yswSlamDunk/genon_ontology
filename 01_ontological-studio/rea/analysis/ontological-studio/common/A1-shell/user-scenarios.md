# A1 셸·부팅·프로세스 — 운영 시나리오

- 상태: 초안 (2026-10-31, ADR-0015 자율 진행)
- 출처: 튜토리얼 01-install.md(설치·첫 실행), 02-tour.md(화면 둘러보기), 배포본 셸 코드
- 기준 버전: 0.1.1

공통 기반이라 사용자 메뉴 대신 앱 운영 시나리오로 정리한다.

## S1. 첫 실행
- **사전 상태:** 데이터 폴더가 비어 있음 (분석용 폴더 `ONTOLOGICAL_STUDIO_USER_DATA=<새 폴더>`)
- **단계:** 앱을 실행한다.
- **기대 결과:**
  - 창이 바로 뜨고 부팅 진행 화면에 단계가 차례로 표시된다: PostgreSQL 시작 → 첫 실행 준비(확장·예제 DB) → Ontological(Bolt 게이트웨이·포털) → Studio(백엔드·MCP·키네틱 액션·예제 시스템) → 준비 완료
  - 준비가 끝나면 부팅 화면이 홈(탭 바 + 카드 8개 + 최근 항목 + 상태)으로 바뀐다
  - 데이터 폴더에 설정 파일(권한 0600), 비밀값 파일(0600), 포트 파일, 로그 폴더, DB 폴더가 생긴다
  - 첫 실행에만 예제 온톨로지 「공급망 운영 (예제)」가 만들어진다(실패하면 다음 시작에 재시도)
- **기록할 것:** 단계별 소요 시간(부팅 시간 파일), 생성 파일 목록과 권한, 띄운 프로세스와 포트

## S2. 다시 실행 (데이터 있음)
- **단계:** 종료 후 다시 실행한다.
- **기대 결과:** 첫 실행 준비 단계를 건너뛴다. 포트는 지난번 값을 다시 쓴다(사용 중이면 다른 빈 포트). 실측 예: 일반 재시작 시 UI 로드까지 약 3.1초.
- **기록할 것:** 포트 재사용 여부, 단계별 시간

## S3. 홈 화면 사용
- **단계:** 카드를 눌러 탭을 연다 / 최근 항목 필터(전체·온톨로지·대화·앱·데이터소스)와 검색 / 빠른 이동(포털·로그 폴더·데이터 폴더) / 테마 전환 / 상태 영역(Ontological 연결, 에이전트) 확인
- **기대 결과:** 카드 8개 중 7개는 탭을 열고, 「설정」은 설정 파일을 OS 기본 앱으로 연다. 에이전트가 준비되지 않으면 「구축」「질의·액션」 카드에 "에이전트 설정 필요" 배지.
- **기록할 것:** 홈이 호출하는 API 7개와 응답, 화면 캡처

## S4. 탭과 창
- **단계:** 여러 탭 열기, 탭 전환(⌘1 홈, ⌘2… 탭, Ctrl+Tab), 탭 닫기(⌘W, 가운데 클릭), 탭 우클릭 메뉴(새로고침·새 창으로 분리·탭 닫기·다른 탭 닫기), 새 창(⌘N)
- **기대 결과:** 탭은 다시 로드하지 않고 다른 창으로 옮겨진다. Studio·포털 밖의 링크는 기본 브라우저로 열린다.

## S5. 메뉴바와 트레이
- **단계:** 메뉴바 「탭」「보기」「런타임」 메뉴, 트레이 아이콘 메뉴 사용
- **기대 결과:** 트레이에 현재 단계(시작 중/실행 중/시작하지 못함)와 에이전트 이름. 「런타임」에서 포털 탭/브라우저, 에이전트 전환, 설정 파일·로그·데이터 폴더 열기.

## S6. 종료
- **단계:** 창을 모두 닫거나 종료한다.
- **기대 결과:** 역순으로 정리 — 코드 앱 작업 중지 → 웹 서버 닫기 → Studio·키네틱·예제 서비스 → 포털·Bolt → PostgreSQL(빠른 종료) 순. 남는 프로세스 없음.

## S7. 비정상 종료 후 재실행
- **단계:** 앱을 강제 종료한 뒤 다시 실행한다.
- **기대 결과:** 지난 실행이 남긴 하위 프로세스를 찾아 정리한 뒤 정상 부팅.
- **주의:** 분석용 데이터 폴더에서만 수행.

## S8. 부팅 실패
- **단계:** (재현이 어려우면 생략) 예: 필요한 포트·파일 문제
- **기대 결과:** 부팅 화면에 오류 메시지와 로그 폴더 위치, 트레이 "시작하지 못함".

## S9. 두 번째 실행 / 다른 데이터 폴더
- **기대 결과:** 같은 데이터 폴더로 두 번 실행하면 기존 창이 앞으로 온다. 다른 데이터 폴더로는 동시에 실행 가능하며, 각자 빈 포트를 잡는다.
