## S1. 데이터소스 탭 열고 구성 보기
- **목적:** 연결된 원천 DB와 가상 그래프를 한눈에 본다.
- **단계:**
  1. 홈에서 「데이터소스」 카드를 누른다.
- **기대 결과 (튜토리얼 + 배포본 화면):**
  - 왼쪽 머리말 `Data fabric`과 「＋」 버튼, 그 아래 `그래프 ontology · Ontological`
  - 왼쪽 위 「데이터소스 3」: `crm`, `erp`, `wms` (각각 엔진 태그 `postgres`, 아랫줄 `127.0.0.1 · 테이블 N · 노드 M`)
  - 왼쪽 아래 「가상 그래프」: `sample`(태그 「예제」), `ontology`(태그 「Studio」, `노드 0 · 관계 0`). 구축으로 만든 다른 그래프도 함께 보임
  - 왼쪽 맨 아래 안내문 「데이터는 복사하지 않습니다…」와 「Ontological Portal 에서 질의」 링크
  - 첫 데이터소스(목록 첫 항목 — 이름순이면 `crm`)가 자동 선택되어 가운데에 테이블 목록, 오른쪽에 첫 테이블 상세
  - 가상 노드로 노출된 테이블엔 초록 칩(예: `:Claim`)
- **기록할 것 (4단계):** 화면 캡처, 탭을 열 때 호출되는 요청 순서(overview → tables → columns → preview)와 응답 형식

## S2. 테이블 살펴보기와 미리보기
- **목적:** 원천 테이블 구조와 실제 데이터를 복사 없이 확인한다.
- **단계:**
  1. 왼쪽에서 `erp`를 누른다.
  2. 테이블 중 하나를 고른다.
  3. `wms` → `shipment` 테이블을 연다.
  4. `crm` → `claim` 테이블을 연다.
- **기대 결과 (튜토리얼 실측값):**
  - `erp` 머리말: `127.0.0.1 · 테이블 6 · 가상 노드 3`, 테이블 6개 중 `item`·`purchase_order`·`supplier`에 칩
  - 오른쪽 위 카드: `erp.<table>` 제목과 「가상 노드 :X」 또는 「노출 안 됨」, 컬럼·타입·제약(NOT NULL)·KEY 표
  - 가상 노드면 「미리보기」 카드: 문장 `MATCH (n:Shipment) RETURN n LIMIT 20`, 「그래프 sample」 태그, 복사 버튼
  - `wms.shipment` 미리보기에서 지연일 최대: `SHP-03` (9일, `CUSTOMS_HOLD`)
  - `crm.claim` 미리보기: 3행 (T-1, T-2, T-3)
  - 미리보기 아래 경로 표시: `3행 · Bolt → Ontological → postgres_fdw → 원천`
- **기록할 것:** 미리보기 요청·응답, 원천 DB에서 실제로 읽었는지(원천 행을 바꾼 뒤 다시 열어 반영되는지)

## S3. 새 데이터소스 연결
- **목적:** 외부 DB를 데이터소스로 추가한다.
- **단계:**
  1. 왼쪽 위 「＋」를 누른다 → 「데이터소스 연결」 대화상자.
  2. 엔진을 고른다 (PostgreSQL / MySQL · MariaDB / Oracle / SQL Server · Azure SQL). 이 설치에 커넥터가 없는 엔진은 「— 이 설치에 없음」으로 비활성.
  3. 엔진별 칸을 채운다 (이름·스키마·호스트·포트·DB(Oracle은 서비스 이름)·사용자·비밀번호).
  4. 아래 「실행될 문장」 미리보기를 확인하고 「연결」을 누른다.
- **기대 결과:**
  - 기본값: 호스트 `127.0.0.1`, 포트 5432, 스키마 `public`. 엔진을 바꾸면 포트·스키마가 그 엔진 기본값으로 바뀜(MySQL은 스키마 칸 없음, SQL Server는 `dbo`)
  - 필수 칸(이름·호스트·DB/서비스·사용자, Oracle은 스키마도)이 차야 문장이 미리 보이고 「연결」이 켜짐
  - 미리보기 문장 예: `CREATE DATASOURCE mydb WITH ENGINE = 'postgres', PARAMETERS = {host: '10.0.0.5', port: 5432, database: 'sales', schema: 'public', user: 'reader', password: '••••'}`
  - 이름 규칙 위반 시 미리보기 자리에 오류: 「데이터소스 이름은 영문 소문자·숫자·밑줄만 쓸 수 있고 숫자로 시작할 수 없습니다: "…"」
  - 성공하면 대화상자가 닫히고 새 데이터소스가 선택되어 테이블 목록이 보임. 데이터는 복사되지 않음
  - 실패하면 대화상자 아래에 한국어 오류(인증 실패·접속 실패·DB/스키마 없음·이름 중복 등)
- **기록할 것:** 엔진별 폼 항목, 오류 표시(이름 규칙·접속 실패·인증 실패), 생성 요청과 그 뒤 목록 갱신
- **열린 질문:** 연결할 테스트 원천 DB가 필요함 → 앱에 들어 있는 PostgreSQL의 `sample` DB(다른 스키마)나 별도 DB를 쓸지 4단계 전에 결정

## S4. 실행한 문장 확인과 패브릭 문장
- **목적:** 화면 조작이 어떤 패브릭 문장으로 실행되는지 본다.
- **단계:**
  1. 쓰기 작업(S3, S5, S6, S8 등)을 한 번 이상 한 뒤, 화면 아래 「실행한 문장」 막대를 눌러 연다.
  2. (M4 Portal에서) `SHOW TABLES FROM erp`를 실행해 결과를 비교한다.
- **기대 결과:**
  - 「실행한 문장」 막대는 **쓰기 작업을 한 뒤에만** 나타남. 막대에 건수와 마지막 결과(✓/✕ + 결과 문구)
  - 펼치면 최신순 목록(최대 30건), 각 줄에 문장(키워드 강조)과 결과 또는 오류
  - 기록되는 문장: `CREATE DATASOURCE …`(비밀번호 가림), `REFRESH DATASOURCE <ds>`, `DROP DATASOURCE <ds>`, `CREATE/DROP VIRTUAL NODE …`, `CREATE/DROP VIRTUAL RELATIONSHIP …`
  - 읽기 문장(`SHOW DATASOURCES`, `SHOW TABLES FROM`, `SHOW COLUMNS FROM`, 미리보기 `MATCH`)은 화면 뒤에서 실행되지만 이 목록에는 남지 않음(튜토리얼 표현과 다름 — 확인 대상)
  - 탭을 새로 고치면 목록은 사라짐(저장 안 됨)
  - `SHOW TABLES FROM erp` 결과 6행 (expedite_request 9, item 3 Item, po_hold 8, po_line 4, purchase_order 5 PurchaseOrder, supplier 4 Supplier)
- **기록할 것:** 화면 조작별 문장과 결과 문구(엔진이 돌려주는 `result` 문자열)

## S5. 데이터소스 새로 고침과 연결 해제
- **목적:** 원천 변화 반영과 연결 해제 규칙을 확인한다.
- **단계:**
  1. S3에서 만든 데이터소스를 고르고 「테이블 다시 읽기」를 누른다.
  2. 「연결 해제」를 누르면 그 자리에 `DROP DATASOURCE <ds>` 문장과 「해제」·「취소」가 나온다. 「해제」를 누른다.
  3. 가상 노드가 쓰고 있는 데이터소스(예: `erp`)를 연결 해제해 본다.
- **기대 결과:**
  - 1: 원천에 새로 생긴 테이블이 목록에 추가됨(이미 있던 테이블의 컬럼 변경은 반영되지 않음 — 셸 코드 주석 근거, 확인 대상)
  - 2: 해제 성공, 첫 데이터소스로 선택이 넘어감
  - 3: **엔진이 거절**. 배너: 「가상 노드 Item, PurchaseOrder, Supplier 이(가) 이 데이터소스를 읽고 있어 해제할 수 없습니다. 왼쪽 「가상 그래프」에서 그 노드를 먼저 지우세요.」 + 원문 오류
- **기록할 것:** 거절 시 원문 오류와 화면 표시
- **주의:** 3은 거절되는 것이 기대 결과. 만약 성공하면 예제 데이터가 깨지므로 스냅샷 후 실행 (ADR-0009)

## S6. 테이블을 가상 노드로 노출 (튜토리얼 06)
- **목적:** 아직 노출되지 않은 테이블 `erp.po_line`을 가상 노드 `PoLine`으로 만든다.
- **단계:**
  1. `erp` → `po_line`을 누른다. 「노출 안 됨」 표시.
  2. 오른쪽 아래 「가상 노드로 노출」 상자에서 노드 타입 이름 `PoLine`, 그래프 `sample`, KEY 컬럼 `po_line_id` 확인.
  3. (선택) 속성 이름 바꾸기: `qty` 오른쪽 칸을 `quantity`로. 속성 체크를 끄면 그 컬럼은 빠짐(KEY 컬럼은 끌 수 없음).
  4. 「실행될 문장」을 확인하고 「가상 노드 만들기」를 누른다.
- **기대 결과:**
  - 상자의 기본값은 자동으로 채워짐: 노드 이름 = 테이블 이름을 파스칼 표기로(`po_line` → `PoLine`), 그래프 = 이 데이터소스의 기존 가상 노드가 있는 그래프(없으면 `sample`), KEY = 키 후보 컬럼
  - 속성을 그대로 두면: `CREATE VIRTUAL NODE PoLine IN sample FROM erp.po_line KEY po_line_id`
  - 이름을 바꾸면: `… KEY po_line_id PROPERTIES (po_line_id, po_id, item_id, qty AS quantity)`
  - 만들자마자 테이블에 `:PoLine` 칩, 오른쪽에 미리보기 9행
- **기록할 것:** 기본값 자동 채움 결과, 생성 요청·응답, 「실행한 문장」 결과 문구

## S7. 가상 그래프 보기
- **목적:** 그래프별 가상 노드와 관계 구조를 본다.
- **단계:**
  1. 왼쪽 아래 「가상 그래프」에서 `sample`을 누른다.
  2. 지도에서 노드 하나(예: `Shipment`)를 누른다.
- **기대 결과:**
  - 머리말 `Virtual graph` / `sample` 「그래프」, 「가상 노드 8, 관계 5. 관계는 두 노드의 속성 값이 같은 행끼리 잇습니다.」(S6 후)
  - 「지도」 카드: 열 = 데이터소스(crm·erp·wms), 노드 상자에 노드 이름과 `테이블 · KEY`, 관계는 화살표와 이름표. `PoLine`은 아직 연결 없음
  - 「노드 타입」 표: 노드·원천·KEY·속성 수·저장(가상/물리화)·삭제
  - 「관계」 표: `[:ORDERED_FROM]` `PurchaseOrder.supplier_id → Supplier.supplier_id` 형식·삭제
  - 2: 해당 원천 테이블(`wms.shipment`) 상세로 이동
- **기록할 것:** 화면 캡처(지도 배치), overview 응답

## S8. 가상 관계 만들기 (튜토리얼 06)
- **목적:** `PoLine`을 발주·품목과 관계로 잇는다.
- **단계:**
  1. `sample` 그래프 화면 아래 「관계 만들기」에서 관계 이름 `IN_ORDER`.
  2. 출발 노드 `PoLine`, 속성 `po_id` → 도착 노드 `PurchaseOrder`, 속성 `po_id`.
  3. 「관계 만들기」를 누른다.
  4. (포털) `CREATE VIRTUAL RELATIONSHIP OF_ITEM IN sample FROM PoLine(item_id) TO Item(item_id)` 실행 후 데이터소스 탭으로 돌아온다.
  5. (포털) 튜토리얼의 4노드 질의와 두 시스템 걸친 질의 실행.
- **기대 결과:**
  - 노드를 고르면 속성 칸이 그 노드의 속성 목록으로 채워지고, 상대 노드의 KEY와 같은 이름이 있으면 그것이 자동 선택됨
  - 문장: `CREATE VIRTUAL RELATIONSHIP IN_ORDER IN sample FROM PoLine(po_id) TO PurchaseOrder(po_id)`. 성공하면 관계 이름 칸이 비워지고 지도·표 갱신
  - 4: 포털에서 만든 관계가 탭을 다시 불러오면(다른 작업 후 또는 탭 재열기) 보임 — 자동 갱신은 없음(추정)
  - 5: 협력사별 품목 수량 6행, 지연 선적 품목 2행(PCB 기판 SHP-02 7일, SHP-03 9일)
  - 존재하지 않는 속성을 고르면: 「노드에 X 속성이 없습니다. 관계는 노드의 속성으로 잇습니다.」
- **기록할 것:** 속성 자동 선택 동작, 생성 요청·응답

## S9. 가상 관계·노드 지우기와 거절 (튜토리얼 06 + 화면)
- **목적:** 만든 것을 지우고, 의존 관계가 있는 노드 삭제가 거절되는지 본다.
- **단계:**
  1. `sample` 그래프의 「노드 타입」 표에서 `PoLine` 「삭제」 → 「삭제」 확인.
  2. 「관계」 표에서 `OF_ITEM`, `IN_ORDER` 「삭제」.
  3. 다시 `PoLine` 「삭제」. (또는 테이블 상세 미리보기 카드의 「노출 해제」)
- **기대 결과:**
  - 1: 거절. 배너 「관계 IN_ORDER, OF_ITEM 이(가) PoLine 노드를 잇고 있어 지울 수 없습니다. 관계를 먼저 지우세요.」 + 원문 `virtual relationships still join on 'PoLine' (IN_ORDER, OF_ITEM); drop them first`
  - 2·3: 성공. 원천 테이블은 영향 없음, `po_line`은 다시 「노출 안 됨」
- **주의:** 튜토리얼 7–9장이 `PoLine`과 두 관계를 쓰므로, 기록 후 S6·S8로 다시 만들어 두거나 스냅샷으로 되돌린다.

## S10. 테이블 찾기 (화면 기능, 튜토리얼에 없음)
- **목적:** 테이블이 많을 때 이름으로 거른다.
- **단계:** `erp`를 고르고 테이블 목록 위 「테이블 찾기」에 `order` 입력, 이어서 `supplier`(노드 이름 일부)도 입력.
- **기대 결과:** 테이블 이름 또는 가상 노드 이름에 입력값이 들어간 테이블만 남음(대소문자 무시). `order` → `purchase_order`, (노드 `PurchaseOrder`)
- **기록할 것:** 필터가 서버 요청 없이 화면에서만 동작하는지

## S11. 홈 「최근 항목」에서 데이터소스 바로 열기 (튜토리얼 02 언급)
- **목적:** 홈에서 특정 데이터소스를 곧바로 연다.
- **단계:** 홈 「최근 항목」에서 「데이터소스」 필터를 누르고 `wms` 행을 누른다.
- **기대 결과:** 행 설명 `postgres · 테이블 3 · 노드 1`. 누르면 데이터소스 탭이 `wms`가 선택된 채로 열림
- **기록할 것:** 열린 탭의 주소에 데이터소스 지정이 들어가는지

## S12. 미리보기 문장 복사와 포털로 이동 (화면 기능)
- **목적:** 화면의 문장을 포털에서 이어 쓴다.
- **단계:** 가상 노드 테이블의 미리보기 카드에서 복사 버튼을 누르고, 왼쪽 아래 「Ontological Portal 에서 질의」를 누른다.
- **기대 결과:** 클립보드에 `MATCH (n:X) RETURN n LIMIT 20`, 포털 탭이 열림(그래프 선택은 사용자가 `sample`로 바꿔야 함 — 23 FAQ)

## 튜토리얼에 없어 확인한 것 (정적 분석 결과)
- 데이터소스 **수정**(접속 정보 변경) 화면은 없다. 바꾸려면 해제 후 다시 연결(가상 노드가 있으면 먼저 지워야 함).
- 테이블 검색(S10)은 있다. 데이터소스 목록 검색은 없다.
- 가상 노드의 **물리화**(`MATERIALIZE VIRTUAL NODE`)는 화면에 버튼이 없고, 노드 타입 표의 「저장」 칸에 「물리화」로만 표시된다(포털에서 문장으로 실행).
- 비밀번호는 화면·로그에 `'••••'`로만 보이고, 엔진 안의 외부 서버 접속 설정(사용자 매핑)에 저장된다(`design.md` 상태·저장 참조).
