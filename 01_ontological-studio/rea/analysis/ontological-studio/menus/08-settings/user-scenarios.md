# M8 설정 — 사용자 시나리오

- 상태: 초안 (2026-10-31, 정적 분석 기반)
- 출처: 튜토리얼 `01-install.md`(「코딩 에이전트 연결하기」·「데이터는 어디에 저장되나요」), `02-tour.md`(홈 카드 표), `14-systems.md`(비밀 값 주의), `23-faq.md`(「에이전트 설정 필요」), 배포본 0.1.1 코드
- 기준 버전: 0.1.1 (ADR-0012)
- 범위 확정: 「설정」은 (1) 홈 카드가 studio.env를 OS 기본 앱으로 여는 것, (2) 메뉴 「런타임 › 에이전트」 전환, (3) 홈의 상태 줄·카드 배지, (4) 메뉴·트레이·홈의 "설정 파일/로그 폴더/데이터 폴더 열기"까지다. 앱 안에 설정 편집 화면은 **없다**.

## 검토 요청 (사용자)
1. 「설정」 카드를 눌렀을 때 실제로 열리는 앱(텍스트 편집기 등)이 무엇이었나요?
2. studio.env를 직접 고쳐 본 적이 있다면 어떤 값을 바꿨나요?
3. 메뉴 「런타임 › 에이전트」로 바꿔 본 경험과 다른 부분이 있나요?

## 공통 사전 상태
- 분석용 데이터 폴더로 첫 실행한 직후 (studio.env가 예제에서 복사돼 있음)
- 앞 대상(A3)까지 진행한 상태 (ADR-0009)
- 이 PC의 CLI 설치 여부를 기록해 둔다 (A3 S1)

---

## S1. 「설정」 카드로 studio.env 열기
- **목적:** 설정 파일을 연다.
- **단계:**
  1. 홈에서 「설정」 카드(설명 "studio.env — 에이전트 · LLM 키.")를 누른다.
- **기대 결과:**
  - 사용자 데이터 폴더의 `studio.env`가 OS 기본 앱(macOS는 `.env` 확장자에 연결된 앱, 없으면 선택 창 — 모르는 점)으로 열린다.
  - 앱 화면은 바뀌지 않는다(탭이 열리지 않음).
  - 첫 실행이면 내용은 예제 파일과 같다(아래 S7 참고).
- **기록할 것:** 열린 앱, 파일 경로, 파일 내용 원문, `ls -l`로 권한(`-rw-------` 기대)
- **주의:** 같은 동작이 메뉴 「런타임 › 설정 파일 열기 (studio.env)」, 트레이 「설정 파일 열기 (studio.env)」, 홈 상태 줄의 「설정」 버튼(에이전트를 쓸 수 없을 때만)에도 있다. 네 곳 모두 확인.

## S2. 홈 상태 줄과 카드 배지 읽기
- **목적:** 에이전트·그래프·키네틱 상태가 홈에 어떻게 보이는지 확인한다.
- **단계:** 홈을 연다(다른 탭에서 홈으로 돌아오거나 창에 포커스를 줄 때마다 다시 읽는다).
- **기대 결과 (상태 줄, 왼쪽 아래):**
  - 1행: 점(초록/빨강) + `Ontological 연결됨`/`연결 안 됨` + 작은 글씨 `그래프 <그래프 이름> · PostgreSQL 16 · 127.0.0.1`
  - 2행: 점(초록 = 준비됨이고 안내 문구 없음, 노랑 = 그 밖) + `에이전트 <이름>` 또는 `에이전트 사용할 수 없음` + 작은 글씨(안내 문구, 없으면 CLI일 때 "이 PC 의 CLI 가 Studio 스킬로 구축·질의합니다", 내장일 때 "OpenAI 호환 LLM 으로 구축·질의합니다") + 사용할 수 없을 때만 「설정」 버튼
- **기대 결과 (카드 배지):**
  - 에이전트를 쓸 수 없으면 「온톨로지 구축」·「질의·액션」 제목 옆에 `에이전트 설정 필요`
  - 키네틱이 꺼져 있으면(번들 실행기가 안 떴고 `KINETIC_URL`도 없음) 「시스템 등록」에 `별도 서비스`
- **기록할 것:** 정상 상태 캡처. 가능하면 A3 S2의 두 조건(키 없음·CLI 없음)에서 캡처
- **주의:** 「온톨로지 앱」 카드는 에이전트가 필요하지만 배지 대상이 아니다(원본 그대로).

## S3. studio.env를 고쳐 내장 에이전트로 바꾸기
- **목적:** 파일을 직접 고쳐 설정을 바꾸고, 다시 시작해야 반영됨을 확인한다.
- **단계:**
  1. S1로 파일을 연다.
  2. `AGENT_BACKEND=deepagents`, `OPENAI_API_KEY=<분석용 키 또는 가짜 값>`으로 고치고 저장한다.
  3. 앱을 그대로 둔 채 홈 상태를 본다 → 앱을 다시 시작해 다시 본다.
- **기대 결과:**
  - 다시 시작 전: 홈 상태는 그대로(백엔드가 시작 시 한 번 읽음). 단, 홈 정보는 에이전트가 이미 정해졌으므로 바뀌지 않음.
  - 다시 시작 후: `에이전트 내장 에이전트`, 부제 "OpenAI 호환 LLM 으로 구축·질의합니다", 초록 점
- **기록할 것:** 다시 시작 전후 화면, 백엔드 프로세스 env의 `AGENT_BACKEND`·`OPENAI_API_KEY` 반영 여부
- **주의:** 가짜 키면 대화 시도 시 실패한다 — 에러 표시 형식만 기록. 실제 키 사용 여부는 4단계 계획 때 결정.

## S4. 메뉴 「런타임 › 에이전트」로 바꾸기
- **목적:** 메뉴 전환이 파일을 고치고 즉시 반영되는지 확인한다(다시 시작 불필요).
- **단계:**
  1. 메뉴 「런타임 › 에이전트」를 연다 — 항목 3개를 기록한다.
  2. 「내장 에이전트 (OpenAI 호환 키)」를 고른다.
  3. 진행이 끝나면 홈 상태를 보고 studio.env를 다시 연다.
  4. 「Claude Code」로 되돌린다.
- **기대 결과:**
  - 항목: `Claude Code`, `Codex`(설치 안 됐으면 `Codex (설치 안 됨)`·비활성), `내장 에이전트 (OpenAI 호환 키)` — 라디오, 현재 studio.env 값에 체크
  - 2 후: studio.env의 `AGENT_BACKEND=deepagents`(같은 줄이 바뀜). `EXTERNAL_AGENT_ID`는 그대로
  - 4 후: `AGENT_BACKEND=cliagents`, `EXTERNAL_AGENT_ID=claude-code`
  - 전환 중 부팅 진행 문구 "에이전트를 바꾸어 Studio 를 다시 시작합니다" → "준비 완료"(표시 위치는 모르는 점), 열린 Studio 탭 새로고침
- **기록할 것:** 전환 전후 studio.env diff, 소요 시간, 탭 동작
- **주의:** 앱이 준비 완료 전이거나 이미 전환 중이면 선택이 무시된다.

## S5. 로그 폴더·데이터 폴더 열기
- **목적:** 설정과 함께 쓰는 셸 바로가기를 확인한다.
- **단계:** 홈 왼쪽 「로그 폴더」·「데이터 폴더」, 메뉴 「런타임 › 로그 폴더 열기/데이터 폴더 열기」, 트레이 「로그 폴더 열기」를 각각 누른다.
- **기대 결과:** Finder(탐색기)로 `<데이터 폴더>/logs`, `<데이터 폴더>`가 열린다. 데이터 폴더에 `studio.env`, `secrets.json`, `ports.json`, `pgdata/`, `logs/`, `sandbox/`, `sessions.db` 등.
- **기록할 것:** 데이터 폴더 목록과 각 파일 권한

## S6. 앱이 정하는 값은 바뀌지 않음
- **목적:** studio.env로 바꿀 수 없는 값을 확인한다.
- **단계:** studio.env에 `NEO4J_URI=bolt://127.0.0.1:1`, `BACKEND_PORT=1234`, `SANDBOX_BACKEND=docker`를 넣고 다시 시작한다.
- **기대 결과:** 아무 영향 없음(앱이 덮어씀). 정상 기동.
- **기록할 것:** 백엔드 프로세스 env에서 위 키들의 실제 값
- **주의:** 확인 후 원래대로 되돌린다.

## S7. 실데이터 MCP 확장 끄기
- **목적:** `MCP_ALLOW_DATASOURCE_EXPANSION=false`의 효과를 확인한다.
- **단계:** 주석을 풀어 `false`로 바꾸고 다시 시작 → 「질의·액션」에서 데이터소스 수치 질문 1회, 「온톨로지 앱」에서 대시보드 자동 구성 1회.
- **기대 결과:** 외부 MCP 도구 목록이 4개로 줄고(A3 S7), 설정 파일 설명대로 대시보드 자동 구성이 동작하지 않음(형태는 M5에서 기록).
- **기록할 것:** 질의 응답의 도구 호출 목록, 대시보드 화면 메시지

## S8. 외부 kinetic-action 지정
- **목적:** `KINETIC_URL`을 넣으면 번들 실행기 대신 그것을 쓰는지 확인한다.
- **단계:** `KINETIC_URL=http://127.0.0.1:9`(닿지 않는 주소)를 넣고 다시 시작.
- **기대 결과:** 번들 실행기·예제 서비스가 뜨지 않음, 「시스템 등록」에 `별도 서비스` 배지는 **없음**(KINETIC_URL이 있으면 설정됨으로 봄), 시스템 화면은 연결 실패로 보임(M7).
- **기록할 것:** 프로세스 목록, 홈 배지, 시스템 화면 상태
- **주의:** 첫 실행 예제 온톨로지 생성이 이 상태에서는 건너뛰어진다(키네틱 시작 결과가 false) — 첫 실행 상태에서 하지 말 것.
