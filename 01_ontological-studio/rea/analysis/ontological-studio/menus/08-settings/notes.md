# M8 설정 — 메모

## 범위 결정 (feature-map 열린 질문 답)
- 「설정」 = studio.env 파일 열기 + 메뉴 「런타임 › 에이전트」 + 홈 상태 줄·배지 + 로그/데이터 폴더 바로가기. 앱 안 설정 편집 화면 없음(관찰). feature-map §1의 "(추정 — M8에서 확정)"을 확정으로 바꿔도 됨.

## 보안 관찰
- **실데이터 MCP 기본 켬** — 예제 파일은 주석으로만 `MCP_ALLOW_DATASOURCE_EXPANSION=true`를 보여 주지만, 셸이 값이 없으면 `true`를 넣는다. 백엔드 자체 기본은 false. 설명 문구에 "끄면 다른 AI 클라이언트가 원천 행을 읽을 수 없지만"이라고 위험을 밝혀 두긴 했다. 새 구현에서 기본값을 그대로 둘지 결정 필요(A3 design §11-4).
- **비밀이 들어가는 평문 파일** — studio.env에 `OPENAI_API_KEY`, `KINETIC_*_TOKEN`, (튜토리얼 안내대로라면) 업무 시스템 비밀이 평문으로 들어간다. 생성 시 0600으로 보호. 메뉴 전환 쓰기는 기존 파일 권한을 다시 0600으로 고치지 않는다(파일이 이미 있으면 Node의 mode 옵션이 무시됨 — 관찰·Node 동작 지식). 사용자가 편집기로 저장하며 권한이 바뀌는 경우 대비 없음.
- studio.env 값은 Studio 백엔드 환경 → CLI 에이전트 환경으로 그대로 상속된다(A3 notes 2). 즉 사용자가 넣은 키가 bypassPermissions로 도는 에이전트에게 보인다.

## 품질 관찰
- 예제 21–22행 "키네틱 액션 … 이 패키지에는 들어 있지 않다. 비워 두면 「시스템 등록」은 연결 안 됨으로 보인다" — 0.1.1은 번들 실행기를 띄우므로 사실과 다르다(낡은 주석). 새 구현의 예제 파일은 고칠 것을 권함(비교 테스트 1번은 원본 바이트 비교이므로 구현 결정과 충돌 — REVIEW 대상).
- `llmConfigured`라는 이름은 실제로 "에이전트 준비됨"이다. CLI 방식이면 키가 없어도 true. 한편 CLI 방식에서도 OCR·임베딩·품질 추출은 `OPENAI_API_KEY`가 필요한데 홈에 이를 알리는 표시가 없다.
- 「온톨로지 앱」 카드는 에이전트가 필요한데 `에이전트 설정 필요` 배지 대상이 아니다.
- 메뉴 체크는 요청값, 홈·트레이는 실제값 — 둘이 다를 수 있다.
- 파일 파서가 단순(인라인 주석·export·이스케이프 미지원). 사용자가 `KEY=value # 설명`처럼 쓰면 값에 주석이 들어간다.
- `OPENAI_BASE_URL`을 넣으면 임베딩이 OpenAI가 아니라 Ollama(`OLLAMA_BASE_URL`, 기본 localhost:11434) 경로로 바뀐다 — 예제 설명에 없는 부작용.

## 다른 대상 관련
- **M7**: 튜토리얼 14장 "등록 시스템 비밀 값은 studio.env에 `ERP_API_KEY=...`" ↔ 액션 실행기 프로세스 env에는 studio.env가 없음(셸 코드 관찰). 실행기가 비밀을 Studio 백엔드에서 받는 경로가 있는지 M7에서 확인.
- **M4**: 내장 에이전트 선택 시 포털 자연어→Cypher가 오류 문구로 메뉴 「런타임 › 에이전트」를 안내.
- **A1**: 정보 IPC `phase` 값 집합, 셸 동작 열기의 고정 대상 목록은 A1 문서와 맞출 것.
