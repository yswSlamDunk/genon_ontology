## S1. 시스템 목록 보기
- **목적:** 액션이 호출할 수 있는 등록 시스템을 한눈에 본다.
- **단계:** 홈에서 「시스템 등록」 카드를 누른다 (또는 Studio 왼쪽 내비게이션 「시스템 등록」).
- **기대 결과:**
  - 머리말: 「시스템 등록」 + 「키네틱 액션이 호출하는 서비스 · 게이트웨이 경로 `/svc/<이름>`」, 오른쪽에 신원 배지 `lite-user · 관리자`, 「새로고침」 버튼
  - 카드 3개(이름순): 고객 CRM(`sample-crm`), 구매 ERP(`sample-erp`), 물류 WMS(`sample-wms`). 카드 머리는 아이콘·프로토콜(`REST`)·상태 점(✓ 정상 / ! 이상 / ? 미확인). 몸통은 표시 이름, 이름(slug), 설명, `API N개 · 담당 팀`, 태그
  - 예제 값: ERP `API 6개 · 구매팀`, WMS `API 3개 · 물류팀`, CRM `API 4개 · 고객지원팀`
  - 목록을 읽자마자 시스템마다 상태 확인을 자동으로 부르고, 점에 마우스를 올리면 `정상 · 37ms` 같은 문구
  - 맨 끝 카드 「+ 시스템 등록」(부제 `REST(OpenAPI·Swagger) · SOAP · gRPC · GraphQL …`)
- **기록할 것:** 화면 캡처, 열 때 호출 순서(실행기 상태 → 시스템 목록 → 시스템별 상태), 각 응답 형식
- **주의:** CRM 카드 아이콘은 아이콘 목록에 `crm`이 없어 「기타(🔌)」로 보일 것으로 추정 — 확인

## S2. 시스템 하나 들여다보기 (튜토리얼 14)
- **목적:** 등록 정보와 스펙에서 읽은 API를 본다.
- **단계:** 「구매 ERP」 카드를 누른다. 이어서 「물류 WMS」, 「고객 CRM」도 연다.
- **기대 결과 (튜토리얼 + 배포본 화면):**
  - 머리: 아이콘, `구매 ERP sample-erp`, 배지 `REST`, 상태 점과 `정상 · 37ms`, 버튼 「상태 확인」「스펙 다시 읽기」「편집」「삭제」, 「‹ 목록」
  - 정보 표: 게이트웨이 `/svc/sample-erp` · 활성 주소 `http://127.0.0.1:27841 (local)` · 스펙 `http://127.0.0.1:27841/openapi.json` · 인증 `API 키 · X-API-Key ← $ERP_API_KEY` · 정책 `5000 ms · 재시도 2 · 헬스 /health` · 담당 `구매팀` · 태그 `erp purchasing sample` · 수정 시각
  - 「API (operation) 6개」 표: 메서드·경로·operationId·설명·출처(「스펙」/「직접 추가」)
    - ERP: `GET /purchase-orders/{po_id}` getPurchaseOrder, `POST /purchase-orders/{po_id}/hold` holdPurchaseOrder, `POST …/release` releasePurchaseOrder, `POST /expedite-requests` createExpediteRequest, `POST /expedite-requests/{request_id}/withdraw` withdrawExpediteRequest, `GET /expedite-requests` listExpediteRequests
  - WMS 인증 `Basic ← $WMS_BASIC`, API 3개(우선순위 변경 `POST /shipments/{shipment_no}/priority` setShipmentPriority)
  - CRM 인증 `Bearer · Authorization ← $CRM_TOKEN`, API 4개(createNotice, withdrawNotice 등)
  - 비밀 값 자체는 어디에도 보이지 않음 — 환경 변수 **이름**만
- **기록할 것:** 상세 응답(시스템 + operations), 화면 캡처 3장
- **튜토리얼 확인 문제 정답과 일치해야 함:** WMS 우선순위 = `POST /shipments/{shipment_no}/priority`, CRM = Bearer

## S3. 상태 확인
- **목적:** 지금 그 시스템에 닿는지 본다.
- **단계:** 상세에서 「상태 확인」을 누른다. (선택) 예제 WMS 프로세스가 죽은 상황에서 다시 누른다.
- **기대 결과:** 정상이면 `정상 · Nms`(점 ✓). HTTP 3xx 이상이면 `이상 · HTTP N`, 응답이 없으면 `응답 없음 · <오류>`(점 !). 확인 중엔 `확인 중`
- **기록할 것:** 상태 응답 `{ok, http_status, latency_ms, checked_at, error?}`
- **주의:** 서비스 강제 종료는 셸이 다시 띄우지 않을 수 있으니 기록 뒤 앱 재시작

## S4. 스펙 다시 읽기
- **목적:** 서비스 API가 바뀌었을 때 목록을 갱신한다.
- **단계:** ERP 상세에서 「스펙 다시 읽기」.
- **기대 결과:** 배너 「'sample-erp' 의 스펙을 다시 읽었습니다 — API 6개 (직접 추가한 API 는 유지).」. 스펙 주소가 없는 시스템이면 버튼 비활성(툴팁 「OpenAPI URL 이 없습니다」)
- **기록할 것:** 요청·응답, 감사 기록 남는지

## S5. API 직접 추가·삭제 (튜토리얼 14 「API 추가」)
- **목적:** 스펙에 없는 API를 수동으로 등록한다.
- **단계:**
  1. 상세에서 「API 추가」를 누른다 → 폼(operationId, 메서드, 경로, 설명, 파라미터 행, 요청 본문 JSON Schema).
  2. operationId `getPoHolds`, 메서드 `GET`, 경로 `/purchase-orders/{po_id}` 를 적는다 → 「경로의 {po_id} 를 path 파라미터로 추가하세요. [자동 추가]」 안내 → 「자동 추가」.
  3. 「API 추가」 제출.
  4. 표에서 출처 「직접 추가」 행의 「삭제」 → 확인.
  5. 출처 「스펙」 행에는 삭제 버튼이 없음을 확인.
- **기대 결과:** 추가 성공 배너 「API 'getPoHolds' 을(를) 추가했습니다.」, 표에 「직접 추가」로 보임. 같은 operationId면 교체. 요청 본문 JSON이 틀리면 「요청 본문 JSON 오류: …」. 삭제 후 「API '…' 을(를) 지웠습니다.」
- **기록할 것:** 추가 요청 본문 형식, 스펙 다시 읽기 뒤에도 수동 API가 유지되는지
- **주의:** 같은 operationId를 스펙과 수동으로 둘 다 가지면 수동이 이긴다(코드) — 확인

## S6. GET API 바로 조회 (화면 기능, 튜토리얼에 없음)
- **목적:** 계획·승인 없이 업무 시스템의 현재 값을 읽는다.
- **단계:** WMS 상세 → `GET /shipments` listShipments 행의 「조회」.
- **기대 결과:** 표 아래 「조회 결과 · listShipments · HTTP 200 · Nms」와 JSON(배열이 20건을 넘으면 앞 20건 + `… 외 N건`). 실행기 쪽에서 500건 넘으면 「· 잘림」
- **주의:** 「조회」 버튼은 **경로 변수가 없는 GET**에만 나온다(`/shipments/{shipment_no}`엔 없음). 쓰기(POST 등)는 조회 불가 — 액션으로만.
- **기록할 것:** 조회 요청·응답, 감사 기록

## S7. 새 시스템 등록 — 6단계 마법사 (튜토리얼 14 + 캡처)
- **목적:** 새 업무 시스템을 레지스트리에 등록한다. 연습 대상: Swagger Petstore(튜토리얼 팁).
- **단계:**
  1. 목록의 「+ 시스템 등록」. 왼쪽에 단계 1 기본 정보 · 2 프로토콜·스펙 · 3 환경·주소 · 4 인증 · 5 정책 · 6 연결 테스트·저장. 단계 번호를 눌러 아무 단계로나 이동 가능. 조건을 채운 단계는 ✓.
  2. **기본 정보:** 표시 이름 `Petstore`, 이름 `petstore`(영문 소문자·숫자·`-`, `routes` 금지 → 어기면 「영문 소문자·숫자·- 만, 'routes' 는 예약어입니다.」), 설명, 담당 팀, 연락처, 태그(쉼표 구분), 아이콘 8종(MES·CMMS·APS·ERP·SAP·SCM·WMS·기타, 기본 기타). 「다음」.
  3. **프로토콜·스펙:** 프로토콜 카드 7개(REST · OData · SOAP · gRPC · GraphQL · DB 프로시저 · 비동기 메시지; REST·OData 외엔 「어댑터 필요」). 스펙 방식: 파일 업로드(끌어다 놓기/클릭, `.json .yaml .yml .wsdl .xml .proto .graphql .graphqls .gql`) / URL / 없음(API 를 직접 추가). 「스펙 형식」 선택(자동 판별 기본). URL에 `https://petstore3.swagger.io/api/v3/openapi.json`.
  4. **환경·주소:** 기본 행 `default` + 주소. 「환경 추가」로 여러 환경, 라디오로 활성 환경 선택. 주소 `https://petstore3.swagger.io/api/v3`. 주소가 비면 「환경 이름과 http(s) 주소를 하나 이상 적고 활성 환경을 고르세요.」
  5. **인증:** 없음 / API 키(헤더 또는 쿼리 파라미터) / Basic / Bearer 토큰 / OAuth2 Client Credentials / 로그인 토큰(JSON 로그인). 비밀 값 대신 **환경 변수 이름**을 적는다. 안내 「🔒 비밀 값은 저장하지 않습니다 — 환경변수(비밀 저장소) 이름만 저장하고…」. Petstore는 「없음」.
  6. **정책:** 타임아웃(ms, 기본 5000), 재시도(0–5, 기본 2), 헬스 체크 경로(기본 `/health`). 안내 「재시도는 5xx·연결 오류에만, 멱등 키가 있는 호출에만 합니다…」.
  7. **연결 테스트·저장:** 요약(이름·프로토콜·스펙·활성 환경·인증·정책) → 「연결 테스트」 → 결과 3줄(스펙 / 헬스 / 환경변수) + 앞 12개 API 목록 + 「응답 원문」 펼치기 → 「등록」.
- **기대 결과:**
  - 등록 성공 배너 「시스템 'Petstore' 을(를) 등록했습니다 — API 19개.」(튜토리얼 실측 19개), 바로 상세 화면으로
  - 「연결 테스트」와 「등록」은 1–4단계 조건이 맞으면 켜짐 — **연결 테스트를 통과하지 않아도 등록 가능**(코드)
- **기록할 것:** 테스트·등록 요청 본문, 테스트 응답 전문, 단계별 화면
- **주의 (튜토리얼과 코드 불일치):**
  - 튜토리얼은 "상태 점검 경로를 비워 두라"고 하지만, 0.1.1에서는 비우면 `/health`로 저장·점검된다(코드). Petstore에 `/health`가 없으면 헬스가 실패로 보일 것 — 확인
  - 튜토리얼의 「연결됨 · (경고)」와 주황 `~` 표시는 0.1.1 번들에 없다. 0.1.1은 HTTP 3xx 이상을 모두 실패(빨강)로 보인다 — 확인
- **열린 질문:** 외부 인터넷(petstore3.swagger.io) 접속이 기록 환경에서 가능한지

## S8. 연결 테스트 결과 해석과 비밀 값 위치
- **목적:** 인증이 필요한 시스템에서 "환경 변수 없음"이 어떻게 보이는지 확인한다.
- **단계:**
  1. 새 시스템 `mock-cmms`, 주소 `http://127.0.0.1:27841`(예제 ERP를 재활용), 스펙 URL `http://127.0.0.1:27841/openapi.json`, 인증 API 키 · 헤더 `X-API-Key` · 환경 변수 `CMMS_API_KEY`.
  2. 「연결 테스트」.
  3. (선택) `studio.env`에 `CMMS_API_KEY=...`를 적고 앱을 재시작한 뒤 다시 테스트.
- **기대 결과:** 스펙 `operation 6개 · OpenAPI 3`, 헬스 `정상 · HTTP 200 · Nms`, 환경변수 `없음: CMMS_API_KEY` (빨강). 값을 넣으면 「필요한 이름이 모두 있습니다 (값은 보지 않음)」
- **주의:** 코드상 내장 실행기는 `studio.env` 내용을 환경으로 받지 **않는다**(예제 3개 비밀만 받음). 튜토리얼은 `studio.env`에 적으면 된다고 하므로 3번 결과가 핵심 확인 대상
- **기록할 것:** 3번 전후 테스트 응답의 `auth.missing_env`

## S9. REST가 아닌 시스템 등록 (어댑터 필요)
- **목적:** SOAP·gRPC 등도 등록은 되지만 실행은 안 된다는 표시를 본다.
- **단계:** 새 시스템, 프로토콜 `SOAP`, 스펙 파일로 작은 WSDL 업로드(또는 `.proto`), 환경 주소 입력 → 테스트 → 등록.
- **기대 결과:**
  - 프로토콜을 고르는 즉시 빨간 안내 「실행 어댑터 필요 — 등록만 됩니다. 실행기는 지금 HTTP+JSON(REST·OData)만 호출하므로, 이 시스템을 쓰는 액션은 계획 단계에서 거부(not_executable)됩니다…」
  - 파일을 올리면 형식 자동 판별 후 프로토콜이 맞춰 바뀜(.wsdl→SOAP, .proto→gRPC, SDL→GraphQL, AsyncAPI→비동기, $metadata→OData)
  - 등록 배너 끝에 「실행 어댑터가 필요해 액션 실행은 거부됩니다.」, 카드·상세에 「어댑터 필요」 배지. WSDL이면 operation 이름이 `POST /` 「SOAP operation (어댑터 필요)」로 나열
- **기록할 것:** 등록 응답의 `executable`, `adapter_required`, `spec_format`

## S10. 시스템 편집 (환경 전환·인증 변경)
- **목적:** 등록 정보를 바꾼다.
- **단계:** S7에서 만든 시스템 상세 → 「편집」 → 같은 6단계 마법사(제목 「petstore 편집 — …」). 이름·프로토콜·「파일 업로드」 선택은 잠김. 환경 `prod` 추가 후 활성 환경 전환, 정책 타임아웃 변경 → 「저장」.
- **기대 결과:** 배너 「'petstore' 을(를) 저장했습니다.」, 상세 활성 주소가 바뀐 환경으로, 「환경」 줄에 칩 2개. 스펙 URL을 바꾸면 저장 뒤 자동으로 스펙 다시 읽기(안내 「URL 을 바꾸면 저장 뒤 스펙을 다시 읽습니다.」)
- **기록할 것:** 수정 요청 본문(PATCH), 감사 기록의 바뀐 필드 목록

## S11. 시스템 삭제와 사용 중 경고
- **목적:** 시스템을 지우고, 발행된 액션이 쓰던 시스템이면 경고를 받는다.
- **단계:**
  1. S7의 시스템 「삭제」 → 확인 창 「시스템 '…' 을(를) 레지스트리에서 지울까요? 이 시스템을 쓰는 발행된 액션은 실행이 실패하게 됩니다.」 → 확인.
  2. (스냅샷 후) 예제 `sample-crm` 삭제 → 앱 재시작.
- **기대 결과:**
  - 1: 「'…' 을(를) 지웠습니다.」, 목록으로
  - 2: 삭제는 **거절되지 않고** 진행, 배너(빨강) 「'sample-crm' 을(를) 지웠습니다. 주의 — 이 시스템을 쓰던 액션: <클래스.액션>. 액션 단계를 고치고 다시 발행하세요.」. 재시작하면 예제 시스템이 **다시 자동 등록**됨(코드)
- **주의:** 2는 예제 액션 실행(M2)에 영향 → 스냅샷 후 수행하거나 재시작으로 복구 확인

## S12. 같은 이름으로 다시 등록 (덮어쓰기)
- **목적:** 이름 중복 시 동작을 확인한다.
- **단계:** 「+ 시스템 등록」에서 이름을 이미 있는 `petstore`로 적고 다른 주소로 등록.
- **기대 결과 (코드):** 오류 없이 기존 등록을 **교체**(직접 추가한 API와 최초 등록 시각은 유지). 화면엔 중복 경고 없음
- **기록할 것:** 응답과 교체 후 상세

## S13. 실행기가 없을 때 (운영)
- **목적:** 액션 실행기가 뜨지 않았을 때 화면을 본다.
- **단계:** (a) 부팅 직후 실행기가 준비되기 전에 탭을 연다, 또는 (b) `studio.env`에 존재하지 않는 `KINETIC_URL`을 넣고 재시작.
- **기대 결과:**
  - (a) 빨간 배너 「kinetic-action 에 닿지 못했습니다 (시작하지 않음). 키네틱 액션 실행기(kinetic-action)가 아직 시작되지 않았거나 시작하지 못했습니다. 로그 폴더의 kinetic.log 를 확인하세요.」, 목록 실패 문구
  - (b) 「kinetic-action 에 닿지 못했습니다 (<주소>). kinetic-action 에 닿지 못했습니다 (…): ConnectError. KINETIC_URL 과 서비스 기동 여부를 확인하세요.」 형태, 예제 시스템 자동 등록 없음, 신원 배지 `신원 미설정 · 조회 전용`(토큰 미설정 시, 코드 기준 추정)
- **주의:** 실행기 상태는 페이지에서 한 번만 읽어 기억하므로, 실행기가 나중에 떠도 탭을 새로 고치기 전엔 배너가 남을 것으로 추정
- **기록할 것:** 두 경우의 상태 응답

## S14. 포트가 바뀐 뒤 재시작 (운영)
- **목적:** 예제 서비스 포트가 바뀌어도 등록 주소가 따라가는지 본다.
- **단계:** 예제 ERP 선호 포트(27841)를 다른 프로그램이 점유한 상태에서 앱 재시작(또는 `ONTOLOGY_LITE_ERP_PORT` 지정).
- **기대 결과:** `sample-erp`의 활성 주소·스펙 주소·환경 `local`이 새 포트로 바뀜, 로그 `시스템 주소 갱신 sample-erp: … → …`. 사용자가 바꾼 나머지 설정은 유지
- **기록할 것:** 재시작 전후 상세
