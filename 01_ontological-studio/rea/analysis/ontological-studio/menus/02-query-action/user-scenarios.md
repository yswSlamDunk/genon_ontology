## 검토 요청 (사용자)
1. 실제로 써 본 화면·동작과 다른 부분이 있나요? (특히 계획 카드의 버튼 문구, 승인 후 안내)
2. 빠진 사용 방법이 있나요?
3. 중요하지 않아 빼도 되는 시나리오가 있나요?

## 공통 사전 상태
- 분석용 데이터 폴더(ADR-0004)에서 앞 메뉴(M8 → M3 → M4 → M7 → M1 → M6)까지 진행한 상태(ADR-0009 연쇄).
- 예제 온톨로지 「공급망 운영 (예제)」 발행됨, 예제 액션 3개(`Shipment.expediteShipment`, `PurchaseOrder.holdPurchaseOrder`, `Customer.notifyCustomer`, 모두 승인 임계치 0 → 항상 사람 승인 필요, 최대 대상 20).
- 내장 액션 실행기와 예제 시스템 `sample-erp`·`sample-wms`·`sample-crm`이 떠 있음(M7).
- 에이전트: Claude Code(cliagents) 기본. 비교용으로 내장 에이전트(deepagents)도 1회 기록 권장.

## S1. 질의·액션 탭 열기
- **목적:** 질문·지시를 함께 받는 대화 화면에 들어간다.
- **단계:** 홈의 「질의·액션」 카드(설명 「온톨로지에 묻고, 지시하면 액션을 계획·실행합니다.」, 에이전트 필요 배지)를 누른다.
- **기대 결과:**
  - Studio 탭이 `view=act`로 열림. 상단 내비에 「💬 질의·액션」 선택.
  - 대화가 비어 있으면 가운데에 제목·모드 이름 「질의·액션」, 설명 「구축된 온톨로지에 질문하고, 지시하면 정의된 액션을 계획해 승인·확인을 거쳐 외부 시스템에 실행합니다. 실행한 것은 "취소해"로 되돌릴 수 있습니다.」, 예시 버튼 4개:
    「3일 넘게 늦어진 입고 선적은 어떤 것이고, 어느 협력사 건이야?」, 「3일 넘게 늦어진 입고 선적을 긴급 처리해 줘. 사유는 생산 차질 우려.」, 「방금 한 긴급 처리를 취소해 줘.」, 「어떤 액션을 쓸 수 있어?」
  - 입력창 안내문 「질문하거나 지시하세요. 예: 3일 넘게 늦어진 입고 선적은? / 그 선적들 긴급 처리해 줘 (사유: 생산 차질 우려)」.
  - 오른쪽에 온톨로지 그래프(스키마·인스턴스).
  - 튜토리얼은 예시가 "예제 온톨로지의 골든 퀘스천·골든 커맨드"라고 하지만, 0.1.1에서는 **화면에 고정된 문구**다(다른 온톨로지여도 같은 예시).
- **기록할 것:** 화면 캡처, 탭을 열 때 요청(`/api/schema`, `/api/graph?limit=0`, `/api/sessions`, `/api/act/health` 등)

## S2. 질문하고 근거와 함께 답 받기 (튜토리얼 13)
- **목적:** 자연어 질문에 그래프 조회 근거가 붙은 답을 받는다.
- **단계:** 예시 1번을 누르거나 `3일 넘게 늦어진 입고 선적은 어떤 것이고, 어느 협력사 건이야?`를 입력해 보낸다.
- **기대 결과 (튜토리얼 실측):**
  - 상태 줄 「질의·액션 모드 실행 시작...」 → 도구 칩이 차례로 나타남(스키마 읽기 → 이름 해석 → Cypher 조회 등) → 답이 흐름(약 30초).
  - 답 = 결론(SHP-03 9일, SHP-02 7일, 협력사 Shenzhen Goldline PCB) + 근거(어떤 노드·관계·조건으로 찾았는지) + 경계(SHP-06은 정확히 3일이라 제외, "아무것도 바꾸지 않았다", "발행 스냅숏이라 실제와 다를 수 있다").
  - 오른쪽 그래프에서 답에 쓰인 노드(조회 결과에 나온 노드)가 강조됨.
  - 아무 데이터도 바뀌지 않음(실행기 계획·실행 없음).
- **기록할 것:** SSE 이벤트 순서(`status` → `tool_start`/`tool_result` 반복 → `traversed_nodes` → `token` … → `done`), 각 도구 이름과 인자 형태, 강조된 노드 수, 포털 Cypher 검산 결과와 일치 여부.
- **주의:** 근거는 구조화된 인용 데이터가 아니라 **답 본문(마크다운)** 에 들어 있다. 화면의 구조화된 근거는 도구 칩(인자·결과)과 그래프 강조뿐.

## S3. 이어서 묻기
- **목적:** 같은 대화에서 앞 맥락을 이용한다.
- **단계:** S2 대화에서 `그 협력사의 다른 미결 발주는?` → `PCB 납땜 불량 클레임은 어느 고객의 어떤 주문에서 나왔어?`
- **기대 결과:** 첫째 PO-001($82,000)·PO-002($41,000), 둘째 Tokyo Devices의 SO-05(클레임 T-3). "그 협력사"를 앞 답에서 해석.
- **기록할 것:** 후속 턴에서 Claude Code가 `--resume`으로 이어지는지(같은 CLI 세션 id), 도구 호출 수.

## S4. 답할 수 없는 질문
- **단계:** `안전재고보다 재고가 적은 품목이 있어?`
- **기대 결과:** "온톨로지에 재고 정보가 없다"고 이유와 함께 답함(지어내지 않음).
- **기록할 것:** 답 구조(이유 제시), 시도한 도구.

## S5. 지시 → 계획 카드 (튜토리얼 16 ①)
- **목적:** 지시를 액션 계획(드라이런)으로 바꾼다.
- **단계:** `3일 넘게 늦어진 입고 선적을 긴급 처리해 줘. 사유는 생산 차질 우려.`
- **기대 결과:**
  - 에이전트가 액션 목록 → 대상 조회 → 계획 요청(약 25~50초). 답 본문에 허용/거부 표, plan id, 만료 시각, 단계 순서, 첫 호출 미리보기, "Studio 의 plan 카드에서 승인이 필요합니다"류 안내 후 **멈춤**.
  - 대화에 **계획 카드**: 머리 「실행 계획」 + `Shipment.expediteShipment` + 상태 배지 「승인 대기」 + 「새로고침」 버튼; 요약 「허용 2건 · 거부 0건 · 사람 승인 필요 · 만료 <시각> · 작성 lite-agent」; 표(구분/대상 키/속성 최대 3열/사유) SHP-02, SHP-03; 「호출 미리보기 (4건)」 접이식(첫 호출 JSON); 「승인 메모 (선택)」 입력과 「승인」 버튼.
  - 아직 아무것도 바뀌지 않음.
- **기록할 것:** SSE `kinetic_plan` 이벤트(plan_id, status, requires_approval, tool), 카드가 부르는 `GET /api/act/plans/{id}`, 응답 필드(allowed/denied/preview/expires_at/actor_sub), 실행기 감사 표의 `plan` 행.

## S6. 승인 (튜토리얼 16 ②)
- **단계:** 계획 카드에 메모(예 `확인함`)를 적고 「승인」.
- **기대 결과:** 배지 「승인됨」, 카드 아래 안내 「에이전트가 만든 계획입니다. 승인되었습니다 — 대화에서 “실행해”라고 요청하면 에이전트가 실행합니다.」. 승인자는 화면 공용 신원 `lite-user`로 기록.
  - 화면에는 「실행」 버튼이 **나오지 않는다**(계획 작성자 = 에이전트, 실행은 작성자만 가능).
- **기록할 것:** `POST /api/act/plans/{id}/approve` 본문 `{note}`·응답, 감사 표 `approve` 행(actor_sub=lite-user).

## S7. 실행 (튜토리얼 16 ③)
- **단계:** 대화에 `실행해`.
- **기대 결과:** 에이전트가 계획 상태(approved)를 확인하고 **같은 plan**을 실행(다시 계획하지 않음). 카드가 실행 결과를 보여 줌: 「실행 <run id> · 성공」, 대상별 표(대상 키/결과/단계 칩 `WMS ✓ ERP ✓`/HTTP/시도/오류). 답 본문에 대상·단계별 결과 표.
  - 원천 확인: 포털(`sample`) 또는 데이터소스 탭에서 SHP-02·SHP-03 `priority = URGENT`, ERP 납기 독촉 2건 생성.
- **기록할 것:** SSE `kinetic_run`(run_id, plan_id, status, tool), `GET /api/act/runs/{id}` 응답(targets/steps/compensations), 업무 시스템 호출 헤더(`Idempotency-Key`, `X-Kinetic-Run`), 원천 DB 전후 차이, 그래프 되쓰기(`priority`).

## S8. 취소 = 역순 보상 (튜토리얼 16 ④)
- **단계 A (대화):** `방금 한 긴급 처리를 취소해 줘.`
- **단계 B (카드, 대안):** 실행 결과 카드의 「취소 사유 (선택)」 입력 + 「취소(보상)」 → 확인창 「이 실행을 취소할까요? 성공한 대상의 단계를 역순으로 되돌립니다.」 (안내 「성공한 대상을 역순으로 되돌립니다. 승인은 필요 없습니다.」)
- **기대 결과:** 상태 「보상 완료」, 「취소 요청 — <주체> · 사유 “…” · 시각」, 「보상 이력 (호출 순서)」 표 4행: SHP-03 erp(withdrawExpediteRequest) → SHP-03 wms(setShipmentPriority) → SHP-02 erp → SHP-02 wms, 각 「보상 성공 (200)」, 계기 「취소」. 원천 priority가 실행 직전 값(NORMAL)으로 복구.
- **기록할 것:** 대화 경로(`compensate_run`, 주체 lite-agent)와 카드 경로(`POST /api/act/runs/{id}/compensate`, 주체 lite-user, approver 역할로 허용) 둘 다, 감사 `compensate` 행.

## S9. 실습 과제 — 발주 보류 (튜토리얼 16 확인 문제)
- **단계:** `Shenzhen Goldline PCB의 미결 발주를 모두 보류해 줘 (사유: PCB 납땜 불량 조사)` → 승인 → `실행해` → 데이터소스 탭 `erp.purchase_order`, `erp.po_hold` 확인 → `취소해 줘`.
- **기대 결과:** 허용 PO-001, PO-002 / 거부 0. 실행 후 `ON_HOLD`, `po_hold`에 사유·이전 상태·요청자 행. 취소 후 `OPEN`. "모든 협력사"로 지시하면 CLOSED 발주가 「미결 발주만」 사유로 거부(또는 에이전트가 필터로 미리 걸러 거부 0).
- **기록할 것:** 거부 사유 문자열이 정책 description 그대로인지.

## S10. 쓸 수 있는 액션 묻기 / 승인 없이 실행 요청 / 만료
- **단계:**
  1. `어떤 액션을 쓸 수 있어?`
  2. 계획 카드가 「승인 대기」인 상태에서 승인하지 않고 `실행해`.
  3. 계획 후 10분(기본 만료) 넘게 기다렸다가 승인 또는 실행.
- **기대 결과:**
  1. 에이전트 신원(lite-agent, 역할 scm_operator)으로 보이는 액션 3개와 대상·입력·단계.
  2. 에이전트가 "승인이 필요하다"고 안내하고 멈춤. 실행을 시도하면 실행기가 409 `approval_required` 「허용 대상 N건 — 사람 승인이 필요합니다 (Studio 에서 승인).」
  3. 상태 「만료」, 승인 시 409 `plan_expired` 「plan 이 만료됐습니다. 다시 plan 하세요.」 → 에이전트가 같은 조건으로 재계획.
- **기록할 것:** 각 오류 코드·메시지, 카드 표시.

## S11. 대화 관리 (튜토리얼 13 끝)
- **단계:** 레일 「워크스페이스」 펼치기 → 지난 대화 목록 → 다른 대화 선택 → 새 대화 → 대화 삭제. 홈으로 가서 「최근 항목」의 「질의·액션 대화」 클릭.
- **기대 결과:**
  - 첫 질문 시 대화 제목 = 질문 앞 30자(+`...`). 대화 목록은 모드 `act`인 대화만.
  - 대화를 다시 열면 메시지·도구 칩·계획 카드가 복원(카드는 plan/run을 다시 조회해 최신 상태).
  - 홈 최근 항목: 종류 「질의·액션 대화」, 누르면 `view=act&session=<id>`로 그 대화.
  - 0.1.1 화면에서는 질의·액션 모드에 파일 첨부가 **꺼져 있다**(튜토리얼의 📎 첨부와 다름 — 확인 대상).
- **기록할 것:** `POST /api/sessions?title=새 대화&mode=act`, `PATCH /api/sessions/{id}?title=…`, `PUT/GET /api/sessions/{id}/messages?mode=act` 본문 형태, 삭제 후 재시작 시 상태.

## S12. 실행 중 끼어들기 (Claude Code 전용)
- **단계:** 에이전트가 도구를 쓰는 중 입력창에 추가 지시를 보낸다.
- **기대 결과:** 「작업 중 지시」 표시, 상태 「사용자 지시를 반영해 방향을 바꿉니다...」. Codex·내장 에이전트면 전달 안 됨 → 턴이 끝난 뒤 보통 메시지로.
- **기록할 것:** `POST /api/agent/steer?session_id=&mode=act` 응답, SSE `steered`.
