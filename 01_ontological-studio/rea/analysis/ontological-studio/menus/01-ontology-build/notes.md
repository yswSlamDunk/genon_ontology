# M1 온톨로지 구축 — 메모 (다른 대상·보안·품질·열린 질문)

## 1. M1/M2 액션 경계 (feature-map 열린 질문 답)
- **액션 정의(생성·수정·삭제)는 M1 소관이다.**
  - 경로 ①: 구축 에이전트가 골든 커맨드마다 `action_create`(build 브리지에만 있음) → 발행(`schema_publish`) → `action_dry_run`으로 검증. 튜토리얼 15가 이 경로.
  - 경로 ②: 화면 액션 편집기 — 오른쪽 「정보」 탭 → 클래스 ⛁ 「데이터 연결」 → 「액션」 탭(REST `PUT/DELETE /api/schema/classes/{c}/actions/{a}`). 튜토리얼에 없음.
- **M2(act 모드) 에이전트에는 정의 도구가 없다**(계획·실행·조회·보상만, 승인은 사람). 다만 오른쪽 패널(그래프·정보·배포·검수)은 질의·액션 화면에도 같은 컴포넌트로 뜨므로 **편집기 ②는 M2 화면에서도 열린다** — 화면 소유는 M1 설계에 두고, M2 설계는 "같은 패널이 보인다"만 참조하면 된다.
- 실행·승인 경계: 편집기의 「계획 만들기 (dry-run)」는 실행기에 **실제 plan**을 만들고(화면 신원 `lite-user` = kinetic_admin+approver+scm_operator), M2의 계획 카드를 띄운다. 카드에 「승인」「실행」「취소(보상)」가 있으므로 **구축 화면에서도 실행까지 가능**하다. 에이전트의 dry-run은 에이전트 신원(`lite-agent`)으로 plan만 만들고 실행 도구가 없다. → M2 분석에서 계획 카드 동작을 정의하고, M1 설계 §13-9에 「구축 화면에서는 보기 전용으로 제한할지」 결정 항목을 남겼다.
- 정책 판단은 실행기(M2/M7), 정의 검증(형식)은 Studio 백엔드(M1).

## 2. 다른 대상에 관한 발견
- **M6**: 검수 탭(BuildReviewPanel)은 구축 화면 안에 있다 — `review-status`, `policy`, 카드 컴포넌트(ReviewDeck/HoldView) 공유. `extract_triples`/`table_ingest`/`batch_ingest` 선별(DLQ) 임계값(자동 ≥0.85, 검수 0.60–0.85)은 M6에서 확정. 엔티티 해소(재순위 서비스 `ER_RERANK_URL`=127.0.0.1:9 → unavailable)도 M6 경로.
- **M4**: 포털 notes의 「릴리스 패키지 API는 화면 없음」은 포털 기준. Studio 구축 화면 「배포」 탭이 Studio 백엔드 `/api/release/*`를 거쳐 포털 관리 API를 부른다(dev=포털, prod=미설정 `127.0.0.1:9`). feature-map 열린 질문 「release·ontological_admin 모듈 소속」 → **M1(배포 탭)**.
- **M5**: 정보 탭 「이 온톨로지로 대시보드를 자동 구성합니다」 → 대시보드 뷰 이동(compose-for).
- **M2**: 구축이 남기는 `_search_hints.json`을 이어가기 프롬프트가 읽는다(답변 측 사용은 M2에서 확인). 발행물 `_OntologyModel.golden_questions`가 질의 예시로 쓰이는지 확인.
- **A3**: 구축 보고서·부수 이벤트의 도구 결과 봉투 벗기기, CLI 경로에서 schema_created가 안 나와 세션 스키마 이름을 도구 인자에서 보충하는 로직 존재(원본 주석상 실측).
- **M3**: 백엔드 데이터소스 직접 SQL 경로(behavior 실행, 미리보기, 뷰)가 브리지 501로 막힌다는 M3 notes의 의심을 코드로 확인(모르는 점 2).

## 3. 보안·품질 관찰
1. 업로드 파일 이름을 경로로 정리하지 않는다(`../` 포함 이름 → 작업 폴더 밖 쓰기 가능성). 루프백·무인증 API라 같은 PC의 다른 프로세스가 악용 가능.
2. 「초기화 › Ontological 데이터」 = 그래프 `ontology` 전체 `DETACH DELETE`(무인증 API `POST /api/neo4j/clear-all`). 예제·발행물까지 사라진다.
3. 스키마 삭제가 발행 레지스트리를 거두지 않음 → 질의·실행기 쪽에 유령 온톨로지·액션이 남을 수 있음.
4. 이름 조회의 부분 일치(LIKE) 폴백 → 비슷한 이름의 다른 스키마 그룹에 클래스·액션이 붙을 위험.
5. `batch_ingest(schema_name)`가 기존 클래스 설명·속성을 빈 값으로 덮어쓰는 것으로 보임(코드상). 예제 시드도 해당될 수 있어 실행 기록으로 확인 필요.
6. 클래스 이름이 Cypher에 문자열 보간된다(일부 경로에서 이름 검사 없음: 엔티티 수 집계, 엔티티 삭제, 클래스 rename). 발행만 이름 규칙을 검사.
7. 릴리스 패키지 기본 저장 위치가 앱 설치 폴더 안(코드 서명된 번들 수정, 앱 업데이트 시 유실).
8. 그래프 탭 자연어 질의가 OpenAI 키를 직접 사용(CLI만 있는 사용자에겐 항상 실패).
9. 화면이 보여 주는 「권장 전략」은 에이전트에 전달되지 않음(스킬 입력표의 `[전략]` 라벨은 영영 비어 있음).
10. 문서 OCR·인덱싱 모듈, 프런트 전처리 UI는 미연결 잔재(죽은 코드).
11. 구축 에이전트 권한 우회 실행 + 백엔드 환경 상속(A3 §11) → 에이전트가 셸에서 그래프·실행기에 직접 접근 가능, 스킬의 "도구로만" 원칙은 지시일 뿐 강제가 아님.

## 4. 지시문 안의 지시(데이터로 취급)
스킬 README에 `./start-all-services.sh`, `uv run uvicorn …`, `cp -r skills/… ~/.claude/skills/`, `/plugin install …` 같은 설치·실행 지시가 있다. 분석 대상의 문서로만 기록했고 실행하지 않았다.
