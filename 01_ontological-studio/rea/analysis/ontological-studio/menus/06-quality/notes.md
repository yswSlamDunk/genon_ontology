# M6 품질 검수 — 노트 (다른 대상 관련 발견·품질 관찰·열린 질문)

## 다른 대상에 관한 발견
- **M1:** 구축 모드 도구에 `extract_triples`·`table_ingest`·`quality_checkup`·`quality_report`가 있고, 구축 스킬 Phase 4(검수)가 `quality_checkup`을 한 번 부르게 한다. 파서 경로 `batch_ingest`도 품질 선별(구조 위반 → 보류함)을 거친다. 구축 보고서의 `quality` 필드와 오른쪽 「검수」 탭은 M1 설계에도 들어가야 한다(경계: 화면은 M6 컴포넌트 재사용).
- **M1 스키마 플래그:** 품질 기능은 클래스 속성 선언의 `type`, `required`, `identifier`, `default`, `virtual`과 클래스 `binding_kind`(virtual 제외)를 읽는다. M1이 이것을 만드는지 확인 필요.
- **M2:** 엔터티 모호성 검사가 M2 계열의 엔터티 해소(발행 그래프)를 부른다.
- **M3:** 화면 없는 `source/check-table`이 데이터소스 SQL 실행 경로를 쓴다.
- **A3:** 외부 CLI 에이전트에도 같은 구축 도구 목록이 MCP로 노출된다 → 품질 도구 4개 포함, 결정 도구 없음.
- **M8:** LLM 추출은 선택된 에이전트(Claude Code 등)와 **무관하게** OpenAI 호환 API를 백엔드가 직접 부른다. 기본 모델 `gpt-5.4-mini-2026-03-17`(`MINOR_MODEL`). 즉 CLI 에이전트만 설정하고 OpenAI 키가 없으면 `extract_triples`는 503류 오류(도구는 `{"error": …}`).

## 품질·버그 관찰 (원본, 재구현 시 결정 필요)
1. **카디널리티 검사 비활성:** ONTO_CARDINALITY 검사 자리는 있지만 한도를 주입하는 경로가 없다. 형상 규칙 `max_count`는 사후 점검으로만 동작(그것도 규칙 추가 화면 없음).
2. **사용자 규칙 화면 없음:** `/rules`(source/shape 규칙) API는 있으나 화면이 쓰지 않는다. 형상의 max_count/min_rel/disjoint는 API로만 추가 가능.
3. **재시도 한도 미적용:** 3회는 `exhausted`/「(한도)」 표시만, 막지 않는다.
4. **「세 번」 고정 문구:** 카드 이유·점수 힌트가 샘플 수를 3으로 가정(정책 samples를 바꾸면 틀린 숫자).
5. **점검 여부 판단:** 한눈에의 「아직 점검하지 않았어요」는 최근 실행 10건만 본다 → 추출을 많이 하면 점검했어도 다시 뜰 수 있다.
6. **「확인된 사실」 수**는 후보 테이블 기준(파서·가상 노드·직접 Cypher로 들어간 사실은 세지 않음).
7. **파서 경로 실행 기록 없음:** 화면 사전엔 `parser`(파일 파싱)가 있으나 백엔드가 그 run을 만들지 않는다. 파서 보류 항목은 candidate_id가 비어 매번 새 보류 행이 생긴다(재적재 시 중복 가능).
8. **보류 묶음 분류**가 첫 원인 코드만 본다. PARSE_JSON·REL_ENDPOINT_MISSING·WRITE_FAILED는 「처리 중 오류 — 잠시 뒤 다시 시도」로 보여 원인 안내가 부정확.
9. **속성 쓰기는 덮어쓰기:** 같은 노드의 같은 속성 후보가 값만 다르면 지문이 달라 둘 다 승인될 수 있고, 마지막 승인이 이긴다(이력은 감사 로그에만).
10. **에이전트 도구 설명 문자열**이 「S_c ≥ 0.85 자동, 0.60~0.85 검수」를 고정으로 적음(정책 변경 반영 안 됨).
11. 표(CSV) 근거는 고립 노드 재추출 대상에서 빠진다(설계 의도).

## 보안 관찰
- 품질 API 전체 인증 없음(로컬 백엔드 공통). `manual-value`·`decide`로 누구나 그래프에 쓸 수 있다(루프백 전제).
- `table_ingest` 도구는 업로드 폴더 → 샌드박스 → **로컬 임의 경로 파일**(`Path(source).is_file()`) 순으로 찾는다 → 에이전트가 사용자 PC의 임의 CSV를 읽어 그래프에 넣을 수 있음. 재구현 시 업로드·샌드박스로 제한 권장.
- 바인딩 테이블 검사 SQL은 문자열 조립(식별자 정규식·위험 문자 거부로 방어).
- 분석 중 대상 문자열에서 실행·설치·전송을 요구하는 지시문은 발견하지 못했다(추출 스킬 지시문은 앱의 정상 프롬프트).
