- 출처: 튜토리얼 `12-build.md` 5단계(검수와 발행), `02-tour.md`(홈 카드 표), 화면 캡처 `images/quality.webp`. 튜토리얼은 이 메뉴를 거의 설명하지 않으므로, S2 이후 대부분은 배포본 0.1.1 프런트엔드 번들과 Studio 백엔드 품질 모듈에서 확인한 동작으로 채웠다(근거는 `code-trace.md`).
- 기준 버전: 0.1.1 (ADR-0012)
- 성격: 화면 자체는 LLM을 부르지 않는 결정적 동작이 대부분이다. 단, **추출 실행(S12)과 고립 노드 재추출(S8의 일부)** 은 LLM을 부르므로 결과 내용은 실행마다 다르다 → 구조·계약 기준으로 기록(ADR-0010).

## 검토 요청 (사용자)
아래 시나리오를 보고 다음을 알려 주세요. 맞으면 "확인"만 주셔도 됩니다.
1. 실제로 써 본 화면·동작과 다른 부분이 있나요?
2. 빠진 사용 방법이 있나요?
3. 중요하지 않아 빼도 되는 시나리오가 있나요? (특히 「⚙ 고급」 화면 S11–S15는 전문가용이라 범위에서 뺄지 결정이 필요합니다)

## 공통 사전 상태
- 분석용 데이터 폴더로 실행, M8 설정(OpenAI 키)과 M1 온톨로지 구축까지 진행한 상태(ADR-0009 연쇄 기록).
- 판단할 항목을 만들려면 M1 구축 중 에이전트가 `extract_triples`(문서) 또는 `table_ingest`(CSV)를 써야 한다. 파서 경로(`batch_ingest`)만 쓰면 보류함 항목만 생기고 「확인하기」 항목은 생기지 않는다.
- 예제 온톨로지 `공급망 운영 (예제)`만 있는 첫 실행 직후에는 모든 숫자가 0이다(튜토리얼 캡처와 같음).

## 화면 이름 정리
- 홈 카드 「품질 검수」 → Studio 탭 `view=quality`. 화면 머리말은 **「지식 품질」**.
- 위쪽 탭: 「🏠 한눈에」 · 「🙋 확인하기」 · 「🗂️ 보류함」, 오른쪽 끝 「⚙ 고급」.
- 같은 「확인하기」·「보류함」 화면이 **M1 구축 화면 오른쪽 「검수」 탭**에도 들어 있다(S10).

## S1. 품질 검수 열기 — 한눈에 (튜토리얼 12장 5단계)
- **목적:** 구축이 남긴, 사람이 판단할 것이 몇 건인지 본다.
- **단계:**
  1. 홈에서 「품질 검수」 카드를 누른다.
  2. 위쪽 목록에서 온톨로지를 고른다(처음엔 목록 첫 온톨로지 또는 최근 구축한 온톨로지가 자동 선택).
- **기대 결과:**
  - 머리말 「지식 품질」, 온톨로지 선택 상자, 탭 「한눈에」가 선택됨.
  - 큰 문장 「지식 지도에 확인된 사실이 **N**개 들어 있어요.」 — N = 자동 적재 + 승인 + 수정 승인된 후보 수(그래프 전체 노드 수가 아님).
  - 카드 3개: 「🙋 N 확인이 필요한 내용 · 확인하기 →」, 「🗂️ N 문제가 있어 보류된 항목 · 보류함 열기 →」, 「🏗 + 문서·표는 온톨로지 구축에서 넣어요 · 온톨로지 구축으로 →」.
  - 「지금 할 일」: 확인 대기·보류가 있으면 각 한 줄 + 버튼, 최근 활동에 점검 기록이 없으면 「🩺 아직 지식 지도를 점검하지 않았어요.」 + 「점검하기」(→ 보류함 탭으로 이동만 함), 모두 없으면 「🎉 지금은 할 일이 없어요. 모두 깔끔해요.」
  - 접힌 「어떻게 동작하나요?」: 확실한 내용은 바로 들어가고, 애매한 내용은 사람에게 묻고, 문제가 있는 내용은 보류함에 원인과 함께 모은다는 3갈래 설명 + 「AI가 직접 승인하거나 보류를 풀 수는 없습니다. 판단은 항상 사람이 합니다.」
  - 「최근 활동」: 최근 실행 최대 6건(시각 + 「문서에서 뽑기 'x' — N개 찾음 (바로 넣음 a · 확인 b · 보류 c)」 형식). 없으면 「아직 활동이 없어요.」
  - 탭 배지: 「확인하기」 옆에 대기 건수, 「보류함」 옆에 열린 보류 건수.
- **기록할 것 (4단계):** 화면 캡처, 열 때 요청(스키마 상세 + `GET /api/quality/summary`)과 응답 형식.
- **주의:** 「온톨로지 구축으로」를 누르면 같은 탭 안에서 구축 화면으로 넘어간다(선택한 온톨로지를 넘김).

## S2. 확인하기 — 카드 한 장씩 판단
- **목적:** 자동으로 넣기엔 애매했던 사실을 사람이 맞다/틀리다로 판단한다.
- **단계:**
  1. 「확인하기」 탭을 연다.
  2. 위쪽 종류 칩(전체·관계·값·항목·같은 대상·새 종류)으로 거른다.
  3. 카드의 문장·이유·원문 근거를 읽고 「✓ 맞아요(Y)」, 「✕ 틀려요(N)」, 「나중에(→)」 중 하나를 누른다.
- **기대 결과:**
  - 머리말 「확인할 내용 i / n」. 카드 순서는 **종합 점수가 높은 것부터**(빨리 승인으로 소진되도록).
  - 카드: 종류 표시(관계/값/항목/같은 대상인가요?/새 종류 제안), 큰 문장(예: 「A 공급한다 B」, 「A의 단가 1200」), 확신 배지(확실함/애매함/약함/확인 필요) + 이유 한 줄(예: 「AI가 같은 문단을 세 번 읽었는데 2번만 이 내용을 찾았어요.」, 「원문에서 이름을 그대로 찾지 못했어요.」, 「비슷한 관계 이름으로 바꿔 읽었어요. 맞는지 봐 주세요.」).
  - 근거 상자: 「원문 — 문서명」 또는 「원본 표 파일 N번째 줄」, 인용 구간이 노란 표시로 강조되고 앞뒤 약 220자.
  - 승인: 토스트 「지식 지도에 넣었어요: …」, 카드가 사라지고 다음 카드. 그래프에 노드·관계·속성이 MERGE로 쓰인다.
  - 기각: 「넣지 않았어요: …」. 같은 사실은 다시 추출돼도 되살아나지 않는다.
  - 스키마 규칙에 어긋나면 승인해도 거절: 「넣을 수 없어요 — 스키마 제약 위반으로 적재할 수 없습니다: …」.
  - 남은 카드가 없으면 「🎉 지금은 확인할 내용이 없어요.」 + 「온톨로지 구축으로」.
  - 키보드: Y=승인, N=기각, E=고치기, →=다음(입력란에 커서가 있을 때는 무시).
- **기록할 것:** 카드 종류별 캡처, `POST …/decide` 요청·응답, 승인 뒤 그래프에 생긴 노드·관계의 속성(`_confidence`, `_run_id`, `_evidence_ref`), 트랜잭션 감사 메타데이터(actor = `studio-user`).

## S3. 확인하기 — 고쳐서 넣기
- **목적:** 거의 맞지만 이름·관계·값이 틀린 사실을 고쳐 넣는다.
- **단계:** 카드에서 「✎ 고쳐서 맞아요(E)」 → 양식 수정 → 「이렇게 고쳐서 넣기」.
- **기대 결과:**
  - 관계: 「누가」·「어떤 관계」(스키마 관계 목록, 설명 표시)·「누구에게/무엇을」. 값: 「값」. 항목: 「이름」. 새 종류: 「이름」·「설명」.
  - 결측 보정 제안 카드는 버튼 문구가 「이 값 쓰기 / 다른 값 입력 / 쓰지 않기」, 같은 대상 제안은 「같은 대상 맞아요 / 서로 달라요」(고치기 없음), 새 종류 제안은 「지도에 추가 / 이름 고쳐서 추가 / 추가 안 함」.
  - 고친 결과도 스키마 게이트를 다시 거친 뒤 그래프에 쓰인다.
- **기록할 것:** `edit` 요청 본문 형태(종류별), 응답 `status: edited`.

## S4. 새 종류(스키마 변경) 제안 승인
- **목적:** 추출기가 스키마에 없는 클래스·관계를 발견해 제안한 것을 지식 지도에 추가한다.
- **단계:** 「새 종류」 칩 → 카드 「새로운 관계 …(A → B)」 → 「지도에 추가」.
- **기대 결과:** 토스트 「지식 지도에 새 종류를 추가했어요: …」, 응답 `applied: "schema"`. 온톨로지 스키마(M1 「정보」 탭)에 클래스/관계가 추가되고 출처가 사람(검수)으로 기록된다. 이미 같은 제안을 처리했으면 거절.
- **기록할 것:** 승인 전후 스키마 응답 비교.
- **주의:** 이 승인은 그래프 데이터가 아니라 **스키마**를 바꾼다. 이 관계를 기다리며 보류됐던 항목은 자동으로 풀리지 않는다 — 보류함에서 「다시 시도」해야 한다.

## S5. 보류함 — 지식 지도 점검하기
- **목적:** 이미 들어간 지식 지도 전체를 한 번에 점검해 문제를 보류함에 모은다.
- **단계:** 「보류함」 탭 → 위 「🩺 지식 지도 점검」 상자의 「지금 점검하기」.
- **기대 결과:**
  - 버튼이 「점검 중…」으로 바뀌었다가, 결과 알약 7개: 「✏️ 빠진 값 n」, 「🏝️ 연결 없음 n」, 「🔗 같은 대상 자동 연결 n」, 「🙋 같은 대상인지 확인 n」, 「⚖️ 값 충돌 n」, 「💡 채울 값 제안 n」, (있으면) 「✓ 해결됨 n」. 0이면 초록, 있으면 빨강/주황.
  - 토스트 「점검을 마쳤어요 — 고칠 것 a건, 확인할 제안 b건」.
  - 확인할 제안이 있으면 「제안 확인하러 가기 →」(→ 확인하기 탭).
  - 점검은 ① 필수 속성 누락·타입 위반·연결 규칙(형상 검증) ② 관계가 하나도 없는 노드 ③ 다른 원천의 같은 대상(자동 SAME_AS 연결 또는 확인 요청) ④ 같은 대상끼리 값이 엇갈림 ⑤ 빠진 값 제안을 차례로 한다. ①②④는 보류함에, ③의 확인 요청과 ⑤는 확인하기로 간다.
  - 이전 점검에서 보류됐다가 이번에 문제가 사라진 항목은 자동으로 닫힌다(「해결됨」).
- **기록할 것:** `POST /api/quality/checkup` 응답 전체, 점검 전후 그래프의 `SAME_AS` 관계.
- **주의:** 점검은 그래프에 쓰기를 한다(같은 대상 자동 연결 = `SAME_AS` 관계 생성). 같은 원천 시스템 안의 두 노드끼리는 비교하지 않는다(문서 추출 노드끼리는 비교함).

## S6. 보류함 — 원인별 고치기 (스키마·원천)
- **목적:** 보류된 항목을 원인별로 묶어 보고 바로 고친다.
- **단계:** 「보류함」에서 원인 묶음을 펼쳐 항목별 버튼을 누른다.
- **기대 결과 (묶음 = 아이콘·제목·건수·도움말, 항목 = 쉬운 문장 + 버튼 + 「버리기」 + 접힌 「자세히」):**

  | 묶음 | 해당 원인 | 항목 버튼 |
  |---|---|---|
  | 🧭 지식 지도에 없는 관계 | 허용 어휘에 없는 술어 | 「‘X’ 관계를 지도에 추가하고 넣기」 — 스키마에 관계를 추가한 뒤 그 항목을 다시 판단 |
  | 🧩 지도의 규칙과 맞지 않음 | 정의역·공역 위반, 없는 클래스·속성, 이름 규칙, 카디널리티 | 「다시 시도」 |
  | 📄 원본 표의 잘못된 행 | 원천 결측·중복·범위·참조·허용 목록, 식별자 없음 | 「다시 시도」(현재 파일을 다시 읽음) |
  | ⛔ 파일 전체를 가져오지 않음 | 차단 규칙 위반 | 「다시 시도」 |
  | ✏️ 꼭 있어야 할 값이 빠졌거나 형식이 틀림 | 필수 속성 누락·타입 위반 | 값 입력란 + 「저장」 (S7) |
  | 🔗 연결 규칙 위반 | 최대 연결 초과·배타 클래스 | 「다시 시도」(재검사) |
  | 🏝️ 다른 항목과 연결이 없음 | 고립 노드 | 「원문에서 연결 다시 찾기」 (S8) |
  | ⚖️ 같은 대상인데 값이 서로 다름 | 다중 원천 값 충돌 | 「대표로 쓸 값:」 값 버튼들 (S9) |
  | 🌫️ 근거가 너무 약함 | 종합 점수가 하한 미만 | 「그래도 넣기」 — 사람 승인으로 적재 |
  | ⚠️ 처리 중 오류 | 그 밖(그래프 쓰기 실패 등) | 「다시 시도」 |

  - 묶음에 「다시 시도」류 항목이 2건 이상이면 머리에 「모두 다시 시도」. 묶음당 8건만 보이고 「N건 더 보기」로 20건씩 더.
  - 「다시 시도」 결과 토스트: 「지식 지도에 넣었어요」, 「해결됐어요」, 「찾은 연결을 확인하기로 보냈어요」, 「아직 같은 문제가 있어요」, 「자동으로 다시 시도할 수 없는 항목이에요」 등(여러 건이면 「(N건)」).
  - 「버리기」(title 「이 항목은 넣지 않습니다」): 「버렸어요. 다시 넣지 않아요」.
  - 「자세히」: 원인 코드, 단계, 시도 횟수, 처음 본 시각, 상세 문구, 원본 데이터(JSON).
  - 비어 있으면 「🗂️ 보류된 항목이 없어요.」
- **기록할 것:** 원인별 항목 캡처, `POST /api/quality/dlq/redrive` 결과(`outcome`) 종류, 「관계를 지도에 추가하고 넣기」 시 스키마 API 호출.
- **주의:** 다시 시도는 **현재** 스키마·정책으로 다시 판단한다. 같은 사실은 MERGE라 여러 번 해도 중복되지 않는다. 시도 횟수 3회를 넘어도 막지 않고 표시만 한다(고급 화면 「(한도)」).

## S7. 보류함 — 빠진 값 직접 넣기
- **목적:** 필수 속성이 비어 있는 노드에 사람이 값을 넣는다.
- **단계:** 「✏️ 꼭 있어야 할 값이…」 묶음에서 「<속성> 입력」 칸에 값을 적고 「저장」.
- **기대 결과:** 「<이름>의 <속성> 값을 넣었어요」. 입력값도 같은 게이트(스키마 검사)를 거쳐 그래프에 쓰이고, 곧바로 형상 검증을 다시 돌려 해결된 보류 항목을 닫는다. 값이 스키마를 어기면 거절되고 그 입력은 기각으로 남는다.
- **기록할 것:** `POST /api/quality/manual-value` 요청·응답(`resolved` 수), 그래프의 해당 속성.

## S8. 보류함 — 고립 노드의 연결 다시 찾기
- **목적:** 관계가 하나도 없는 노드에 대해 원문을 다시 읽어 관계를 찾는다.
- **단계:** 「🏝️ 다른 항목과 연결이 없음」 항목의 「원문에서 연결 다시 찾기」.
- **기대 결과:** 버튼이 「원문 다시 읽는 중…」. 그 이름이 나온 원문(이전 추출 근거, 최대 3개)을 다시 LLM 추출 → 새 관계 후보가 확인하기로 가면 「찾은 연결을 확인하기로 보냈어요」, 바로 들어가 연결되면 「원문에서 연결을 찾았어요」, 원문이 없으면 「아직 같은 문제가 있어요」(상세: 문서를 추가하라는 안내).
- **기록할 것:** 재추출 실행 기록(최근 활동에 「다시 시도」 또는 「문서에서 뽑기」), 결과 outcome.
- **주의:** LLM 호출(OpenAI 키 필요). 표(CSV)에서 온 근거는 재추출 대상이 아니다.

## S9. 보류함 — 값 충돌에서 대표 값 고르기
- **목적:** 같은 대상으로 이어진 노드끼리 속성 값이 다를 때 어느 값을 대표로 쓸지 정한다.
- **단계:** 「⚖️ 같은 대상인데 값이 서로 다름」 항목 「A = B 의 <속성>」에서 값 버튼(예: 「4.5 (ERP)」)을 누른다.
- **기대 결과:** 「대표 값으로 4.5 (ERP) 를 골랐어요. 원래 값은 그대로 남아요」. 그래프의 원천 값은 바뀌지 않고 선택만 기록된다. 이후 점검에서 그 (묶음, 속성)은 충돌로 다시 보류되지 않는다.
- **기록할 것:** 선택 전후 그래프 값이 그대로인지, 고급 「식별자」 화면의 대표 값 표시.

## S10. 구축 화면 오른쪽 「검수」 탭과 구축 보고서
- **목적:** 구축 대화를 하면서 바로 판단한다.
- **단계:**
  1. M1 구축 대화에서 에이전트가 검수 단계(점검 도구 호출)까지 마치고 보고서를 낸다.
  2. 보고서 카드 「🙋 확인이 필요한 내용 N건 · 🗂️ 보류 M건 — 사람이 판단해야 지식 지도에 들어갑니다.」의 「검수 탭에서 보기」를 누른다(또는 오른쪽 탭 「검수」, title 「빌드가 남긴 것 중 사람이 판단할 것」).
- **기대 결과:**
  - 오른쪽 탭 「검수」 배지 = 확인 대기 + 보류 합.
  - 패널 머리: 온톨로지 선택(title 「검수할 온톨로지」), 요약 「지도에 n개 · 확인 필요 a · 보류 b」.
  - 하위 탭 「🙋 확인하기 (a)」·「🗂️ 보류함 (b)」 — 내용은 S2–S9와 같은 화면(좁은 배치). 확인 대기가 0이고 보류가 있으면 보류함이 먼저 열림.
  - 에이전트 응답이 끝날 때마다 숫자가 새로 고쳐짐.
  - 온톨로지를 고르기 전: 「구축을 시작하면 이곳에 사람이 판단할 내용이 모입니다.」
  - 에이전트는 승인·기각·재처리를 할 수 없다(도구가 없음). 보고서의 숫자는 에이전트가 쓴 값이 아니라 백엔드가 붙인 실제 숫자.
- **기록할 것:** 보고서 카드 캡처, 탭 전환 시 요청(`review-status`, `policy`, 스키마 상세).

## 고급 화면 (「⚙ 고급」, title 「점수·규칙·임베딩 모델 등 세부 화면」)
머리말 「추출 품질 검수」, 온톨로지 선택, 탭 「검수 큐 · DLQ · 검증 · 식별자 · KGE · 판정 이력 · 추출 실행 · 정책」, 「새로고침」. 튜토리얼에 전혀 없는 전문가용 화면이다.

## S11. 고급 — 검수 큐·판정 이력·일괄 처리
- **단계:** 「검수 큐」에서 종류를 거르고, 항목을 골라 오른쪽 상세를 본다. 체크박스로 여러 개 골라 「선택 승인 (n)」/「선택 기각」. 「판정 이력」 탭에서 처리된 후보를 본다.
- **기대 결과:**
  - 목록 항목: 종류 칩, 문장(`A —REL→ B`, `A.prop = v`, `A : Class`, `A ≡ B (Class)`, `관계 X (A → B)`/`클래스 X`), 점수 칩(소수 둘째 자리).
  - 상세: 원인 칩(코드 · 설명), 게이트 메모, 「점수 분해 — S_c = G × m × (linear|harmonic)」 막대 5개(S_llm 일관성, S_ground 근거, S_graph 지지, G_onto × m, S_c) + 힌트(빈도·logprob·어휘·cos·거리·우회경로·KGE), 「원문 근거 (n)」 최대 3개(인용을 원문에서 못 찾으면 「모델이 낸 인용이 원문에서 그대로 발견되지 않았습니다: “…”」), 「연결 대상의 인접 서브그래프 (n개 노드)」 그래프(후보 관계는 점선, 새 노드는 「(신규)」).
  - 「수정」 양식(엔터티는 클래스도 바꿀 수 있음) + 「승인」·「수정 후 승인」(변경이 있어야 켜짐)·「기각」, 안내문 「승인·수정은 스키마 게이트를 다시 거친 뒤 그래프에 쓰이고, 판정은 다음 추출의 검수 예시로 쓰입니다. 기각한 사실은 재추출해도 되살아나지 않습니다.」
  - 일괄 처리 결과: 「n건 처리, m건 실패: …」. 일괄은 승인·기각만.
- **기록할 것:** `bulk-decide` 응답, 판정 이력 상태 표시(자동 적재/승인/수정 승인/기각).

## S12. 고급 — 추출 실행 (LLM)
- **단계:** 「추출 실행」 탭 → 업로드 파일을 고르거나 「(직접 입력)」으로 문서 이름과 텍스트를 붙여 넣고 「추출 실행」.
- **기대 결과:** 안내문(샘플 수·자동 적재 하한·검수 하한이 정책값으로 채워짐). 실행 중 「추출 중입니다. 청크 수와 샘플 수에 비례해 시간이 걸립니다…」 → 「추출 완료 (run_…)」, 결과 줄 「청크 n · 후보 n · 자동 적재 a · 검수 b · DLQ c · 기존 판정 보존 d」. 「최근 실행」 표(시각·종류·원천·자동·검수·DLQ).
- **기록할 것:** 실행 시간, 응답 통계 형식, 생성된 후보 구조. OpenAI 키가 없으면 503 「OPENAI_API_KEY 가 없어 LLM 추출을 할 수 없습니다.」
- **주의:** 같은 문서를 다시 추출해도 이미 사람이 판정한 사실은 바뀌지 않고 「기존 판정 보존」으로 센다.

## S13. 고급 — 검증: 원천 CSV 검증 후 적재, 형상 검증, 고립 노드
- **단계:**
  1. 「검증」 탭 ①: CSV 파일을 고르거나 업로드 → 컬럼·행 수 표시, 매핑 JSON 초안이 자동으로 채워짐 → 고쳐서 「검증만」 또는 「검증 후 적재」.
  2. ②: 「형상 검증 실행」, 「고립 노드 린팅」.
- **기대 결과:**
  - 매핑 초안: 원천 시스템 `ERP`, 첫 클래스, 키 = 이름이 id/code/key로 끝나는 첫 컬럼, 이름 = name/…명 컬럼, 클래스 속성과 이름이 같은 컬럼, 키에 `not_null`(row) 규칙 하나.
  - 결과 표(컬럼·규칙·방식·관측·기준·결과 「통과」/「실패 n행 · 코드」). block 규칙 실패 시 배너 「차단 규칙 위반 — 테이블 전체 적재를 멈췄습니다 (SRC_TABLE_BLOCKED)」. 적재 시 「n행 중 적재 a · 격리 b · 후보 n (자동 · 검수 · DLQ)」.
  - 형상 표(Shape 설명 · 출처 스키마/규칙 · 위반 수 · 예시 이름), 토스트 「형상 n개 검사 · 위반 m건 · 해소 k건」.
  - 고립 노드: 「고립 노드 n건 — …」, 토스트 「… DLQ 에서 관계를 재추출할 수 있습니다」.
- **기록할 것:** 매핑 초안, 행 격리와 블록 동작, 표에서 들어간 노드 키 형식(`원천시스템:원천키`).

## S14. 고급 — 식별자(같은 대상)와 결측 보정
- **단계:** 「식별자」 탭 → 「식별자 해소 실행」, 「결측 보정 제안 만들기」. 충돌이 있는 속성에서 「대표로」.
- **기대 결과:** 「SAME_AS 자동 n건 · 검수 제안 n건 · 충돌 n건」, 보정 「기본값 · 이웃 패턴 · KGE 링크 → 검수 큐 n」. 묶음 카드: 「동일 개체」 + 원천별 구성원(원천·이름·키), 표(속성 · 원천별 값 · 대표 값 / 「충돌 — 선택 필요」). 없으면 「아직 이어진 동일 개체가 없습니다.」
- **기록할 것:** 클러스터 응답 형식, 자동 연결 기준(식별 속성 일치·정규화 이름 일치).

## S15. 고급 — KGE(그래프 임베딩)·내보내기·정책
- **단계:** 「KGE」 탭 → 「학습」, 「링크 예측 후보 만들기」, 주어·관계·목적어를 골라 「점수」, 「검수 판정 내보내기 (JSONL)」, 「학습 삼중주 (TSV)」. 「정책」 탭에서 가중치·결합 방식·하한 등을 고쳐 「저장」.
- **기대 결과:**
  - 학습: 「KGE 학습 중…」 → 「학습 완료 — 삼중주 n · MRR x · s초」, 통계 6칸(삼중주, 엔터티·관계, 손실 처음→끝, MRR·Hits@3, 거리 양성·음성, 학습 시각). 관계(삼중주)가 4개 미만이면 오류 「학습할 삼중주가 너무 적습니다 (n < 4)」.
  - 점수: `(h, r, t)` 확률 막대와 「상위 후보: …」, 최근 4건 유지.
  - 링크 예측: 「링크 예측 n건을 검수 큐로 보냈습니다 (확률 0.7 이상만 …)」.
  - 정책: 「가중치 합: x」. 합이 1이 아니거나 하한 순서가 틀리면 저장 거절(422). 저장 성공 「정책을 저장했습니다. 다음 추출·재처리부터 적용됩니다.」
- **기록할 것:** 정책 기본값 응답, 내보내기 파일 형식.
- **주의:** 정책 변경은 이미 내려진 판단을 바꾸지 않는다(다음 추출·재처리부터).
