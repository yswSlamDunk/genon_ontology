# M5 온톨로지 앱 — 메모 (다른 대상·보안·품질·열린 질문)

근거 위치 표기는 `code-trace.md`와 같다.

## 1. 대시보드가 앱 패키지 안에 저장된다 (중요 — 데이터·배포 문제)
- 저장 폴더는 `BOARD_STORAGE_DIR`가 없으면 백엔드 패키지 기준 `data/boards`(`BD/spec_store.py:34-38`). 셸은 이 변수를 넣지 않는다(M8 code-trace의 "앱이 덮어쓰는 변수" 목록에 없음). 결과적으로 `/Applications/Ontological Studio.app/Contents/Resources/runtime/studio/app/backend/data/boards/`에 쓴다.
- 배포본 0.1.1에 **개발 중 만든 대시보드 JSON 12개가 동봉**돼 있다(2026-10-24~26 생성: 「공급망 현황판」 4벌, 「공급망 조치판」, 「발주 조치판」 4벌, 「조치판」 2벌, 자동 구성 결과 1개). 모든 사용자의 갤러리·홈 최근 항목에 처음부터 보인다.
- 영향(추정): ① 앱을 새 버전으로 바꾸면 사용자가 만든 대시보드가 사라진다. ② `ONTOLOGICAL_STUDIO_USER_DATA`로 데이터 폴더를 나눠도 대시보드는 공유된다 — **분석용 데이터 폴더로 4단계 기록을 해도 평소 설치의 대시보드 폴더를 건드린다**(ADR-0004의 격리 전제가 깨짐). ③ 서명된 앱 번들 안 파일을 수정한다(ad-hoc 서명이라 실행엔 영향 없을 가능성). 사용자 실행 흔적: 같은 위치에 `data/releases/`가 2026-10-29 생성됨(release 모듈도 같은 패턴, `B/modules/release/api.py:36`).
- 4단계 기록 전 할 일(제안): 동봉 12개 파일 해시를 기록하고, 기록용 실행 때는 studio.env에 `BOARD_STORAGE_DIR=<분석용 폴더>/boards`를 넣는다(studio.env 값이 백엔드에 전달됨 — M8 확인). 이것은 원본 동작을 바꾸는 설정이므로 기록 문서에 명시.

## 2. 대시보드 "사람이 적용" 원칙의 구멍
- 스트리밍 편집에서 Claude Code에게 브리지 도구 `dashboard_patch`가 허용되고, 그 도구는 `dry_run=false`면 즉시 저장한다(`BD/tools.py:73-81`, `BD/ask.py:263-270`). 스킬은 "승인 후에만 dry_run=false"라고 하지만 `-p` 단발 실행이라 대화 중 승인이 없다. 모델이 스킬을 오해하면 「적용」 전에 파일이 바뀐다. 이어서 서버가 같은 패치를 dry-run으로 다시 검증해 「승인 대기」 카드를 보여 주므로 사용자는 차이를 모른다.
- 또한 「AI 로 고치기」 요청마다 프런트가 먼저 현재 화면을 PUT으로 저장한다 — "저장" 버튼을 안 눌러도 저장됨.
- 구현 권장: 브리지 쪽에서 dry_run 강제.

## 3. 코드 앱 보안 모델 — 정적 분석 관찰 (실행 확인 필요)
의도(코드 주석·튜토리얼): 앱은 읽기 전용 Cypher만, 값 변경은 SDK `act()` 창에서 사람이 승인, 앱 탭에는 셸 API 없음, 에이전트는 승인·실행을 시험할 수 없음.
관찰된 틈:
1. **같은 오리진**: 앱은 `http://127.0.0.1:<web>/apps/<id>/`에서 Studio UI와 같은 오리진으로 뜬다. 생성된 코드(또는 사용자가 손으로 고친 코드)가 `fetch('/api/…')`로 분석 백엔드 API 전체(온톨로지 수정·삭제, 대시보드 저장, `/api/act/plans/<id>/approve`·`execute` 등)를 부를 수 있다. 백엔드 `/api/act/*`에는 브라우저 확인이 없다(`B/modules/kinetic/api.py:492-517`). 읽기 전용 경계는 `/codeapps/api/query`에만 있다.
2. **헤더 확인은 우회 가능**: `/codeapps/api/act/.../approve|execute|compensate`의 "사람 확인"은 `Sec-Fetch-Mode` 헤더 존재 여부뿐(`E/main/codeapps.js:189`). 에이전트에게 허용된 `curl`로 `-H 'Sec-Fetch-Mode: cors'`를 붙이거나 백엔드 `/api/act/...`를 직접 부르면 통과한다(추정). 브라우저 안 앱 코드는 헤더가 자동으로 붙으므로 처음부터 통과.
3. **SDK 창은 앱 문서 안 DOM**: `act()` 창은 앱 페이지에 삽입되는 요소라 앱 코드가 버튼을 프로그램으로 누르거나 똑같이 흉내 낼 수 있다. 튜토리얼 20의 "앱이 흉내 낼 수 없습니다"는 정확하지 않다.
4. **미리보기 iframe**: Studio 안 미리보기는 샌드박스 속성 없는 같은 오리진 iframe(`F@2143942` 부근). 생성 코드가 `window.parent`로 Studio 창에 접근할 수 있고, Studio 탭에는 셸 브리지(`liteShell`)가 있으므로 탭 열기·자연어→Cypher 등 셸 기능을 부를 수 있다(추정). "생성 코드는 셸 API를 못 쓴다"는 앱 탭에서만 성립.
5. **에이전트 권한**: Claude Code 허용 도구 `Bash(curl:*)`는 접두 일치라 임의 URL 요청·`-o`로 임의 경로 쓰기·외부 전송이 가능할 수 있다(추정). Read/Glob/Grep은 폴더 밖도 읽을 수 있다(추정 — 규칙 문서로만 금지). `acceptEdits`는 cwd 밖 편집을 자동 승인하지 않는 것으로 알려져 있으나 확인 필요. Codex는 `--full-auto`(작업 폴더 쓰기 샌드박스).
6. **읽기 전용 검사**: 단어 기반(`CREATE|MERGE|DELETE|DETACH|SET|REMOVE|DROP|FOREACH|LOAD CSV`, 일부 CALL)이고 세션은 READ 모드. 패브릭 문장 중 `REFRESH DATASOURCE`, `SHOW …`(데이터소스 접속 정보 노출 여부는 M3 확인) 등은 단어 목록에 없다. 엔진이 READ 모드를 강제하는지 모름.
7. 셸 웹 오리진·백엔드는 인증이 없다(A1). 같은 PC의 다른 프로세스도 위 경로를 모두 쓸 수 있다.
- 4단계에서 확인할 것: S13·S16 + 위 1–6을 **분석용 폴더에서만**, 실제 업무 시스템 변경이 없는 방식(계획만, 승인 X)으로. 우회 시험(헤더 위조 curl 등)은 사용자 결정 후.

## 4. 대시보드 품질 관찰
- 화면 「저장」이 `model:{}`, `description:""`로 덮어 자동 구성이 넣은 모델 정보·에이전트 메모가 사라진다(F@2167841 부근 `tt`).
- 홈 최근 항목의 대시보드 행: 정보 칸이 늘 비고(목록 응답에 모델 이름 없음), 누르면 갤러리만 열린다(특정 대시보드 아님).
- 이름 기반 키: 이름을 바꿔 저장해도 처음 키 유지. 갤러리 목록을 다시 읽기 전 같은 이름으로 두 번 만들면 키가 겹쳐 덮어쓸 수 있다(추정).
- 저장 검증의 "질의 단어" 검사가 제목·이유 문장에도 걸린다(예: 위젯 제목 "Match 결과 보기 " 같은 문장 → 저장 거부 가능, 대소문자 무시).
- SQL 필터에서 위험 문자 값은 **조용히 필터를 뺀다**(`BD/query_gen.py:285-287`) → 예: `O'Neil` 필터를 걸면 그 위젯은 필터 없이 전체 숫자를 보여 준다. 선택(클릭) 값에도 같은 경로가 쓰인다.
- 값 목록 API의 가상 클래스 경로가 컬럼·테이블 이름을 검사 없이 SQL 문자열에 넣는다(`BD/service.py:344-350`). 속성 이름은 프로파일에서 찾은 것만 통과하므로 영향은 작다(MCP 도구가 단일 SELECT·바인딩 테이블만 허용 — A3).
- 스트리밍 CLI 편집에는 제한 시간이 없다(단발만 180초). CLI가 멈추면 화면이 「생각 중…」에 머문다.
- `box_plot`·`word_cloud`는 막대로 그린다(이름과 다른 모양). `pivot_table`은 표.
- 프로파일 캐시가 (schema_id, published_at) 키라 데이터가 바뀌어도 재발행 전엔 옛 통계(고유값 수 → 위젯 종류)가 유지. 팔레트 「새로고침」은 캐시를 비우지 않는다(`/cache/clear`는 화면에서 안 씀 — 추정).
- 위젯 액션 창의 조건 값 변환이 숫자 모양 문자열을 숫자로 바꾼다(`"0012"` 같은 코드 값 → 12).

## 5. 다른 대상 메모
- **A1**: 코드 앱 탭이 셸 브리지 없이 뜨는 것은 확인. 다만 미리보기 iframe 경로(§3.4)는 A1 설계 "코드 앱 탭에는 셸 API를 주지 않는다"의 범위 밖 — A1 15절(개선 여지)에 추가 검토 권장.
- **A3**: 대시보드 스트리밍·자동 구성 CLI는 cwd를 지정하지 않음(사용자 데이터 폴더). 자동 구성도 같은 스트리밍 함수라 브리지 도구 3개가 붙는다. 코드 앱 실행기의 종료 코드 3/5와 이벤트 어휘는 A3 design §5와 일치.
- **M1**: 「대시보드도 같이 생성」이 구축 화면 쪽에도 있는지(BoardPanel의 `composeFor` 입력). 자동 구성은 모델의 `golden_questions`·`intent`를 쓴다. 관계의 `join` 속성("a = b")이 전역 필터 연결의 유일한 재료 — 구축이 이 속성을 안 만들면 교차 필터가 동명 속성에만 걸린다.
- **M2**: 위젯 액션 창이 M2 계획 카드 부품을 재사용(`Go`). 코드 앱은 `plans/by-ids`를 쓰고 대시보드는 `plans`(where). 액션 목록 항목 형태 `{class, action, description, key_property, parameters}`는 M2 설계와 맞출 것.
- **M3**: 가상 클래스 위젯은 SQL 도구 → 패브릭. MySQL 원천은 따옴표·CAST 차이 대응 코드가 있음(원본 주석).
- **M4**: 포털 notes의 질문 "대시보드 질문과 같은 방식의 한 턴 실행기" → 대시보드는 `agent_turn.py`를 쓰지 않고 백엔드 안에서 직접 CLI를 부른다(같은 패턴, 다른 코드). 셸 nl2cypher 주석의 "Studio's dashboards make" 표현은 같은 호출 형태라는 뜻.
- **M8**: `MCP_ALLOW_DATASOURCE_EXPANSION=false`면 가상 클래스 위젯 가드 G8, 팔레트 비활성, 열기 판정 `expansion_disabled`. `BOARD_STORAGE_DIR`·`BOARD_MCP_SAMPLE_LIMIT`·`BOARD_MCP_TIMEOUT`은 studio.env로 바꿀 수 있다.

## 6. 라이선스 메모
- 코드 앱 런타임에 Vue 3.5.31(MIT), ECharts(Apache-2.0)가 그대로 들어 있다. 새 구현에서 같은 라이브러리를 쓰면 각 라이선스 고지 필요. 대시보드 렌더러는 gridstack 13.0.1(MIT)과 ECharts를 번들에 포함.
- 내장 지도(한국 시도·미국 주 GeoJSON)의 출처는 번들에서 확인 못 함 — 새 구현은 출처가 분명한 지도 데이터를 쓸 것.

## 7. 열린 질문 (사용자)
- 4단계 기록에서 코드 앱 보안 우회(§3)를 실제로 시험할지, 시험한다면 범위(헤더 위조 curl, 앱 코드의 `/api/act` 직접 호출, iframe 부모 접근).
- 새 구현에서 "같은 오리진 앱 + 헤더 확인" 구조를 재현할지(비교 테스트 일치) 아니면 처음부터 격리할지.
- 동봉 대시보드 12개를 원본 비교 기준에 포함할지.
