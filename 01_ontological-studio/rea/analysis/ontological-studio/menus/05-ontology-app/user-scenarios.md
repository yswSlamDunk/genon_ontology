## 공통 사전 상태
- 분석용 데이터 폴더(ADR-0004)에서 앞 메뉴(M1 구축·M6·M2)까지 진행한 상태 (ADR-0009 연쇄 기록)
- 예제 온톨로지 「공급망 운영 (예제)」가 `ontology` 그래프에 **발행**되어 있음(클래스 Supplier·Item·PurchaseOrder·Shipment·Customer·SalesOrder·Claim 등, 골든 퀘스천 있음)
- 내장 액션 실행기와 예제 업무 시스템(ERP·WMS·CRM)이 떠 있고, 예제 액션(발주 보류 `PurchaseOrder.holdPurchaseOrder`(대상 키 `po_id`), 긴급 처리 `Shipment.expediteShipment`(`shipment_no`), 고객 안내 `Customer.notifyCustomer`(`cust_no`))이 발행돼 있음
- 에이전트: Claude Code(기본). Codex·내장 에이전트는 S19에서 별도 확인
- **주의(중요):** 0.1.1 배포본은 대시보드 저장 폴더가 **앱 패키지 안**이고, 그 안에 개발 중 만든 대시보드 12개가 들어 있다(`공급망 현황판`, `공급망-현황판-2`…, `발주-조치판`, `조치판-2` 등). 그래서 처음 열어도 갤러리가 비어 있지 않다. 기록 전 갤러리 목록을 그대로 캡처해 둔다(`notes.md` §1).

## S1. 온톨로지 앱 화면 열기
- **목적:** 앱을 만드는 화면의 구성을 본다.
- **단계:**
  1. 홈에서 「온톨로지 앱」 카드를 누른다.
- **기대 결과 (튜토리얼 + 배포본 화면):**
  - 머리말 「온톨로지 앱」, 부제 「발행된 온톨로지로 만든 화면들입니다.」, 오른쪽 「+ 빈 화면에서 시작」
  - 「말로 만드는 온톨로지 앱」 영역: 안내문(왼쪽 자원을 끌어다 놓거나 `@`로 부르기 / 대시보드는 멘션한 클래스가 바로 위젯이 되고 나머지 말은 에이전트가 구성안 / 코드 앱은 에이전트가 코드를 씀)
    - 왼쪽 서랍: 자원 트리(검색칸 「자원 찾기 (클래스·속성)」, 모델 이름별 묶음과 개수, 클래스(사람이 읽는 이름 + 클래스 이름, 가상 클래스는 「가상」 배지) ▸ 속성, 각 줄의 「+」), 아래 「클래스 N개 · 끌어다 놓거나 + 를 누르세요」
    - 「앱 이름」 칸(placeholder 「비우면 문장에서 짓습니다 — 예: 공급망 현황판」, 최대 60자)
    - 입력창(placeholder 「예: @PurchaseOrder 를 공급사별 금액으로 보고, 늦어지는 @Shipment 상태도 같이 보여 줘」)
    - 「골든 퀘스천」 예시 칩(발행 모델들의 골든 퀘스천, 최대 6개) — 누르면 입력창에 들어감
    - 아래: 「대시보드」/「코드 앱」 전환, 「▤ 자원 닫기 / 온톨로지 자원」 토글(고른 자원 수 배지), 안내 문구, 「앱 만들기 →」 또는 「코드로 앱 만들기 →」 버튼(입력이 비면 비활성)
  - 「모델 전체로 자동 구성」 영역: 모델 선택 상자 + 「대시보드도 같이 생성」 버튼
  - 「코드 앱 N」 목록(있을 때만), 「대시보드 N」 목록(카드: 이름, 「위젯 N개 · 날짜」, × 삭제)
  - 목록이 비면 「아직 만든 앱이 없습니다. 위에서 말로 만들거나 모델 전체로 자동 구성하세요.」
- **기록할 것 (4단계):** 화면 캡처(낮·밤), 열 때 요청 순서(`/api/board/health` → `/api/board/classes` → `/api/act/actions` → `/api/board/dashboards`, `/codeapps/api/apps`)와 응답 형식, 갤러리에 미리 들어 있는 대시보드 목록

## S2. 말로 대시보드 만들기 — 「공급망 현황판」 (튜토리얼 17)
- **목적:** 멘션으로 위젯을 바로 놓고, 나머지 요청은 에이전트 구성안으로 받아 적용한다.
- **단계:**
  1. 앱 이름에 `공급망 현황판`, 「대시보드」 선택.
  2. 입력창에 `@Purch` → 후보 팝업(↑↓ 고르기 · Enter 넣기 · Esc 닫기)에서 `PurchaseOrder` → Enter. 칩이 생김.
  3. `를 협력사별 금액 합계로 보고,` 입력.
  4. 왼쪽 트리에서 `Shipment`를 문장 안으로 끌어다 놓고 `는 상태별 건수로 보여 줘` 입력.
  5. 「앱 만들기 →」(또는 ⌘/Ctrl+Enter).
  6. 오른쪽 「AI 로 고치기」에 구성안이 나오면 「적용」을 누른다.
- **기대 결과:**
  - 안내 문구가 「위젯 2개를 바로 놓고, 나머지는 에이전트에게 묻습니다.」로 바뀜
  - 편집 화면으로 바뀌고, 클래스마다 「X 분석 중…」 → 「X → <위젯 종류> (<규칙>)」 메시지. 약 1초 안에 위젯 2개가 놓임(튜토리얼: 처음엔 날짜별 추이 그래프 — 규칙 O1)
  - 대시보드가 **자동 저장**됨(이름이 저장 키가 됨, 같은 이름이 있으면 `-2`, `-3` …)
  - 이어서 에이전트 스트리밍: 「AI 로 고치기」 패널에 사용자 말 + `⚙ <도구 이름>`/`↳ <결과>` 줄 + 「생각 중…」. 실측 약 35초
  - 결과 카드: 「승인 대기」 배지 + 바뀔 내용 목록(`set dimensions : [order_date, status] → [supplier_id]`처럼 취소선→굵은 글씨), 「취소」·「적용」. 에이전트가 축을 시간→범주로 바꾸면 종류를 막대로 바꾸는 줄이 **자동으로 추가**되어 함께 보임
  - 메시지 「구성안이 오른쪽에 있습니다 — 적용을 누르면 반영됩니다.」
  - 「적용」 → 「패치를 적용했습니다.」, 위젯이 협력사별 금액 합계 막대·선적 상태별 건수 막대로 다시 그려짐, 배지 「적용됨」
  - 거부된 구성안은 「거부됨」 + `경로 — 사유` 목록. 바꿀 것이 없거나 에이전트가 말로만 답하면 「바꿀 것 없음」 + 에이전트 메모
- **기록할 것:** 요청 순서(recommend ×2 → widgets/query ×2 → PUT dashboards → ask/stream SSE 이벤트들 → patch(dry_run=false) → GET dashboards/{id} → widgets/query), SSE 이벤트 종류·순서, 결과 객체 형태(`valid, applied, diff, errors, patch, note, question`), 저장된 JSON 파일 위치·내용, **적용 전에 이미 저장 파일이 바뀌었는지**(에이전트가 `dashboard_patch(dry_run=false)`를 스스로 부를 수 있음 — `notes.md` §2)
- **주의:** LLM 결과라 구성안 내용은 매번 다름. 구조만 비교(ADR-0010).

## S3. 이어서 고치기 — 위젯 멘션·직접 설정·되돌리기·저장 (튜토리얼 17)
- **목적:** 만든 대시보드를 말과 손으로 고친다.
- **단계:**
  1. 위젯 머리의 `@`를 눌러 그 위젯을 AI 입력창에 칩으로 넣고 `원형 그래프로` → 보내기 → 「적용」.
  2. 위젯을 눌러 오른쪽 인스펙터에서 위젯 종류·시간 입도·축(차원)·지표(속성+집계)를 바꾼다. 「자동 추천으로 되돌리기」를 누른다.
  3. 위젯 하나를 제거한 뒤 상단 「되돌리기」.
  4. 위젯 테두리를 끌어 위치·크기를 바꾼다.
  5. 대시보드 이름을 고치고 「저장」.
- **기대 결과:**
  - 1: 대상 표시가 위젯 이름으로, 안내 「'<위젯>' 위젯을 말로 고칩니다.」. 구성안에 `set widget_kind : … → pie`
  - 2: 인스펙터 머리에 사람이 읽는 클래스 이름, 손댄 위젯에 「고정됨」 배지, 규칙 코드와 이유 문장(예: `R6 'status'(3종) 별로 'amount_usd' 를 막대로 비교합니다.`). 되돌리면 「자동 추천으로 되돌렸습니다.」
  - 3: 「되돌렸습니다.」(되돌리기는 화면 안 기록 — 저장된 파일은 그대로)
  - 4: 12칸 격자, 넓은 화면(860px 이상)은 2열, 좁으면 1열
  - 5: 「저장했습니다.」. 저장 거부 시 「저장 거부: <경로> — <사유>」
  - 낮/밤 테마를 바꾸면 차트의 축·글자 색이 함께 바뀜
- **기록할 것:** 인스펙터 선택지(위젯 종류 17가지, 입도 hour/day/month/quarter/year, 집계 count/sum/avg/min/max), PUT 요청 본문, 저장 거부 예(값에 `MATCH ` 같은 문장을 넣어 저장)
- **열린 질문:** 이름을 바꿔 저장하면 새 파일이 생기는가, 기존 파일이 바뀌는가(코드상 처음 저장된 키를 계속 씀 — 확인 대상)

## S4. 전역 필터와 선택 연동 (튜토리얼 17)
- **목적:** 대시보드 전체 필터와 클릭 교차 필터를 쓴다.
- **단계:**
  1. 위쪽 「필터」 막대의 「+ 필터 추가」에서 `PurchaseOrder › status (범주)`를 고르고 값 `OPEN`.
  2. 기간 필터(시간 속성) 하나를 추가해 `2025-01 ~ 2025-12`처럼 적는다.
  3. 막대 하나(예: 협력사 `S-KR-01`)를 누른다.
  4. 선택의 ×를 눌러 해제한다.
- **기대 결과:**
  - 필터가 없을 때 안내 「기간·지역 같은 필터를 추가하면 대시보드 전체에 걸립니다.」
  - 필터마다 `걸린 위젯 수/전체` 표시(예 `1/2 위젯`), 마우스를 올리면 「모든 위젯에 걸립니다.」 또는 「걸리지 않는 위젯: …」
  - 필터가 걸린 위젯 머리에 「필터 N」 배지, 마우스를 올리면 `라벨: 조인(<관계>)` / `same_name` / 걸리지 않은 사유(「'<클래스>' 에 연결할 속성이 없습니다.」)
  - 3: 「<값> 선택 — 관련 위젯에 필터를 겁니다」, 필터 막대에 「선택 <값> <클래스.속성>」. 선택 값은 클릭한 행의 **키 속성**을 우선 사용
  - 4: 「선택을 해제했습니다.」
  - 행이 많아 잘린 위젯은 「N건 중 M건」 배지, 상한 때문에 집계가 올라간 위젯은 「집계 승격」 배지(계열을 먼저 버리고, 다음에 일→월→년)
- **기록할 것:** `filters/applicability`, `classes/{c}/values`, `widgets/query` 요청 본문(`global_filters`, `selection`)과 응답의 `context` 배열
- **주의:** 필터·선택은 저장 대상이 아님(필터 정의는 저장되지만 선택은 화면 상태) — 저장 후 다시 열어 확인

## S5. 모델 전체로 자동 구성 — 「대시보드도 같이 생성」
- **목적:** 발행 모델 하나로 대시보드를 한 번에 만든다(튜토리얼에 없음, 배포본 기능).
- **단계:**
  1. 갤러리 「모델 전체로 자동 구성」에서 「공급망 운영 (예제)」를 고르고 「대시보드도 같이 생성」.
- **기대 결과:**
  - 버튼이 「구성 중…」, 아래 로그에 클래스마다 `⚙ widget_recommend · <클래스>` / `↳ <클래스> → <종류> (<규칙>)` 또는 `↳ <클래스>: 건너뜀 — <가드 사유>`
  - 이어서 에이전트가 클래스 선택·순서·제목을 고르는 과정(도구 줄·토큰). 에이전트를 못 쓰면 「에이전트를 쓸 수 없어 결정적 순서로 채웁니다. (…)」
  - 완료되면 제외 목록(「제외: Claim(G2), …」)과 함께 새 대시보드가 열림. 제목 기본값 `<모델 이름> 대시보드`(에이전트가 바꿀 수 있음), 위젯 최대 8개, 2열 배치, 전역 필터 후보 최대 3개(값 미지정)
  - 위젯을 하나도 못 만들면 「대시보드를 만들지 못했습니다.」/「위젯을 하나도 만들지 못했습니다.」
- **기록할 것:** `POST /api/board/compose` SSE 전체, 저장 키(에이전트 제목에서 만든 키 — 배포본 안 예제 `공급망_운영___늦어진_입고는…json`처럼 긴 키가 될 수 있음), 실행기 없는 상태와 비교
- **참고:** M1 구축 화면에서 「대시보드도 같이 생성」 흐름으로 이 화면이 열려 바로 자동 구성이 시작될 수 있음(`composeFor`) — M1과 경계 확인

## S6. 빈 화면에서 시작 — 끌어다 놓기
- **목적:** 말 없이 팔레트에서 위젯을 놓는다.
- **단계:**
  1. 「+ 빈 화면에서 시작」.
  2. 왼쪽 「온톨로지 객체」 목록에서 `Supplier`를 캔버스로 끌어다 놓는다(또는 더블클릭).
  3. ▸로 속성을 펼쳐 속성 하나를 오른쪽 AI 입력창에 끌어다 놓는다.
  4. 「새로고침」을 누른다.
- **기대 결과:**
  - 빈 캔버스 안내: 「두 가지 방법이 있습니다.」 — 끌어다 놓기 / 대화
  - 이름 기본값 「새 대시보드」. 위젯이 자동으로 정해짐(종류·규칙 메시지)
  - 가상 클래스는 「가상」 배지, 실데이터 확장이 꺼져 있으면 비활성(끌 수 없음) + 안내 「데이터소스 확장이 꺼져 있습니다…(MCP_ALLOW_DATASOURCE_EXPANSION=false)」
  - MCP에 닿지 못하면 「MCP 에 연결하지 못했습니다. <오류>」
  - 발행 레지스트리에 없는 클래스는 「고아」 배지
- **기록할 것:** 팔레트 목록 응답(`/api/board/classes`), 가드에 걸리는 클래스(데이터 0건 → 「이 클래스에는 아직 데이터가 없습니다.」)

## S8. 대시보드 위젯의 액션 버튼 (튜토리얼 20)
- **목적:** 보고 있는 위젯에서 액션을 계획·승인·실행·취소한다.
- **단계:**
  1. 발주 위젯을 협력사별 금액 막대로 두고 상태를 계열로 나눈다(AI에게 「상태별로 색을 나눠 줘」).
  2. 협력사 `S-KR-01` 막대를 누른다(선택).
  3. 위젯 머리의 「액션 N」을 누른다 → 액션 창.
  4. 「발주 보류」 액션을 고르고(골든 커맨드 문장 표시), 대상 조건이 선택값으로 채워진 것을 확인, 사유 입력 → 「계획 세우기」.
  5. 계획 카드에서 허용/거부 확인 → 「승인」 → 「실행」.
  6. 「취소」(보상).
- **기대 결과:**
  - 액션 창 머리 「액션 — `PurchaseOrder`」, 부제 「계획 → 승인 → 실행 → 취소(보상). 업무 시스템은 액션 실행기를 거쳐서만 호출됩니다.」
  - 대상 조건: 「차트에서 고른 「supplier_id = S-KR-01」 로 채웠습니다.」. 조건이 없으면 「조건이 없으면 모든 인스턴스가 후보이고, 정책이 대상마다 허용·거부를 정합니다.」. 「+ 조건」, 연산자 `= != > >= < <= contains`
  - 필수 입력이 비면 「계획 세우기」 비활성
  - 계획: PO-008 허용, PO-003 거부(「미결 발주만」 정책). 승인·실행 후 막대가 OPEN→ON_HOLD로 다시 그려짐 — 메시지 「액션 결과를 반영해 위젯을 다시 읽었습니다.」. 취소 후 「취소(보상)를 반영해 위젯을 다시 읽었습니다.」
  - 「다른 대상으로」로 계획을 버리고 처음으로, 「닫기」
  - 쓸 수 있는 액션이 없거나 실행기가 꺼져 있으면 「액션 N」 버튼이 없음
- **기록할 것:** `/api/act/actions`, `/api/act/plans`(본문 `{class, action, where, params}`), approve/execute/runs 폴링(1.5초), compensate 요청·응답, 원천(ERP) 상태 변화
- **주의:** 실제 예제 업무 시스템이 바뀜 → 끝에 반드시 취소. M2 계획 카드와 같은 화면 부품 사용

## S16. 읽기 전용·사람 승인 경계 확인 (보안 관찰, 튜토리얼 19·20 확인 문제)
- **목적:** 코드 앱 데이터 경로의 거부 동작을 확인한다.
- **단계 (분석용 데이터 폴더에서만):**
  1. 브라우저 콘솔(미리보기 또는 앱 탭)에서 `query('MATCH (s:Supplier) SET s.tier = 1')`.
  2. 문자열 안에만 쓰기 단어가 있는 질의 `query("MATCH (s:Supplier) WHERE s.name <> 'SET' RETURN count(s) AS n")`.
  3. 터미널에서 `curl -X POST http://127.0.0.1:<web>/codeapps/api/act/plans/<id>/approve`(헤더 없이).
- **기대 결과:** 1: 403 「읽기 전용입니다 — CREATE·MERGE·SET·DELETE 같은 쓰기 절은 쓸 수 없습니다.」 → `query()`가 Error. 2: 정상 실행. 3: 403 「승인·실행·취소는 앱 화면에서 사람이 눌러야 합니다.」
- **기록할 것:** 각 응답. (우회 가능성 — 헤더를 붙인 curl, `/api/act/...` 직접 호출 — 은 `notes.md` §3에 정리. 실제 우회 시험은 사용자 결정 후)
