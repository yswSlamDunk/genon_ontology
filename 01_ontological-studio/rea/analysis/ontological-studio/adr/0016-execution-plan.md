# ADR-0016 실행 방식: 정적 분석은 병렬 에이전트, 실행 기록은 순차
- 상태: 승인(Claude) (2026-10-31) — ADR-0015에 따라 Claude 결정

## 맥락
대상 11개, 백엔드만 Python 약 31k줄. 한 세션에서 순서대로 전부 읽으면 오래 걸리고 맥락이 섞인다. 반면 원본 동작 기록(4단계)은 ADR-0009의 연쇄 순서가 필요하다.

## 결정
- **1·2·3·5단계(정적 분석과 설계 초안)**: 대상별 서브에이전트가 `BRIEF.md`를 따라 수행. 두 차례로 나눠 병렬 실행.
  - 1차: A2 저장소, A3 에이전트·MCP + M8 설정(겹침이 커서 한 에이전트), M3 데이터소스, M4 Portal
  - 2차: M7 시스템 등록, M1 온톨로지 구축, M6 품질 검수, M2 질의·액션, M5 온톨로지 앱
  - A1 셸은 Claude(메인)가 직접 수행 (DMG ↔ 설치본 동일성 확인 포함)
- 서브에이전트는 앱 실행·REA 세션 열기/닫기·증거 내보내기를 하지 않는다(REA 서버 공유).
- **4단계(원본 동작 기록)**: 정적 분석이 끝난 뒤 Claude(메인)가 ADR-0009 순서대로 분석용 데이터 폴더에서 연쇄 실행. 결과로 각 `design.md`의 "모르는 점"을 갱신.
- 서브에이전트 산출물은 Claude가 훑어 형식·클린룸 규칙 위반을 점검한다.

## 결과
병렬로 토큰 사용이 몰린다(에이전트 9개 수준). 대신 사용자가 돌아왔을 때 전 대상의 초안이 준비된다.
