# ADR-0009 분석 순서
- 상태: 승인 (2026-10-31, 사용자가 Claude에게 결정 위임)

## 맥락
사용자 지적: 온톨로지 구축은 데이터소스·시스템 등록 이후에 진행할 수 있다(구축은 클래스·관계뿐 아니라 액션도 만든다). 사용자 작업 의존 순서와 분석에 유익한 순서는 다를 수 있으므로 Claude가 결정한다.

## 결정
A1 셸 → A2 저장소 → A3 에이전트·MCP → **M8 설정 → M3 데이터소스 → M4 Portal → M7 시스템 등록 → M1 온톨로지 구축 → M6 품질 검수 → M2 질의·액션 → M5 온톨로지 앱**

| 순서 | 대상 | 근거 |
|---|---|---|
| 1–3 | A1–A3 | 모든 메뉴의 기반 |
| 4 | M8 설정 | 작고 A3와 겹침. 에이전트 설정이 M1·M2·M5 실행 기록의 전제 |
| 5 | M3 데이터소스 | 원천 데이터의 입구 (생산자) |
| 6 | M4 Portal | 분석상 이유: 이후 메뉴가 그래프를 어떻게 바꾸는지 Cypher로 확인하는 관찰 도구. 튜토리얼 순서와도 일치 |
| 7 | M7 시스템 등록 | 액션이 호출할 대상. M1의 액션 생성 전제 |
| 8 | M1 온톨로지 구축 | 데이터소스·시스템을 재료로 클래스·관계·액션 생성 |
| 9 | M6 품질 검수 | M1 산출물 검수 |
| 10 | M2 질의·액션 | 온톨로지와 액션을 소비 |
| 11 | M5 온톨로지 앱 | 전체를 소비하는 최종 단계 |

## 결과
- 원본 동작 기록(ADR-0006 4단계)은 **분석용 데이터 폴더 하나에서 이 순서대로 연쇄 실행**한다. 각 메뉴의 시작 상태 = 앞 메뉴의 종료 상태.
- 메뉴 사이마다 DB 스냅샷(pg_dump)과 상태 요약을 `baseline/`에 남겨, 특정 메뉴만 다시 기록하거나 구현물과 비교할 때 같은 출발점을 재현한다.
- 앞 메뉴 분석 중 뒤 메뉴에 관한 사실을 발견하면 해당 메뉴 폴더에 메모만 남기고 순서는 유지한다.
