# 00. 비전과 범위

## 1. 한 줄 정의
**흩어진 업무 데이터를 "업무 객체·관계·행동"의 온톨로지로 묶고, 그 위에서 사람과 AI가 질의·판단·실행하는 로컬 데스크톱 플랫폼.**

## 2. 원본과의 관계
| | Ontological Studio 0.1.1 [원본] | 새 플랫폼 [제안] |
|---|---|---|
| 온톨로지 단위 | 클래스. 데이터 연결은 "테이블 하나 = 가상 노드 타입, 행 = 인스턴스" | **Object type**: 저장과 분리된 의미 타입. 여러 원천을 속성 단위로 매핑, 식별자 매칭으로 하나의 객체로 합침 ([02](02-ontology-model.md)) |
| 관계 | 관계 유형 + 가상 관계(두 컬럼 조인) | **Link type**: 카디널리티, 조인 방식 3종(외래키 / 조인 테이블 / 링크 객체) |
| 행동 | 액션(등록 시스템 operation 호출, 정책, 보상) | **Action type**: 파라미터·규칙(객체/링크 편집 + 시스템 호출)·제출 조건·부수효과·감사. 원본 액션 계약을 포함 |
| 로직 | behavior(파라미터 SQL) | **Function**: 질의형·계산형·LLM형. 계산 속성·액션 규칙·앱에서 재사용 |
| 다형성·재사용 | 없음 | **Interface, Shared property, Value type** |
| 변경 관리 | 스키마 그룹 + 발행(전체 덮어쓰기) | **변경 제안(Proposal) → 검토 → 발행(버전)**, 이력·되돌리기 |
| 앱 | 대시보드(말로 만들기), 코드 앱 | 대시보드·코드 앱 유지 + **Object view(객체 360° 기본 화면)**, Object set(저장된 객체 집합) |
| AI | 구축·질의·액션 계획·대시보드 에이전트, MCP | 유지. 도구가 Object type·Action type 단위로 자동 생성(OSDK식), 권한 분리 강화 |
| 보안 | 루프백 의존, 무인증, 에이전트 권한 우회 실행 | 실행별 토큰, 오리진 분리, 사람 승인 증명, 비밀 금고 ([03](03-security.md)) |

[조사] Palantir와의 차이: Palantir는 클라우드 엔터프라이즈 플랫폼(파이프라인, 브랜치, 마킹 보안 등). 새 플랫폼은 그중 **온톨로지 모델링 경험(Ontology Manager)과 Object/Link/Action/Function 개념**을 로컬 데스크톱 규모로 가져온다. 대규모 파이프라인·멀티테넌트·세분화된 마킹 보안은 범위 밖.

## 3. 사용자
- **도메인 설계자**(주 사용자): 업무 객체·관계·액션을 정의하고 데이터를 연결한다. SQL·Cypher는 몰라도 되지만 읽을 수 있으면 좋다.
- **업무 사용자**: 질의하고, 액션을 계획·승인·실행하고, 앱(대시보드)을 쓴다.
- **개발자**: 코드 앱·SDK·MCP로 온톨로지를 외부에서 쓴다.

| F2 | 질의·액션 | 유지 + Action type 기반 계획·승인·실행, Object set 결과 | features/F2 |

## 5. 단계별 범위 [제안 — 결정 대기 D-01]
| 단계 | 포함 |
|---|---|
| **MVP** | 플랫폼 공통, F3 데이터소스, F1의 수동 설계(Object type·Property·Link type·백킹 매핑·Action type 기본) + 발행, F4 콘솔, F2 질의(에이전트)·액션 실행, F7 시스템 등록, F8 설정 |
| **v1** | F1 에이전트 구축(문서·카탈로그·골든 퀘스천), F6 품질 검수, F5 대시보드·Object view, Interface·Shared property·Value type, 변경 제안·이력 |
| **v2** | 코드 앱·SDK, Function(LLM형), 인과 발견, 시점 조회 고급, 외부 MCP 공개 |

## 6. 범위 밖
멀티 사용자 서버 배포, 클라우드 동기화, 대규모 ETL 파이프라인 빌더, 행·열 단위 마킹 보안, OWL 추론기. (OWL/RDF 내보내기는 v2 이후 검토.)

## 7. 성공 기준
1. 튜토리얼 예제(공급망: erp·wms·crm)를 새 플랫폼에서 **Object type 방식으로** 다시 만들고, 원본 튜토리얼의 질의 결과(실측값)를 같은 값으로 재현한다.
2. "3일 넘게 늦은 선적은 어느 협력사의 어느 발주 건인가?" 같은 다원천 질의를 **테이블 조인이 아니라 Object/Link 탐색**으로 답한다.
3. "그 선적을 긴급 처리해 줘" → 액션 계획 → **사람 승인(증명 필요)** → 실행 → 보상(취소)까지 동작하고, 에이전트는 승인할 수 없음을 테스트로 보인다.
4. 원본 대비 보안 약점(03 문서의 위협 목록)이 테스트로 막혀 있다.
