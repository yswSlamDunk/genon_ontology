# 03. 보안 설계

## 1. 원칙
1. **루프백은 경계가 아니다.** 같은 PC의 다른 프로그램·브라우저 탭·AI 도구도 127.0.0.1에 닿는다. 모든 내부 API는 토큰을 요구한다.
2. **사람의 결정은 증명된다.** 승인·발행·삭제 같은 확정 행위는 사람이 했다는 증거가 있어야 하고, 감사 기록에서 사람·에이전트·시스템이 구분된다.
3. **최소 권한.** 구성 요소·에이전트 모드·코드 앱마다 필요한 권한만.
4. **비밀은 값이 아니라 참조로 다닌다.** 실제 값은 OS 키체인에만.

## 3. 인증 — 실행별 세션 토큰
- 셸이 부팅할 때 무작위 **세션 토큰**을 만든다(메모리에만). 코어·게이트웨이는 모든 요청에 `Authorization: Bearer <token>`(또는 같은 사이트 쿠키, HttpOnly·SameSite=Strict)을 요구한다.
- UI(셸의 탭)는 셸이 주입한 쿠키로 자동 인증. 외부 브라우저로 콘솔을 여는 기능은 일회용 링크(짧은 유효기간)로만.
- 코어는 `Host`·`Origin` 검사(DNS 리바인딩 방지), CORS는 게이트웨이 오리진만.
- 외부 MCP/API 클라이언트: 설정 화면(F8)에서 이름·범위(읽기/실데이터/액션 계획)·만료를 정해 **개인 접근 토큰** 발급. 기본 0개.

## 4. 사람 승인의 증명
- 승인·발행·대량 삭제는 **셸의 네이티브 확인 창**(Electron 메인 프로세스가 그리는 OS 대화상자)을 거친다. 창에는 무엇을 승인하는지(액션, 대상 수, 시스템 호출 요약)를 보여 준다.
- 확인하면 셸이 **일회용 승인 증표**(대상 계획 id + 해시 + 만료 60초, 셸만 아는 키로 서명)를 코어에 전달한다. 코어는 증표 없이는 승인하지 않는다.
- 웹 페이지(탭·코드 앱·에이전트)는 이 창을 열 수는 있어도(요청) 대신 누를 수 없다.
- 감사 기록: `actor.kind = human|agent|system`, `actor.id`, `proof = 증표 id`. 에이전트가 만든 계획을 사람이 승인하면 계획자=agent, 승인자=human으로 남는다.
- 직무 분리(02 §10 `separationOfDuties`): 계획자와 승인자가 같은 주체면 거부(1인 사용 모드에서는 사람 본인이 계획·승인 가능하나, **에이전트가 계획한 것은 반드시 사람이 승인**).

## 5. 에이전트 환경
- CLI 에이전트 프로세스에는 **화이트리스트 환경 변수만** 넘긴다: PATH, HOME, 언어 설정, 그리고 턴별 MCP 토큰. DB 비밀번호·실행기 토큰·LLM 키는 넘기지 않는다(필요한 일은 MCP 도구로만).
- 턴별 MCP 토큰은 해당 모드의 도구 집합에만 유효하고 턴이 끝나면 폐기.
- 상세는 04 문서.

| 역할 | 권한 | 사용 |
|---|---|---|
| `wb_owner` | 스키마 소유(마이그레이션) | 부팅 시 마이그레이션만 |

## 7. 비밀 관리
- 저장: OS 키체인(macOS Keychain, Windows Credential Manager). DB에는 `secret_ref`(이름·종류·마지막 사용)만.
- 데이터소스 비밀번호: 그래프 엔진(FDW)이 사용자 매핑에 비밀번호를 요구하면, 코어가 접속 시점에 키체인 값으로 매핑을 만들고 [결정 대기 D-09: 세션 단위 생성·폐기 vs 엔진 저장 + DB 파일 암호화]. 화면·API·로그에는 항상 `••••`.
- 등록 시스템 인증(API 키, Basic, OAuth): 키체인 참조. 원본처럼 "터미널에서 export 후 실행"이 필요 없도록 F7 화면에서 입력(원본 튜토리얼 불일치 해결).

## 8. 코드 앱 격리
- 코드 앱은 **별도 오리진**(`127.0.0.1:<apps>`)에서 제공. Studio API에 직접 닿지 않는다.
- 앱은 **앱별 SDK 토큰**으로 Object API의 허용 범위만 호출: 앱 설정에 선언한 Object type 읽기, 선언한 Action type의 **계획 요청**까지. 승인은 §4 네이티브 창.
- 미리보기 iframe은 `sandbox`(scripts만 허용, same-origin 불허).
- 앱 정적 파일 응답에 CSP(외부 스크립트·연결 금지, 앱 오리진의 API만).

## 9. 파일 경로 규칙
- 업로드: 파일 이름 정규화(경로 구분자·`..` 제거), 저장 경로는 대화 작업 공간 아래로 고정, 심볼릭 링크 따라가지 않음.
- 적재·파서 도구는 작업 공간과 업로드 폴더 안의 파일만. 절대 경로 입력 거부.

## 10. 빌드 하드닝
- Electron fuse: RunAsNode 끔, NODE_OPTIONS 끔, CLI inspect 끔, ASAR 무결성 검증 켬, OnlyLoadAppFromAsar 켬.
- 코드 서명·공증(macOS Developer ID + notarization, Windows Authenticode).
- 개발자 도구 메뉴는 개발 빌드에서만.

## 11. 보안 테스트 (성공 기준)
1. 토큰 없는 요청 → 401 (게이트웨이·코어·MCP 전부)
2. 다른 Origin의 요청 → 거부
3. 에이전트 턴에서 승인 API 호출 → 거부, 셸 증표 없는 승인 → 거부
4. 에이전트 프로세스 환경에 DB 비밀번호·실행기 토큰 없음
5. 코드 앱에서 Studio API·승인 경로 접근 불가, 확인 창 흉내로 승인 불가
6. 업로드 파일 이름 `../../x` → 작업 공간 안에 정규화된 이름으로 저장
7. 데이터소스 비밀번호가 DB 덤프·로그에 평문으로 없음(D-09 결정에 따름)
8. 외부 MCP는 토큰 발급 전 접근 불가
