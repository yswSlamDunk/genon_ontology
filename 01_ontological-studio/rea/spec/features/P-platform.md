## 1. 목적
여러 구성 요소(DB, 그래프 엔진, 코어, 예제 업무 서비스)를 **설치 없이 한 데스크톱 앱 안에서** 띄우고, 사용자에게는 탭 기반 창 하나로 보여 주는 실행 기반. 모든 기능(F1–F8)이 이 위에서 돈다.
- 창·탭·단축키·홈 화면
- 부팅·종료·고아 정리·포트·데이터 폴더
- **로컬 게이트웨이**(UI·API·MCP의 단일 입구, 세션 토큰 검사)와 **앱 오리진**(코드 앱 격리)
- **네이티브 승인 창**(사람 승인의 증명, 03 §4)
- 프로세스 감독, 로그, 상태 API, 예제 서비스

## 2. 원본 기준 동작 요약 [원본]
근거: A1 §2–§13, A2 §4–§9, A3 §4·§10.
- Electron 셸이 하위 프로세스 **9개**(PostgreSQL, Bolt 게이트웨이, 포털 서버, 분석 백엔드, 검색 MCP, 액션 실행기, 예제 서비스 3)를 띄움. 선호 포트 27432/27687/27474/27800/27810/27900/27830/27841–27843, 우선순위 = 서비스별 환경 변수 > 지난번(`ports.json`) > 선호 > OS 임의.
- 데이터 폴더(환경 변수 `ONTOLOGICAL_STUDIO_USER_DATA`로 지정, 폴더당 인스턴스 1개): `studio.env`(0600), `secrets.json`(0600, 비밀 8개), `ports.json`, `pgdata/`(단계 완료 표식), `logs/`, `run/`(PID), `sandbox/`, `codeapps/`, SQLite 2개. 대시보드는 **앱 패키지 폴더**에 저장(결함).
- 부팅 단계 `starting → postgres → bootstrap → ontological → studio → ready | error`, 부팅 화면에 단계·경과 시간, 트레이 첫 줄 라벨. 부팅 시간 기록 `boot-timings.json`. 재시작 약 3.1초.
- 준비 확인: TCP 연결 또는 HTTP < 500, 150ms 간격, 120초. 고아 정리: PID 살아 있고 명령 줄이 이 앱 런타임을 가리킬 때만(DB SIGINT, 나머지 SIGTERM, 10초 후 SIGKILL). 종료는 역순, DB 마지막.
- 로컬 웹 오리진(127.0.0.1, **인증 없음**): `/lite-shell/…`, `/app/status`, `/app/portal-info`, `/api/…` 프록시, `/mcp…` 프록시, `/fabric-bridge/…`, `/codeapps/api/…`, `/apps/…`(코드 앱 **같은 오리진**), SPA.
- 창 1440×900(최소 1024×640), 탭 바 38px, 탭 종류 studio/portal/app, 단축키(⌘T·⌘1 홈, ⌘2–⌘8·⌘9, Ctrl+Tab, ⌘W, ⌘R, ⌘N, ⌥⌘I, 우클릭 메뉴), 탭 분리 시 다시 로드 안 함. 코드 앱 탭에는 셸 API 없음.
- 홈: 카드 8개, 최근 항목(이름/종류/정보/날짜, 필터·검색), 빠른 이동, 상태 2줄, 테마 토글.
- 메뉴바 「런타임」, 트레이(단계·에이전트·홈·포털·데이터소스·새 창·설정 파일·로그·종료).
- 보안 약점: 무인증(S1), DB 슈퍼유저 공유(S5), 비밀 평문 파일, Electron fuse 기본값·ad-hoc 서명(S12).

## 5. 화면 구성과 상호작용

### 5.1 창
- 기본 1440×900, 최소 1024×640, macOS는 타이틀바 숨김 + 신호등 버튼을 탭 바 안에(원본). 준비 전 부팅 화면, 준비 후 셸 화면.
- 테마: 밝음/어두움/시스템. 셸과 모든 탭이 같은 설정을 즉시 공유(원본은 저장 키 공유 → 새 설계는 셸이 탭에 테마 변경을 알림).

### 5.2 탭 종류와 주소
| 종류 | 내용 | URL |
|---|---|---|
| studio | 메인 UI의 한 화면 | `https://`가 아닌 `http://127.0.0.1:<web>/?view=<v>&…` |
| app | 코드 앱(F5) | `http://127.0.0.1:<apps>/apps/<id>/` (id 규칙 원본: 소문자·숫자·하이픈 4–64자) |
- `view` 값: `build`(F1), `act`(F2), `datasources`(F3), `console`(F4), `board`(F5 대시보드·Object view), `quality`(F6), `systems`(F7), `settings`(F8). 원본 `browser`(포털) → `console`로 별칭 처리.
- 공통 쿼리: `session`(대화), `ds`(데이터소스, F3), `ontology`(rid 또는 apiName), `edit`(F1 편집 대상), `object`(`<Type>:<pk>`, Object view), `section`(F8).
- 탭 제목: studio는 화면 제목(기본 view 이름), app은 앱 이름(원본).

**최근 항목** (원본 표 구조·날짜 형식·필터·검색·빈 상태 문구 유지):
| 종류 | 정보 칸 | 열리는 곳 |
|---|---|---|
| 구축 대화 / 질의·액션 대화 | 대상 온톨로지 표시 이름 | build/act + 대화 |
| 온톨로지 | 「Object type N · v<발행 버전>」(초안만 있으면 「Object type N · 초안」) — 원본 「클래스 N」 | build + 온톨로지 |
| 변경 제안 (신규) | 「검토 대기 · 변경 N」 | build + 제안 |
| 대시보드 | 온톨로지 표시 이름 | board |
| 코드 앱 | 「에이전트 작업 중」 또는 「수정 N회」(원본) | app 탭 |
| 데이터소스 | `<엔진> · 테이블 N · Object type M` (원본 `노드 N`) | datasources + `ds` |
- 날짜: 오늘 「오늘 HH:MM」, 올해 「M월 D일」, 그 외 「YYYY. M. D.」(원본). 기본 대화(id `default`)는 제목·대상이 바뀌기 전엔 숨김(원본). 날짜 없는 항목은 뒤로.
- 필터: 전체 · 온톨로지 · 대화 · 앱 · 데이터소스(개수). 검색: 이름+정보 부분 일치(대소문자 무시). 빈 상태: 「아직 만든 것이 없습니다. 위에서 시작하세요.」 / 「조건에 맞는 항목이 없습니다.」(원본).
- 데이터 출처: 코어 단일 API `GET /api/v1/home/recent`(원본은 7개 병렬 조회 — 하나가 실패해도 나머지를 보이던 성질은 응답의 부분 오류 필드로 유지 `{items, errors:[{source, message}]}`).
- 다시 조회: 홈 탭으로 돌아올 때, 창 포커스, `/api/v1/events` 알림(신규).

**빠른 이동**: 그래프 콘솔(탭), 로그 폴더, 데이터 폴더(OS 파일 관리자), 설정(신규).

## 6. API · 계약

### 6.1 로컬 게이트웨이 (셸 메인 프로세스, `127.0.0.1:<web>`)
| 경로 | 동작 | 인증 |
|---|---|---|
| `/` , 정적 자산 | 메인 UI(SPA). `/assets/…`(해시)만 1년 immutable, 나머지 no-cache(원본 규칙) | 세션 쿠키 없으면 401 페이지(셸 탭은 항상 쿠키 보유) |
| `/shell/…` | 셸 페이지(탭 바·홈·부팅 화면) — 원본 `/lite-shell/…` | 쿠키 |
| `/api/v1/…` | 코어로 리버스 프록시(SSE 포함) | 쿠키 또는 Bearer(세션 토큰). 코어가 다시 검사 |
| `/mcp/agent/<mode>/` | 코어 에이전트 브리지(04) | **턴별 일회용 토큰**만 |
| `/mcp/external` | 코어 외부 MCP(04 §8) | **개인 접근 토큰**만, 설정에서 켰을 때만 |
| `/auth/once?t=<일회용>` | 외부 브라우저용 쿠키 교환 → `/`로 리다이렉트 | 일회용 토큰(60초, 1회) |
| 그 밖 | SPA 진입 HTML | 쿠키 |
- 제거: `/app/portal-info`, `/fabric-bridge/…`, `/api/gateway/…`, `/kinetic-idp/jwks.json`, `/analyzer…`, `/codeapps/api/…`·`/apps/…`(→ 앱 오리진).
- 공통 검사(모든 경로): `Host`가 `127.0.0.1:<web>` 또는 `localhost:<web>`이 아니면 421/403(DNS 리바인딩 방지). `Origin`이 있으면 게이트웨이 오리진과 같아야 함(아니면 403 `{"error":"cross-origin request refused"}` — 원본 포털 문구 재사용). CORS 응답 헤더 없음. 비-GET JSON API는 `Content-Type: application/json` 필수(415, 원본 포털 규칙 일반화).
- 프록시 오류: 502 `{"error":"upstream <구성> <오류코드>"}`(원본 형식, 포트 대신 구성 이름).

### 6.2 앱 오리진 (`127.0.0.1:<apps>`)
- `/apps/<id>/…` 정적 파일(CSP: `default-src 'self'; connect-src 'self'; script-src 'self'`), `/apps/<id>/sdk/v1/…` → 코어 Object API 하위 집합(앱 SDK 토큰, 앱 선언 범위만). 세부는 F5·03 §8.
- 게이트웨이 세션 쿠키는 이 오리진에 보내지지 않는다(포트가 달라 쿠키가 공유되는 브라우저 동작을 피하기 위해 쿠키 이름·`Path`·`SameSite=Strict` + 앱 오리진에서 쿠키 무시) [확인 필요: 127.0.0.1 포트 간 쿠키 공유 — 필요하면 앱 오리진을 `localhost`로, 게이트웨이를 `127.0.0.1`로 나눔].

### 6.3 세션 토큰 (03 §3)
- 셸이 부팅 때 32바이트 난수 생성, 메모리에만. 코어 시작 시 **파일·환경 변수가 아니라 상속된 파이프(stdin)** 로 전달 [제안] — 다른 프로세스가 `ps`·환경에서 못 보게.
- 셸 탭(WebContentsView)에는 셸이 세션 파티션에 쿠키를 직접 심음(`HttpOnly; SameSite=Strict; Path=/`). 페이지 JS는 토큰 값을 못 읽음.
- 코어는 게이트웨이를 거친 요청과 직접 요청 모두 토큰 검사(코어 포트는 127.0.0.1, 임의 포트).
- 종료 시 폐기, 다음 실행은 새 토큰.

### 6.5 네이티브 승인 창 호스트 (03 §4)
흐름:
1. 페이지가 `requestApproval({kind, refId})` 호출(`kind`: `action.approve`, `ontology.publish`, `ontology.reset`, `bulk.delete`, `settings.broaden`, `token.issue`, `samples.reset`). **표시 문구를 페이지에서 받지 않는다.**
2. 셸 메인이 코어에 `GET /api/v1/approvals/summary?kind=&refId=`(세션 토큰)로 요약을 직접 받는다: 제목, 대상 수, 시스템 호출 요약, 위험 표시, 요약 해시.
3. 셸이 OS 모달 대화상자를 그린다(앱 창에 붙은 시트/대화상자): 제목 「<액션 표시 이름> 승인」, 본문(요약, 최대 10줄 + 「외 N건」), 버튼 「승인」/「취소」, 기본 버튼 = 취소. 대화상자는 렌더러 입력 이벤트로 누를 수 없다(OS 창).
4. 「승인」 → 셸이 증표 생성: `{proofId, kind, refId, summaryHash, actor: {kind:"human", id:<OS 사용자>}, exp: now+60s}`를 셸만 아는 키(부팅 때 생성, 메모리)로 HMAC 서명. 서명 키는 코어 시작 때 세션 토큰과 함께 파이프로 전달(코어가 검증).
5. 셸이 코어 `POST /api/v1/approvals/confirm {proof}`를 **직접** 호출 → 코어는 서명·만료·1회 사용·요약 해시(그 사이 계획이 바뀌지 않았는지) 확인 후 대상 작업 수행, 감사에 `proof` 기록.
6. 결과(`approved|rejected|expired|changed`)를 페이지에 돌려준다.
- 한 번에 하나의 승인 창만(겹침 방지). 창이 열린 동안 같은 요청 반복 무시.
- 직무 분리(02 §10): 코어가 계획자 = agent인지 확인해 사람 승인만 허용. 1인 모드에서 사람이 계획·승인하는 것은 허용(03 §4).
- 테스트 훅: 자동화 테스트용 승인 자동 응답은 **개발 빌드 + 환경 변수**에서만 [제안].

### 6.6 셸 정보 `info()` (원본 호환)
`{graph, ports, phase, agent:{backend, agentId, label, ready, note}, llmConfigured, kineticConfigured, version}` — 원본 키 유지. `graph` = 그래프 엔진 기본 그래프 이름, `backend`는 `cliagents|builtin`(원본 `deepagents`는 별칭으로도 인식), `kineticConfigured`는 항상 `true`. 추가: `product`, `dataFolder`, `externalMcp:{enabled, tokens}`, `restartPending: bool`.

## 7. 데이터 · 저장

### 7.1 데이터 폴더
- 위치: 환경 변수 `WORKBENCH_USER_DATA`(이름은 제품 이름 D-11에 따라 확정)가 있으면 그 경로, 없으면 OS 앱 데이터 위치의 제품 이름 폴더. 원본 데이터 폴더 이전은 하지 않는다(새 제품, 원본과 공존).

```
<데이터 폴더>/
  instance.json        { id, createdAt, productVersion }
  shell-settings.json  선호 포트·예제 서비스 켬 (F8 §7), 0600
  override.env         (선택) 고급 고정 파일 (F8 §5.8), 0600
  ports.json           구성 → 포트 (원본 형식)
  pgdata/              DB 클러스터(0700) + 단계 완료 표식 (원본 규칙)
  run/<구성>.pid
  logs/<구성>.log, shell.log, core.jsonl, boot-timings.json
  workspaces/sessions/<세션>/{uploads/, output/, .claude/skills/…|.agents/skills/…}   (04 §7)

```

| `bolt` (D-02 A) | 번들 게이트웨이, `wb_core` 접속 | TCP, 30초 | 부팅 실패 |
| `core` | 번들 런타임(D-03) | `GET /api/v1/system/ready`(토큰), 120초 | 부팅 실패 |
| `samples` | 예제 업무 서비스 묶음 | 각 포트 HTTP < 500, 30초 | **경고만, 계속**(원본 액션 실행기 실패 처리와 같음) |
- 로컬 게이트웨이·앱 오리진은 셸 메인 프로세스 안의 HTTP 서버(별도 프로세스 아님).
- 하위 프로세스: 이름별 로그 `logs/<이름>.log` append(시작 시각·명령 줄 헤더 — 단 명령 줄의 비밀 마스킹), `run/<이름>.pid`(원본).
- 감독 [제안]: `core`가 예기치 않게 종료되면 1회 자동 재시작(5초 대기), 또 죽으면 홈 상태 빨강 + 「코어를 다시 시작」 버튼. 재시작 횟수는 상태 API에.

### 8.2 부팅 순서 (01 §5)
1. 데이터 폴더 준비(`instance.json`), 단일 인스턴스 잠금
2. 키체인 준비(데이터 폴더 id 이름공간; 없으면 비밀 생성)
3. 고아 정리(§8.4) + 지난 실행의 원천 비밀번호 잔존 정리(D-09 권장안, F3 §7.3)
4. 포트 할당·저장, 세션 토큰·승인 서명 키 생성(메모리)
5. PG 시작(첫 실행: 초기화·부트스트랩·예제 DB), 죽은 lock 파일 처리(원본)
6. 그래프 엔진(·Bolt) 시작
7. 코어 시작(세션 토큰·서명 키를 파이프로) → 메타 마이그레이션 → 발행 모델 적재 → 내장 데이터소스 포트 점검·예제 패브릭 등록(필요 시)
8. 예제 서비스 시작(켜져 있으면) → 예제 시스템 등록 확인(F7)
9. 게이트웨이·앱 오리진 시작
10. (첫 실행) 예제 온톨로지 생성·발행 — 실패해도 계속, 다음 시작에 재시도
11. 준비 완료 → 모든 창 부팅 화면 → 셸 화면 → 부팅 시간 기록
- 단계 이름(상태 API·트레이): `starting`, `keychain`, `postgres`, `bootstrap`, `graph`, `core`, `samples`, `ready`, `error`(원본 `ontological`→`graph`, `studio`→`core`).
- 부팅 시간 기록 `{at, fresh, timings:{keychain, postgres, bootstrap?, graph, core, fabricSeed?, samples?, sampleOntology?, uiLoaded}}`(원본 형식 확장).

### 8.3 종료
역순: 승인 창 닫기(진행 중이면 취소로) → 트레이 제거 → 코드 앱 에이전트 턴 중지 → 게이트웨이·앱 오리진 닫기 → 코어(진행 중 에이전트 CLI 프로세스 그룹 정리 포함, 8초) → 예제 서비스(5초) → Bolt(5초) → PG(SIGINT 빠른 종료, 20초) → 세션 토큰·서명 키 폐기. 시간 초과 시 SIGKILL(원본). 모든 창을 닫으면 종료(원본). Windows는 PG 제어 도구 fast 모드(원본).

### 8.4 고아 정리 (원본 유지)
`run/`의 PID가 살아 있고 명령 줄이 이 앱 런타임 폴더를 가리킬 때만 종료(DB SIGINT, 나머지 SIGTERM, 10초 후 SIGKILL), PID 파일 삭제. 명령 줄 확인이 핵심(다른 프로그램을 죽이지 않음). 추가: 코어가 띄운 CLI 에이전트 프로세스 그룹도 `run/agent-<턴>.pid`로 기록해 정리 대상에 포함 [제안].

### 8.5 로그
- 셸 로그 줄 형식 `<ISO 시각> <메시지>`, 단계 `[<단계>] <문구>`(원본). 코어는 JSON 줄(`ts, level, reqId, module, actor, msg`).
- 비밀 마스킹 필터: 세션 토큰·PAT·키체인 값·`password=`/`Authorization:` 패턴을 `••••`로(모든 로그 공통).
- 회전: 파일당 10MB, 5개 보관(C12).
- 에이전트 결정 로그 한 줄(원본 형식 유지): `에이전트: <표시 이름> (backend=<방식>[, <cli id>])[ — <안내 문구>]`.

### 8.6 상태 API
- `GET /api/v1/system/status`(세션 토큰): `{phase, timings, ports, userData, error, pids:[{name, pid, status, startedAt, restarts}], components:{postgres, graph, core, samples:{erp, wms, crm}}, agent, version, product}` — 원본 `/app/status` 필드(`phase, timings, ports, userData, error, pids`) 포함.
- `GET /api/v1/system/ready`: 준비 확인용(토큰), `{ready: bool}`.
- 셸 IPC `info()`(§6.6)는 부팅 중(코어 없음)에도 응답.

### 8.7 예제 업무 서비스
- erp·wms·crm 세 서비스를 **한 프로세스**에서 세 포트로(01 §2.1). 튜토리얼 API 형태·경로·인증 방식(API 키 / Basic / Bearer)은 원본과 같게(F7 비교 테스트).
- 인증 비밀(원본 `erpApiKey`, `crmToken`, `wmsBasic`)은 키체인에 생성, 예제 시스템 등록(F7)의 시스템 인증으로 연결 — 사용자가 터미널에서 export할 필요 없음(REVIEW #11 해결).
- DB 역할 `sample_svc`로 `sample` DB 접근(원본).
- 원본의 실행기 내부 비밀 헤더 전송(S8)은 해당 없음(실행기 내장, 시스템별 인증만 전송).

## 9. 에이전트 연동
- 셸은 에이전트를 직접 실행하지 않는다(원본은 셸이 결정·단발 스크립트 실행). **결정·전환·실행은 코어 Agent 모듈**(04). 셸은 CLI 탐지에 필요한 보충 PATH(원본 A3 §4.2 목록)를 코어에 넘기고, 종료 시 프로세스 그룹 정리를 보장한다.
- 에이전트 MCP 경로 `/mcp/agent/<mode>/`는 게이트웨이를 거치되 턴별 토큰만 통과(세션 쿠키로는 안 됨 — 사람 UI 세션과 에이전트 권한 분리).
- 에이전트 CLI 프로세스 환경 화이트리스트(03 §5): `PATH`(보충 포함), `HOME`, 언어 설정, `TERM`, 턴별 MCP 토큰. 셸·코어의 세션 토큰·서명 키·DB 비밀번호는 절대 포함하지 않음.
- 에이전트는 `requestApproval`을 부를 수 없다(브리지는 렌더러 전용, 에이전트 도구에 승인 없음 — 04 §4).

## 12. 원본과 비교할 테스트
**같아야 함**
1. 빈 데이터 폴더 첫 실행: 단계 순서(이름은 §8.2 대응표), 예제 DB 행 수(supplier 5, item 4, purchase_order 8, po_line 9, shipment 8, stock_daily 10, customer 3, sales_order 5, claim 3), 예제 데이터소스 3·`sample` 가상 노드 7·관계 5.
2. 재실행: 첫 실행 단계 생략, 포트 재사용, 데이터 보존.
3. 선호 포트 점유 시 대체·다음 실행 재사용.
4. 같은 폴더 두 번째 실행 → 기존 창 포커스, 다른 폴더 동시 실행.
5. 강제 종료 후 재실행 → 이 앱 프로세스만 정리.
6. 정상 종료 후 하위 프로세스 0.
7. 탭 규칙: 외부 링크는 브라우저, 앱 탭엔 브리지 없음, 분리 시 상태 유지. 단축키 §5.3(원본분).
8. 홈: 최근 항목 종류·날짜 형식·필터·검색·빈 상태 문구, 상태 줄 점 색 규칙, 「에이전트 설정 필요」 배지 조건.
9. 부팅 시간 기록 형식(키 이름은 확장), 상태 API의 원본 필드.
10. 리슨 주소 127.0.0.1만, DB 유닉스 소켓 없음, 인증 SCRAM(A2 §9-8).

**의도된 차이 (D-12)**
1. 하위 프로세스 수(9 → 4 이하), 포털·검색 MCP·액션 실행기 프로세스 없음.

3. 코드 앱이 다른 오리진(포트) — S7, D-17.
4. 승인은 네이티브 창 + 증표(N2) — S4, D-18.
5. `secrets.json`·`studio.env` 없음, 비밀은 키체인 — S6.
6. DB 역할 분리, 셸·코어가 슈퍼유저를 쓰지 않음 — S5.
7. 「설정」 카드가 탭을 염, `portal` 탭 종류 없음.
8. 선호 포트 28xxx.
9. 개발자 도구 메뉴가 배포 빌드에 없음, fuse·서명 — S12.
10. 대시보드가 앱 패키지 폴더가 아니라 DB에 저장.

## 13. 열린 질문
1. 127.0.0.1의 서로 다른 포트 사이 쿠키 공유 문제(§6.2): 게이트웨이 `127.0.0.1` / 앱 오리진 `localhost`로 나누는 방식이 충분한가, 커스텀 프로토콜(`app://`)로 메인 UI를 띄우는 것이 나은가(외부 브라우저 열기와 충돌).
2. 코어 언어(D-03)에 따라 코어 시작 시간이 4초 목표를 넘을 수 있다 — 재실행 목표 시간 확정 필요.
3. 예제 서비스를 "선택 설치"로 할 때 설치 단위(앱 번들에 항상 포함하고 켬/끔만 vs 별도 다운로드).
4. Windows 키체인(Credential Manager)의 항목 크기 제한과 RSA 키 같은 긴 비밀 저장 — 필요하면 키체인에는 마스터 키만 두고 DB에 암호화 저장.
5. 자동 업데이트(서명된 업데이트 채널) — 범위 밖으로 둘지.
6. 원본 홈 카드 1·5·6·7번의 정확한 설명 문구 [확인 필요 — 원본 실행 기록].
7. 1인 사용 전제의 "사람 신원"(`actor.id`): OS 사용자 이름으로 충분한가, 앱 안 프로필 이름을 둘지.
