# GenTology — 실제로 돌아가는 시스템 (빈 상태에서 시작)

직접 연결하거나 업로드한 데이터로 온톨로지를 만들고, 질문하고, 골든 질문으로 확인하는 로컬 시스템입니다. 더미 데이터는 없습니다.
화면 모양은 제논 어드민 디자인 시스템(genonai/admin-design-system) 토큰과 패턴을, 누르면 어디로 가고 무엇이 뜨는지(화면 흐름)는 Microsoft Fabric을 따릅니다(아래 "화면 흐름"). 같은 화면 코드로 만든 예시 데이터 목업은 `~/Project/20261104_GenO_목업.html`(소스 `~/Project/geno-mock`)입니다.

## 실행

```bash
cd ~/Project/geno-app && uv run uvicorn server:app --port 8795 --reload --reload-dir geno --reload-dir . --reload-exclude '.venv/*' --reload-exclude 'data/*'
```

- 화면: http://localhost:8795/web/ · 목업 보기(자동 새로 고침): http://localhost:8795/mock
- 코드나 화면 파일을 고치면 서버가 다시 뜨고, 열린 페이지가 스스로 새로 고칩니다.
- LLM 키는 `~/Project/geo-proto/.env`를 읽기만 합니다. `GENO_LLM_OFF=1`이면 AI 기능을 끕니다.
- 저장소는 `data/geno.db` 하나(+ 업로드한 문서 `data/files`, PDF 쪽 그림 · 글자 `data/pages`). 처음 상태로: `curl -X POST localhost:8795/api/reset`
- 사용자: 처음엔 사용자가 없어 모든 기능을 씁니다(설정 전). 첫 관리자를 만들면 역할별로 화면 · 권한이 나뉩니다. 로그인 대신 화면 위에서 사용자를 바꿉니다(시험용, 요청 머리 `X-GenO-User`).
- 시험: `uv run pytest -q` (LLM 없이 도는 부분)

## 화면 흐름 (Fabric 기준, 11/05)

| 화면 | 누르면 | Fabric 대응 |
|---|---|---|
| 작업 공간 | 처음 화면(왼쪽 위 "GenTology 작업 공간"). 이 공간의 항목을 종류별 아이콘 목록으로: 데이터(DB 연결 · 업로드 표 · 업로드 문서) · 온톨로지 · 질문 에이전트 · 골든 질문. 누르면 그 화면, [새 항목 ▾]으로 만들기 | Fabric 작업 영역 항목 목록 |

| 개체 추가 | 이름 창 → 데이터 연결 페이지(원본 표 · 미리 보기 · 키 · 조건) → [만들기] → 개체 페이지 | 엔터티 형식 추가 → 속성 바인딩 |

| 관계 | 관계 추가 창(이름 · 원본 · 대상) → 관계 페이지(원본 열 · 관계 · 대상 열, 값 겹침, 방향 바꾸기) → [저장]. 기존 관계는 같은 세 칸 + [삭제] | 관계 세부 정보 |
| 규칙 | 목록(검색 · 시작 개체 필터) → 상세(규칙 문장 · 연결된 개념 · 조건 · 테스트, [시작]/[중지]). 새 규칙은 전체 페이지, [저장](중지 상태) / [저장 후 시작] | 온톨로지 규칙 · Activator |
| 질문하기 | 가운데 대화(새로 고침하면 비워짐, 지난 질문은 질문 기록). 답마다 [실행 단계] 펼치기(구축 담당은 SQL까지), 근거·탄 경로 · 골든 질문으로 저장 · 지표로 저장. 구축 담당 리본: [에이전트 지시문](오른쪽 패널 · 모든 질문의 계획과 답 쓰기에 들어감) · [예시 질문](질문 틀 목록 · 다시 묻기 · 삭제) · [새 대화] | 데이터 에이전트(지시문 · 예시 질문 · 단계 보기) |
| 골든 질문 | 목록 → 상세(정답 · GenTology 답 · 사람 판정 · 실행 단계). 질문하기에서 받은 답을 바로 골든 질문으로 저장 | 목록 → 상세 공통 흐름 |
| 예시 칩 | 지금 데이터로 만든 "누르면 바로 해 보는" 예시(LLM 없음, `/api/examples`, 데이터가 없으면 숨김): 데이터 에이전트 질문 유형별(집계 · 계산 속성 · 여러 단계 · 규칙 판정 · 문서 본문) · 문서 읽기 › 본문 검색(실제로 1건 이상 나오는 말) · 가정 바꿔 보기(복사본에서 돌려 결과가 실제로 달라지는 것만) · 엔터티 형식 추가(값 종류가 몇 개뿐인 열로 떼어 내기) · 관계 추가(값이 겹치는데 아직 안 이어진 열 짝) · 계산 속성 추가 · 에이전트 지침 · 규칙 · 메트릭 · 골든 질문 | 제안 칩 · 예제 쿼리 |
| Copilot | 구축 도우미(설명 · 바꾸기 제안 → 승인). 데이터 질문은 질문하기 대화로 넘김. 질문하기 화면 · 현업에게는 숨김 | Ontology agent(구축) / Data agent(질문) 나눔 |
| 읽을 칸 추천 | 문서 읽기 › 읽을 칸: 칸 없이 한 번 읽으면(문서 종류 · 본문) AI가 본문을 보고 칸 후보(표시 이름 · 뜻 · 형식 · 예시)를 칩으로 → 누르면 추가, [모두 추가]. 다른 테이블에 같은 뜻 열이 있으면 그 열 이름으로 + "이어짐" | Fabric ai.infer_schema |
| 계산 과정 펼쳐 보기 | 인스턴스 탭에서 줄을 누르면 오른쪽 패널에 값 · 계산 속성마다 식 · 들어간 값(원본 테이블 · 줄 · 상태) · 중간 결과. 들어간 값이 비었거나 사람 확인 전(문서 검수 대기)이면 "예상". 데이터 에이전트 답 · 규칙 테스트의 실행 단계에도 같은 풀이 | 팔란티어 파생 속성 · Functions |
| 가정 바꿔 보기(What-if) | 인스턴스 패널 [가정 바꿔 보기] 또는 온톨로지 설계 탐색기 › 가정 바꿔 보기 › [새 가정] → 값을 임시로 바꿈 → 계산 속성 · 규칙 판정 · 골든 질문 답을 "지금 / 바꾸면"으로. 원본은 그대로(임시 복사본 DB에서 계산 후 지움). 이름 붙여 저장 · 삭제 · 지금 데이터로 다시 계산 | 팔란티어 Scenarios |
| 데이터 에이전트 | 오른쪽 아래 말풍선 버튼(메신저처럼) → 작은 대화 창, 어느 화면에서나. [크게 보기]로 전체 페이지. 현업은 전체 페이지가 첫 화면 | 데이터 에이전트 |
| 용어 | 화면 단어는 Fabric 용어: 엔터티 형식(개체) · 테이블(표) · 메트릭(지표) · 데이터 원본(데이터 소스) · 작업 영역 · 데이터 에이전트 · 에이전트 지침 · 예제 쿼리 · 관계 유형 · 전체 온톨로지/동네 | - |
| 속성 이름(영어 칸 이름 숨김) | 업무 이름이 없는 칸은 설명 · 동의어 → 없으면 사전으로 만든 한글 임시 이름(visit_type → 진료 유형, filed_date → 청구일, `geno/naming.py`, LLM 없음). 테이블 이름 그대로인 엔터티 형식 이름도 같게. 엔터티 형식 페이지에 "업무 이름 비어 있음 n" + [이름 채우기], 속성 편집에선 임시 이름을 흐린 글자로. SQL 보기는 원래 이름 그대로 | - |
| 키 점검 | 키 값이 겹치면 엔터티 형식 페이지에 이유 + 고칠 버튼: 값이 모두 다른 열로 바꾸기 / 두 열을 합친 키 만들기(계산 속성 "가-나"를 만들어 키로, Fabric 복합 키처럼) | 엔터티 형식 키 |
| doc_extract | 데이터 원본 › 문서에서 읽은 값 › doc_extract: 위에 표, 줄을 고르면 아래에 그 문서(그림 · 읽은 값 · 본문) | - |
| 이름 · 로고 | 제품 이름 GenTology. 로고는 제논 DS 브랜드 등록(`admin-ds.brand.json` → `npx admin-ds-brand` 또는 DS 레포 `node bin/admin-ds-brand.mjs --config` → `web/brand.css`), GenD처럼 심볼 + GEN(검정) TOLOGY(블루) | - |
| 공통 | 전체 페이지 편집은 아래 고정 [취소]/[저장]. 저장 안 한 채 다른 화면으로 가면 확인 창. 위 경로(온톨로지 설계 › 개체 › 속성 편집)를 눌러 돌아감 | - |

## 흐름과 코드 위치

| 화면 | 하는 일 | 코드 |
|---|---|---|
| 데이터 소스 | CSV · 문서 업로드, DB 연결(PostgreSQL · MySQL · SQLite, 읽기만, 표당 최대 5만 줄 복사) | `geno/sources.py` |
| 온톨로지 설계 | AI 초안(프로그램이 센 "값 겹침 후보"를 힌트로 줌) · 관계 추가 · 값 겹침 · 짝 수(1:1 · N:1 · N:M) 표시 | `geno/onto.py` |
| 개체 정의 층 | 개체 = 원본 표 + 조건 + 계산 속성 → `o:<개체>` 뷰. 속성마다 업무 이름 · 타입 · 설명 · 동의어 · 숨김 · 민감, 키 점검(겹침 · 빈 값), 표시 속성 | `onto.build_view` · `save_def` · `add_object` |
| 계산 속성 | 문장 → 계산(같은 줄 식 / 이어진 줄 집계 / 이어진 값 가져오기). 계산은 SQL | `onto.calc_compile` · `calc_sql` |
| 같은 대상 묶기 | 여러 열을 견줘(정확히 · 표기 차이 무시 · 비슷함) 짝 찾기 → 확정한 짝은 매핑 개체 + 관계 둘. 한 줄이 여러 짝이면 "여러 짝" 표시 | `onto.er_run` · `er_apply` |
| 계산 풀이 · What-if | `explain`(식 · 들어간 값 · 출처 · 예상), `run`(DB 복사본 `DB_OVERRIDE`에서 바꿔 계산 → 원본 그대로), 가정 저장 `scenario` 표 | `geno/whatif.py` · `/api/objects/{name}/explain` · `/api/whatif` |
| 에이전트 지시문 · 예시 질문 | 지시문은 `kv.agent_instr`, 질문 계획 · 답 쓰기 프롬프트에 넣음(기본 형식 규칙보다 앞섬, 숫자는 계산값 그대로). 예시 질문 = 질문 틀(`tpl`) 목록 · 삭제 | `qa._instr` · `qa.agent` · `/api/agent` |
| 문서 읽기 | 누운 문서 자동 회전: AI가 누웠다고 보거나 가로로 긴 쪽만 대상으로, 첫 쪽을 0 · 90 · 180 · 270도 돌린 4장을 보여 주고 바로 읽히는 그림을 고르게 함(순서를 바꿔 두 번 물어 같을 때만, 세로 서류를 눕히는 답은 거절) → 돌려 다시 읽고, 바로 섰다고 나와야 받아들임, 아니면 그림을 되돌림(원본 파일은 그대로, Pillow 필요). 읽을 칸을 사람이 정함 → LLM 그림 읽기(PDF 최대 10쪽) → `doc_extract`(읽은 값) 개체. `doc_key` = 파일 이름 첫 `_` 앞. 본문도 쪽마다 조각으로 저장 | `geno/docs.py` |
| 본문 검색 | 값으로 먼저 좁히고(관계로 이어진 문서만) 임베딩으로 고름. 임베딩이 안 되면 글자 겹침으로 | `docs.search` · `/api/search` |
| 읽은 값 검수 | 확신도 0.8 미만 · 누운 문서 · 이어 둔 표에 없는 값 + 가장 비슷한 값 추천 | `docs.review_list` |
| 규칙 | 문장 → 조건(JSON). 같은 개체 조건은 같은 줄에서 함께 맞아야 함. 실행은 프로그램 | `geno/rules.py` |
| 질문(Copilot) | 질문 틀 찾기 → 한 건: 정해진 길(hops) 따라 SQL → 규칙 실행 → (필요하면 이어진 문서 본문) → LLM 1회로 답. 여러 건: 세기 · 합계 · 순위 · ~별을 SQL 한 번으로(이름 열로 나눠도 키 기준이라 동명이인이 안 합쳐짐). 관계가 없으면 "미연결"로 멈춤 | `geno/qa.py`, `geno/graph.py` |
| 지표 | 여러 건 계산을 이름 붙여 저장 → 같은 지표는 늘 같은 계산식 | `qa.metric_*` |
| 전체 판정 | 시작 개체의 모든 건에 규칙 실행 → "판정 결과" 개체로 저장(다음 질문 · 지표에서 사실로 씀) | `rules.run_all` |
| 사용자 · 역할 | 관리자 · 구축 담당 · 검토자 · 현업. 현업은 질문하기 화면만, 민감 값 가림. 자기 신청은 승인 못 함. 변경 이력에 이름 남음 | `geno/users.py`, `server.actor` |
